Choose a data source above, then use its example and parameter table below. CSV and JSON each support inline content and files.

## Connect a source

Create an AVA instance, then call `source(config)` with the data location and reader settings:

```typescript
import { AVA } from '@antv/ava';

const ava = new AVA({
  llm: { model: 'YOUR_MODEL', apiKey: process.env.OPENAI_API_KEY },
});

await ava.source({
  type: 'json',
  options: { data: [{ city: 'Hangzhou', revenue: 120 }] },
});

const schema = await ava.schema();
```

| Parameter | Type                   | Required | Meaning                                                                                                                                      |
| --------- | ---------------------- | -------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| `type`    | `SourceType`           | Yes      | `csv`, `csv-file`, `json`, `json-file`, `parquet`, `excel`, `text`, `sqlite`, `mysql`, `postgresql`, `mongodb`, `supabase`, `clickhouse`, `sqlserver`, `feishu-bitable`, `tencent-smartsheet`, or `notion`. |
| `options` | Source-specific object | Yes      | Use the matching table below. Field names are relative to `options`.                                                                         |

`source()` returns no value and prepares the data for execution. Schema discovery is deferred until `schema()` or another operation needs it. Calling `source()` again replaces the current source and clears its cached metadata. Use `schema()` to inspect table and field names, and call `await ava.dispose()` when finished.

The examples use Node.js. Supabase, ClickHouse, and SQL Server include their required constructor settings alongside the source call. For frontend applications, see [browser usage](/documentation/browser/).

## CSV

### Inline CSV

Pass the CSV content as a string with `type: 'csv'`.

```typescript
await ava.source({
  type: 'csv',
  options: { csv: 'city,revenue\nHangzhou,120\nShanghai,200' },
});
```

| Field     | Type             | Required | Meaning / default                          |
| --------- | ---------------- | -------- | ------------------------------------------ |
| `csv`     | `string`         | Yes      | Raw CSV content string                     |
| `options` | `CSVReadOptions` | No       | [CSV reader options](#csv-reader-options). |

### CSV files

Use `type: 'csv-file'` with a local path or HTTP(S) URL. For a protected URL, supply request headers in `options.headers`.

```typescript
await ava.source({
  type: 'csv-file',
  options: {
    path: 'https://example.com/sales.csv',
    headers: { Authorization: 'Bearer YOUR_TOKEN' },
    options: { header: true, delim: ';' },
  },
});
```

| Field     | Type                     | Required | Meaning / default                                    |
| --------- | ------------------------ | -------- | ---------------------------------------------------- |
| `path`    | `string`                 | Yes      | Local file path or http(s) URL                       |
| `headers` | `Record<string, string>` | No       | HTTP headers for remote sources (e.g. Authorization) |
| `options` | `CSVReadOptions`         | No       | [CSV reader options](#csv-reader-options).           |

### CSV reader options

Use these fields in `options.options` for `csv` and `csv-file` sources with DuckDB. Every field is optional. AVA forwards supplied values to `read_csv`; omitted values use DuckDB reader defaults or detection. Defaults below describe individual reader settings; automatic detection can determine the effective header, delimiter, and types.

| Field                  | Type                                 | Required | Meaning / default                                                                               |
| ---------------------- | ------------------------------------ | -------- | ----------------------------------------------------------------------------------------------- |
| `header`               | `boolean`                            | No       | First line of each file contains the column names. Default false                                |
| `names`                | `string[]`                           | No       | Column names, as a list                                                                         |
| `columns`              | `Record<string, string>`             | No       | Column names → types struct, e.g. &#123; col1: 'INTEGER' &#125;. Disables schema auto-detection |
| `types`                | `string[] \| Record<string, string>` | No       | Column types, by position (list) or by name (struct)                                            |
| `all_varchar`          | `boolean`                            | No       | Skip type detection and read all columns as VARCHAR. Default false                              |
| `normalize_names`      | `boolean`                            | No       | Remove non-alphanumeric chars from column names; prefix reserved keywords with \_               |
| `force_not_null`       | `string[]`                           | No       | Columns that must not be matched against the NULL string                                        |
| `delim`                | `string`                             | No       | Field delimiter (up to 4 bytes). Default ','                                                    |
| `quote`                | `string`                             | No       | Quote character. Default '"'                                                                    |
| `escape`               | `string`                             | No       | Escape character for the quote within quoted values. Default '"'                                |
| `comment`              | `string`                             | No       | Character used to initiate comments                                                             |
| `new_line`             | `string`                             | No       | New line character(s): '\r' \| '\n' \| '\r\n'                                                   |
| `auto_detect`          | `boolean`                            | No       | Auto detect CSV parameters. Default true                                                        |
| `auto_type_candidates` | `string[]`                           | No       | Types the sniffer considers when detecting column types, e.g. ['BIGINT', 'DATE']                |
| `dateformat`           | `string`                             | No       | Date format used when parsing dates                                                             |
| `timestampformat`      | `string`                             | No       | Timestamp format used when parsing timestamps                                                   |
| `decimal_separator`    | `string`                             | No       | Decimal separator for numbers. Default '.'                                                      |
| `thousands`            | `string`                             | No       | Thousands separator (single char, different from decimal_separator)                             |
| `nullstr`              | `string \| string[]`                 | No       | String(s) that represent a NULL value                                                           |
| `allow_quoted_nulls`   | `boolean`                            | No       | Allow the conversion of quoted values to NULL. Default true                                     |
| `sample_size`          | `number`                             | No       | Number of sample lines for auto detection. Default 20480                                        |
| `buffer_size`          | `number`                             | No       | Size of the read buffers in bytes. Default 16 \* max_line_size                                  |
| `files_to_sniff`       | `number`                             | No       | Files used by the sniffer for multi-file schema detection; -1 = all. Default 10                 |
| `max_line_size`        | `number`                             | No       | Maximum line size in bytes. Default 2000000                                                     |
| `parallel`             | `boolean`                            | No       | Use the parallel CSV reader. Default true                                                       |
| `skip`                 | `number`                             | No       | Number of lines to skip at the start of each file. Default 0                                    |
| `ignore_errors`        | `boolean`                            | No       | Ignore any parsing errors encountered. Default false                                            |
| `null_padding`         | `boolean`                            | No       | Pad short rows with NULL values on the right. Default false                                     |
| `strict_mode`          | `boolean`                            | No       | Throw an error upon encountering any issue. Default true                                        |
| `store_rejects`        | `boolean`                            | No       | Skip faulty lines and store them in the rejects table. Default false                            |
| `rejects_table`        | `string`                             | No       | Temp table name for faulty lines. Default 'reject_errors'                                       |
| `rejects_scan`         | `string`                             | No       | Temp table name for faulty scans. Default 'reject_scans'                                        |
| `rejects_limit`        | `number`                             | No       | Upper limit on faulty lines recorded per file; 0 = no limit. Default 0                          |
| `encoding`             | `string`                             | No       | File encoding: 'utf-8' \| 'utf-16' \| 'latin-1'. Default 'utf-8'                                |
| `compression`          | `string`                             | No       | Compression method: 'none' \| 'gzip' \| 'zstd'. Default auto (from file extension)              |
| `union_by_name`        | `boolean`                            | No       | Align columns from different files by name instead of position. Default false                   |
| `hive_partitioning`    | `boolean`                            | No       | Interpret the path as a Hive partitioned path. Default auto-detected                            |
| `filename`             | `boolean`                            | No       | Add the source file path to each row as a `filename` column. Default false                      |

## JSON

### Inline JSON

Pass an array of objects with `type: 'json'`.

```typescript
await ava.source({
  type: 'json',
  options: { data: [{ city: 'Hangzhou', revenue: 120 }] },
});
```

| Field  | Type    | Required | Meaning / default      |
| ------ | ------- | -------- | ---------------------- |
| `data` | `any[]` | Yes      | Array of rows to load. |
| `options` | `JSONReadOptions` | No | DuckDB reader parameters below. |

### JSON files

Use `type: 'json-file'` with a local path or HTTP(S) URL.

```typescript
await ava.source({
  type: 'json-file',
  options: {
    path: './sales.json',
    options: { columns: { city: 'VARCHAR', revenue: 'DOUBLE' }, sample_size: -1 },
  },
});
```

| Field     | Type                     | Required | Meaning / default                                    |
| --------- | ------------------------ | -------- | ---------------------------------------------------- |
| `path`    | `string`                 | Yes      | Local file path or http(s) URL                       |
| `headers` | `Record<string, string>` | No       | HTTP headers for remote sources (e.g. Authorization) |
| `options` | `JSONReadOptions` | No | DuckDB reader parameters below. |

### JSON reader options

Both JSON source types accept `options.options` when using the DuckDB engine. All fields are optional.
The complete [DuckDB JSON reader parameter list](https://duckdb.org/docs/current/data/json/loading_json) is exposed as `JSONReadOptions`:

| Parameter | Type | Default | Meaning |
| --- | --- | --- | --- |
| `auto_detect` | `boolean` | `true` | Infer schema |
| `columns` | `Record<string, string>` | Unset | Names → DuckDB types; selects columns |
| `compression` | `'auto_detect' \| 'none' \| 'gzip' \| 'zstd'` | `'auto_detect'` | Codec |
| `dateformat` | `string` | `'iso'` | Date pattern |
| `field_appearance_threshold` | `number` | `0.1` | Sparse-object MAP threshold |
| `filename` | `boolean` | `false` | Include filename in `SELECT *` |
| `format` | `'auto' \| 'unstructured' \| 'newline_delimited' \| 'array'` | `'auto'` | Input layout for `read_json` |
| `hive_partitioning` | `boolean` | Auto-detected | Path partitions |
| `ignore_errors` | `boolean` | `false` | Skip errors; NDJSON only |
| `map_inference_threshold` | `number` | `200` | STRUCT subfield limit; `-1` disables MAP inference |
| `maximum_depth` | `number` | `-1` | Inference depth; `-1` unlimited |
| `maximum_object_size` | `number` | `16777216` | Bytes per object |
| `maximum_sample_files` | `number` | `32` | Files sampled |
| `records` | `'auto' \| 'true' \| 'false'` | `'auto'` | Unpack objects |
| `sample_size` | `number` | `20480` | Objects sampled; `-1` scans all |
| `timestampformat` | `string` | `'iso'` | Timestamp pattern |
| `union_by_name` | `boolean` | `false` | Merge schemas |

Inline data is serialized as an uncompressed JSON array; choose compatible reader options.
Remote files are downloaded to temporary paths, so set `compression` explicitly for compressed URLs.

## Excel

Read an `.xlsx` workbook from a local path or HTTP(S) URL. Each selected worksheet becomes a separate table named after the sheet. Call `schema()` to inspect the resulting tables and columns.

```typescript
await ava.source({
  type: 'excel',
  options: {
    path: './sales.xlsx',
    sheets: [
      { sheet: 'Sales', range: 'A3:F100', header: true },
      { sheet: 'Costs', range: 'B2:C50', header: false },
    ],
  },
});
```

### Source options

| Field | Type | Required | Meaning / default |
| --- | --- | --- | --- |
| `path` | `string` | Yes | Local file path or HTTP(S) URL |
| `headers` | `Record<string, string>` | No | HTTP headers for remote sources, such as Authorization |
| `sheets` | `ExcelSheetOptions[]` | No | Sheets to load and their individual read settings; omitted loads all sheets with `header: true` |

### Sheet selection and reader options

Each entry in `sheets` contains a required `sheet` and optional `ExcelReadOptions` fields. Set these fields directly on the sheet entry, as shown above.

| Field | Type | Default | Meaning |
| --- | --- | --- | --- |
| `sheet` | `string` | Required | Exact worksheet name; also used as the table name |
| `range` | `string` | Inferred by the engine | Inclusive A1 rectangle, such as `B3:F100` |
| `header` | `boolean` | `true` | Use the first row of the selected range as column names; `false` keeps it as data |
| `all_varchar` | `boolean` | `false` | DuckDB only: read all cells as VARCHAR |
| `ignore_errors` | `boolean` | `false` | DuckDB only: replace cells that fail type conversion with NULL |
| `stop_at_empty` | `boolean` | `false` with `range`, otherwise `true` | DuckDB only: stop reading at the first empty row |
| `empty_as_varchar` | `boolean` | `false` | DuckDB only: infer empty cells as VARCHAR instead of DOUBLE |

A supplied `sheets` list must be non-empty, and every name must exist in the workbook and appear only once. Ranges must be valid, bounded A1 rectangles. Invalid selections and unsupported fields are rejected.

### Engine behavior

Both engines support `sheet`, `range`, and `header`. The Python engine rejects the four DuckDB-only options in the table above.

DuckDB reader options follow [`read_xlsx`](https://duckdb.org/docs/current/core_extensions/excel#reading-xlsx-files), except that AVA defaults `header` to `true` instead of inferring it. For example, to preserve mixed cell types as text and continue past empty rows:

```typescript
await ava.source({
  type: 'excel',
  options: {
    path: './sales.xlsx',
    sheets: [{ sheet: 'Sales', all_varchar: true, stop_at_empty: false }],
  },
});
```

DuckDB rejects workbooks containing sheet names with literal XML entity text, such as `Sales &amp; Tax`, because its Excel extension can confuse them with another sheet. Rename those sheets or use the Python engine. Ordinary ampersands, quotes, and Unicode names are supported.

## Feishu Bitable

Use `type: 'feishu-bitable'` with the DuckDB engine in Node.js. Rows are exposed as one read-only view named `data`.

```typescript
await ava.source({
  type: 'feishu-bitable',
  options: {
    url: 'https://my.feishu.cn/base/APP_TOKEN?table=TABLE_ID',
    appId: process.env.AVA_FEISHU_APP_ID,
    appSecret: process.env.AVA_FEISHU_APP_SECRET,
  },
});
```

Provide `url`, or both `appToken` and `tableId`, along with `appId` and `appSecret`. The CLI also reads credentials from `AVA_FEISHU_APP_ID` / `AVA_FEISHU_APP_SECRET` or `~/.ava/feishu.json`.

Both `/base/` and wiki-hosted `/wiki/` links are supported. Wiki links require wiki read access and wiki space membership so the app can resolve the Bitable. The `view` query parameter is ignored. Complex cells (people, attachments, links, formulas, locations, and groups) are flattened to comma-separated text.

### Forwarded client fields

`ClickHouseSourceOptions` also accepts the following fields from `@clickhouse/client`. This table follows the installed client type declarations (1.23.1); these fields are owned by that dependency. AVA forwards them when creating the client.

| Field                          | Type                          | Default / meaning                                                                                          |
| ------------------------------ | ----------------------------- | ---------------------------------------------------------------------------------------------------------- |
| `pathname`                     | `string`                      | Empty; extra proxy path.                                                                                   |
| `request_timeout`              | `number`                      | `30000` milliseconds.                                                                                      |

## Notion

Load one authorized Notion database as a read-only snapshot through the official [Notion REST API](https://developers.notion.com/reference/post-database-query), then analyze a complete local snapshot with DuckDB. This source is available in the Node.js SDK, not the browser/Python/JavaScript engines. The existing CLI dataset sessions require macOS/Linux; use the SDK or WSL on Windows.

```typescript
await ava.source({
  type: 'notion',
  options: { databaseId: '<database-id>' },
});
```

Set `NOTION_TOKEN` to an integration/bot token from the [Notion integrations page](https://www.notion.so/profile/integrations). The integration must be a member of the database's parent page and hold read access; a token with write access is still read-only through this connector. IDs are explicit; database sharing URLs are not auto-detected.

For the CLI, put the same source configuration in a JSON file and run `ava source @notion.json`. Keep the token in the environment, not in the file.

|| Field | Type | Required / default |
|| --- | --- | --- |
|| `databaseId` | `string` | Required; the Notion database UUID. |
|| `token` | `string` | Optional; overrides `NOTION_TOKEN`. |
|| `pageSize` | `number` | 1–100; default 100 pages per request. |
|| `maxRecords` | `number` | 1–100,000; default 10,000. Overflow fails, not truncates. |
|| `timeoutMs` | `number` | 1–110,000; default 60,000 ms for the whole load. |
|| `maxRetries` | `number` | 0–5; default 2 for transient failures. |
|| `version` | `string` | Notion-Version header; default `2022-06-28`. |

Supported Notion property types are `title`, `rich_text`, `number`, `select`, `multi_select`, `status`, `date`, `checkbox`, `url`, `email`, `phone_number`, `created_time`, `last_edited_time`, `created_by`, `last_edited_by`, `people`, `unique_id`, plus numeric/string/boolean `formula` and `rollup`. Other property types (`files`, `relation`, `button`, `place`, `verification`) are omitted. Property names become column names; `_id` preserves the source page id. Duplicate/reserved column names and invalid supported values fail the load. Numbers use `DOUBLE`, dates use UTC `TIMESTAMPTZ`, omitted properties use null, and empty pages are retained. Empty databases keep their declared column types.

Pages are fully cursor-paginated. Missing/repeated page ids and inconsistent cursors fail instead of silently loading partial data. Limits are 2,000 properties and 16 MiB for response streams/paginated reads. Expanded snapshots have independent limits of 16 MiB of UTF-8 JSON and 1,000,000 cells (including `_id`); the effective page limit is also capped by `floor(1000000 / (supported property count + 1))`. Validated pages are converted incrementally; no complete raw page array is retained, and over-budget dense rows are not retained. After loading, data is materialized in memory and its temporary JSON file is deleted. Authentication, permission and rate-limit failures are not retried. Upstream error codes/messages and network causes are preserved; HTTP failures retain status and up to 8 KiB of response diagnostics. The configured token is redacted. The connector calls only the database retrieve and database query endpoints; the model cannot access any page write or create/update/delete operation.

This is a load-time snapshot, not live synchronization. Stop source edits during loading: the provider does not expose a transactional multi-page snapshot, so same-count edits cannot be detected. Model-based analysis uses the configured model provider; use non-sensitive test data for initial validation.

Natural-language examples include aggregating tasks by status (`按状态统计每个状态的任务数和金额总和`) and counting tasks per month from a date property (`按月份统计任务数量`). The example scripts in `examples/notion` reproduce both against a synthetic dataset.

See the [reproducible task example](https://github.com/antvis/AVA/tree/oss-camp2026/examples/notion) for configuration, optional synthetic fixture setup, status aggregation and monthly analysis with numerical assertions.

## Tencent Docs SmartSheet

Load one explicitly selected, authorized SmartSheet subtable through Tencent Docs' native OpenAPI (`fetch`, no MCP SDK), then analyze a complete local snapshot in DuckDB. Node.js SDK only, not browser/Python/JavaScript engines. Existing CLI sessions require Linux/macOS; Windows users can use the SDK or WSL.

```typescript
await ava.source({
  type: 'tencent-smartsheet',
  options: {
    fileId: '<native-openapi-file-id>',
    sheetId: '<sheet-id>',
    clientId: '<client-id>',
    openId: '<open-id>',
    accessToken: '<access-token>',
  },
});
```

Explicitly supply `options.clientId`, `options.openId`, `options.accessToken` from an approved application's [OAuth authorization](https://docs.qq.com/open/document/app/oauth2/). The user must have access and the application must have the required approved/authorized permissions. Client Secret is needed for token exchange outside AVA, not record reads. There is no embedded OAuth callback or auto-refresh. **Migration:** remove MCP `token` / `TENCENT_DOCS_TOKEN`; old token options are rejected, never treated as OpenAPI credentials.

IDs are explicit: `fileId` must be the native OpenAPI fileID, not a sharing URL's encoded ID. The [official ID-conversion endpoint](https://docs.qq.com/open/document/app/openapi/v2/file/util/converter.html) converts an explicitly supplied encoded ID using its own permission requirements. AVA never lists/searches private files or automatically converts IDs during loading. Obtain `sheetID` from the documented [subtable-list endpoint](https://docs.qq.com/open/document/app/openapi/v2/smartsheet/sheet/get_sheet.html) using your own authorized API client.

The loader does not read environment variables. Applications may resolve configuration themselves and pass it through options. For CLI, pass all credentials in a local, untracked source JSON file; environment placeholders are not expanded.

| Field | Type | Required / default |
| --- | --- | --- |
| `fileId` | `string` | Required; native OpenAPI fileID (not encoded sharing ID). |
| `sheetId` | `string` | Required; explicit SmartSheet sheetID. |
| `clientId` | `string` | Required; explicitly supplied in options. |
| `openId` | `string` | Required; explicitly supplied in options. |
| `accessToken` | `string` | Required; explicitly supplied in options. |
| `pageSize` | `number` | 1–100; default 100, field and record pages. |
| `maxRecords` | `number` | 1–100,000; default 10,000. Overflow fails, never truncates. |
| `timeoutMs` | `number` | 1–110,000; default 60,000 ms for the whole load. |
| `maxRetries` | `number` | 0–5; default 2 for transient HTTP/network failures. |

Supported native numeric `fieldType` values are **1 text, 2 number, 3 checkbox, 4 date/time, 12 created time, 13 modified time, 14 progress, 15 phone, 16 email, 17 single-select, 26 currency, 28 percentage**. These use the [official numeric type/attribute contract](https://docs.qq.com/open/document/app/openapi/v2/smartsheet/field/property.html#fieldtype) and [cell value contract](https://docs.qq.com/open/document/app/openapi/v2/smartsheet/record/value.html#value), not MCP string enums. Rich text is concatenated; numbers/progress/currency/percentage retain finite raw `DOUBLE` values without percentage scaling; booleans preserve false; phone/email preserve strings and leading zeros; dates use millisecond strings normalized to UTC. For native types 12/13 only, omitted cells use the source record createTime/updateTime millisecond metadata: the real v2 response omits these system cells from values. Explicit values and explicit nulls are never overwritten; ordinary dates/titles do not trigger this mapping. A separately approved synthetic fixture has now verified all six restored types against the real API and formal loader on Windows/Linux, including exact comparisons with independently read record timestamps. Single-select 17 becomes text (empty selection is null); type 9 remains unsupported multi-select.

The legacy v2 enum page is incomplete: independent native currency 26 and percentage 28 were identified through official service metadata and verified with native OpenAPI field creation, record reads and the formal loader. Both retain finite raw DOUBLE values (0.125 stays 0.125), without display parsing or automatic percentage scaling. This does not assert every currency/UI rendering format has been tested; do not infer types from titles. See the [field contract and evidence notes](https://github.com/antvis/AVA/blob/oss-camp2026/examples/tencent-docs/README.md). Other types, including images/computed fields, are omitted. Source titles become columns; `_record_id` preserves identity. Duplicate/reserved names and malformed supported values fail the load. Null/omitted cells, empty rows/tables and all-null column types retain their semantics. Numbers are not exact financial decimals.

Both HTTP status and OpenAPI `ret` are checked. HTTP 429/500/502/503/504 and network failures have bounded retries; valid `Retry-After` waits up to 30 seconds are honored. HTTP 401/403 and business errors are not retried (no unverified MCP error policy). Preserve upstream `ret`/`msg`, HTTP status/request IDs and selected network error name/message/code plus one cause level. Do not copy arbitrary response/error objects, stacks or headers. Exact credentials are replaced in selected strings; fields over 8 KiB are omitted whole, not truncated. Non-JSON or incomplete HTTP error bodies are omitted while status/request ID remain available. Endpoint and read operations are fixed; redirects are refused. The model cannot choose remote writes.

Fields and records are fully paginated; missing/repeated IDs, inconsistent offsets/totals, changing supported metadata and incomplete final pages fail instead of returning partial data. Limits: 1,000 fields, 16 MiB per response/paginated read, independently 16 MiB expanded UTF-8 JSON and 1,000,000 cells including names/nulls/record IDs. Effective rows are additionally capped by `floor(1000000 / (supported field count + 1))`. Conversion is incremental, without retaining all raw records. A parameterized JSON array and explicit schema create the in-memory table directly, without temporary files or a directory whitelist.

Stop editing while loading: same-count changes cannot all be detected, and this is not a transactional remote snapshot or continuous sync. Multi-table JOIN, discovery, views/field selection, ordinary spreadsheet ranges and writes are outside this migration. Model analysis uses your configured provider; start with synthetic data.

See the [reproducible sales example](https://github.com/antvis/AVA/tree/oss-camp2026/examples/tencent-docs) for authorization/configuration, native-ID conversion, manual fixture setup, two natural-language business examples, exact numerical assertions and current validation evidence.
