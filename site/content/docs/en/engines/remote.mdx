## Supabase

```typescript
const ava = new AVA({
  llm: { model: 'YOUR_MODEL', apiKey: process.env.OPENAI_API_KEY },
  engine: { type: 'supabase' },
});
await ava.source({
  type: 'supabase',
  options: {
    projectRef: 'YOUR_PROJECT_REF',
    accessToken: process.env.SUPABASE_ACCESS_TOKEN!,
  },
});
```

The engine discovers schema on demand and executes PostgreSQL queries through the Supabase Management API using read-only requests. Your application handles obtaining and refreshing the access token. Query results are returned to AVA and can be sent to the model for analysis summaries.

## ClickHouse

```typescript
const ava = new AVA({
  llm: { model: 'YOUR_MODEL', apiKey: process.env.OPENAI_API_KEY },
  engine: { type: 'clickhouse' },
});
await ava.source({
  type: 'clickhouse',
  options: {
    url: 'http://localhost:8123',
    database: 'analytics',
    username: 'reader',
    password: process.env.CLICKHOUSE_PASSWORD,
  },
});
```

Use `url` or `host`, with a required `database`. `username` takes precedence over the `user` alias. Queries use the official ClickHouse client with read-only settings.

## SQL Server

```typescript
const ava = new AVA({
  llm: { model: 'YOUR_MODEL', apiKey: process.env.OPENAI_API_KEY },
  engine: { type: 'sqlserver' },
});
await ava.source({
  type: 'sqlserver',
  options: {
    server: 'sql.example.com',
    database: 'sales',
    user: 'reader',
    password: process.env.SQLSERVER_PASSWORD,
  },
});
```

Serves schema discovery and read-only T-SQL execution through the `tedious` driver, with `ApplicationIntent=ReadOnly` and a local read-only guard on every statement. Without a live server, pass `adapter: 'mock'` (plus `tables`) to run the same contract against an in-memory runner.

## Shared workflow

All engines support `schema()`, `profile()`, `translate()`, `query()`, and `analyze()`. Set the matching source and engine types in the JavaScript API. Release resources with `await ava.dispose()` after use.

See [Supabase parameters](/documentation/data/sources/#supabase), [ClickHouse options](/documentation/data/sources/#clickhouse), and [SQL Server options](/documentation/data/sources/#sql-server) for complete configuration tables.
