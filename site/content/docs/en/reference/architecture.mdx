## Public entry points

[`index.ts`](https://github.com/antvis/AVA/blob/ai/src/index.ts) registers all Node.js engines and exports `AVA` plus public types. [`index.browser.ts`](https://github.com/antvis/AVA/blob/ai/src/index.browser.ts) registers only JavaScript. [`ava.ts`](https://github.com/antvis/AVA/blob/ai/src/ava.ts) coordinates source state, data model, events, and engine lifecycle.

Contracts follow the public API. `source/` owns source configurations and its CSV/JSON/Excel reader options. `schema.ts`, `profile.ts`, `semantic.ts`, `query.ts`, `analyze.ts` and `suggest.ts` define each API's public inputs and outputs. `visualize.ts` holds the chart specification shared by `recommend()`, `viz()` and `visualize()`, plus explicit chart bindings. Cross-API JSON values and data-model building blocks live in `shared/`.

Runtime strategy, dialect and per-engine interfaces stay with their implementations. The data-model builder owns its stricter assembly input validation, derived from the public metadata fields. Internal modules import the defining module directly; public entry points keep the existing exports. CLI wire messages, AI-stage response formats and interpreter-specific restrictions remain local to their modules.

## Context and state

An AVA instance owns one active engine and its schema/profile cache. `source()` loads data; `schema()` discovers structure on first use. `profile()` computes and retains fresh observations; the data model is assembled from cached metadata when needed. Reloading or disposal clears both caches.

Engines retain data and connections. Their `load()` returns no metadata; `schema()` discovers it, `profile(schema, options?)` computes observations, and `getDSL(query, dataModel)` consumes AVA's data model. Shared data validators live in `contracts/`; catalog assembly and metric execution helpers stay in `util/`.

Analysis strategies share a runtime containing the engine, model configuration, data model, and event emitter. Query result limits are normalized through shared utilities.

## Documentation organization

Each topic is a separate MDX file under `site/content/docs/`, grouped into `data/`, `analysis/`, `visualization/`, `engines/`, and `reference/`. This mirrors the public capabilities without exposing every internal helper as a separate user-facing page.
