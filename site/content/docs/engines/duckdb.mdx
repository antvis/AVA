## Configure

```typescript
const ava = new AVA({
  llm: { model: 'YOUR_MODEL', apiKey: process.env.OPENAI_API_KEY },
  engine: {
    type: 'duckdb',
    memoryLimit: '512MB',
    threads: 1,
    queryTimeoutMs: 30000,
    maxTempDirectorySize: '1GB',
  },
});
```

DuckDB 2.0 LTS is the default Node.js engine, using `@duckdb/node-api` 2.0. It creates an in-memory instance and registers the source as tables or views. SQL generation uses the schema and optional profile.

## Native JSON loading

AVA loads JSON into a typed `data` table once during `source()`. Nested objects and arrays become `STRUCT` and `LIST` columns. Schema discovery, profiles and queries reuse that table, so later source-file changes do not affect the session. Resource limits apply during ingestion.

Start with automatic inference. For heterogeneous fields, use a `JSON` column type; `columns` selects only the listed fields. AVA forwards reader options without rewriting types. See [JSON source configuration](/documentation/data/sources/#json-reader-options) for options and examples.

For reader behavior and DuckDB 2.0 types, see <a href="https://duckdb.org/docs/2.0/data/json/loading_json"><img src="/logos/duckdb.svg" alt="" width="16" height="16" className="inline-block align-text-bottom" /> JSON loading</a> and <a href="https://duckdb.org/docs/2.0/sql/data_types/variant"><img src="/logos/duckdb.svg" alt="" width="16" height="16" className="inline-block align-text-bottom" /> VARIANT</a>.

## Engine options

Set `engine.type` to `duckdb`. These are all additional fields accepted on `engine`.

| Field                      | Type      | Required | Meaning / default                                                               |
| -------------------------- | --------- | -------- | ------------------------------------------------------------------------------- |
| `memoryLimit`              | `string`  | No       | Memory limit, e.g. '512MB'. Default '512MB'.                                    |
| `threads`                  | `number`  | No       | Number of worker threads. Default 1.                                            |
| `maxTempDirectorySize`     | `string`  | No       | Max size of the spill (temp) directory, e.g. '1GB'. Unset = unlimited.          |
| `queryTimeoutMs`           | `number`  | No       | Per-query timeout in milliseconds. Default 30000.                               |
| `allowCommunityExtensions` | `boolean` | No       | Allow DuckDB community extensions during source loading when explicitly needed. |

## Asynchronous file reads

AVA uses DuckDB's native file readers and default I/O settings; no asynchronous I/O configuration is needed. HTTP(S) CSV, JSON and Parquet URLs are read directly through `httpfs`. Supply request headers in the source options when needed:

```typescript
const ava = new AVA({
  llm: { model: 'YOUR_MODEL', apiKey: process.env.OPENAI_API_KEY },
  engine: { type: 'duckdb' },
});

await ava.source({
  type: 'parquet',
  options: {
    path: 'https://example.com/sales.parquet',
    headers: { Authorization: 'Bearer YOUR_TOKEN' },
  },
});

const result = await ava.engine!.execute(`
  SELECT region, SUM(revenue) AS revenue
  FROM data WHERE year = 2026 GROUP BY region
`);
await ava.dispose();
```

AVA installs `httpfs` before locking configuration and scopes supplied headers and file access to the source URL. CSV and Parquet remain live views: their files or URLs must stay available for subsequent queries. Use immutable URLs for repeatable analysis. JSON queries use the snapshot loaded during `source()`. Remote Excel workbooks are downloaded for local sheet inspection.

Parquet supports selective reads when the server supports HTTP Range requests; CSV aggregations often transfer the whole file. For supported asynchronous reads and remote-file behavior, see <a href="https://duckdb.org/docs/2.0/data/io"><img src="/logos/duckdb.svg" alt="" width="16" height="16" className="inline-block align-text-bottom" /> DuckDB I/O</a> and <a href="https://duckdb.org/docs/2.0/core_extensions/httpfs/https"><img src="/logos/duckdb.svg" alt="" width="16" height="16" className="inline-block align-text-bottom" /> HTTP(S) support</a>.

## Resource limits

Defaults are 512 MB of memory, one worker thread, and a 30-second query timeout. `maxTempDirectorySize` is optional; no spill-size limit is configured when omitted.

These options are separate from `maxRows` and `maxResultBytes`, which bound returned query results.

## Source support

DuckDB supports inline CSV, JSON, and text; local or remote CSV, JSON, Parquet, and Excel; and MySQL, PostgreSQL, SQLite, and MongoDB sources. See [data sources](/documentation/data/sources/) for configuration.

## Query access

After source registration, the engine restricts external access and locks configuration. Queries must be a single read-only SELECT; write operations are rejected, including those inside nested CTEs. Community extensions are disabled by default, with handling for sources such as MongoDB that require them; `allowCommunityExtensions` explicitly enables them when needed.
