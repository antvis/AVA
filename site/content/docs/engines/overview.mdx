For Node.js file and inline-data workflows, you can usually omit engine configuration and specify the data source in `source()`. Configure an execution engine when you need browser execution, Python/pandas, direct Supabase or ClickHouse queries, or custom execution behavior.

## Engine selection

Set the engine in the `AVA` constructor. In the JavaScript API, omitting it always selects DuckDB; source type does not change this selection automatically.

| Engine | Query language | Sources | Runtime |
| --- | --- | --- | --- |
| [DuckDB](/documentation/engines/duckdb/) | SQL | Inline data, files, MySQL, PostgreSQL, SQLite, MongoDB, Feishu Bitable / Lark | Node.js; default |
| [JavaScript](/documentation/engines/javascript/) | JavaScript | Inline CSV, JSON, text | Node.js and browser |
| [Python](/documentation/engines/python/) | Python / pandas | Inline CSV / JSON; CSV / JSON / Parquet / Excel files | Node.js + Python executor |
| [Supabase](/documentation/engines/remote/#supabase) | PostgreSQL SQL | Supabase project | Node.js; remote execution |
| [ClickHouse](/documentation/engines/remote/#clickhouse) | ClickHouse SQL | ClickHouse database | Node.js; remote execution |

## Engine configuration

| Field         | Type                                                                                         | Required                  | Default / behavior                |
| ------------- | -------------------------------------------------------------------------------------------- | ------------------------- | --------------------------------- |
| `engine.type` | `'duckdb'` / `'javascript'` / `'python'` / `'supabase'` / `'clickhouse'` / a registered name | When `engine` is provided | Omitting `engine` selects DuckDB. |

Additional fields depend on `type`: [DuckDB options](/documentation/engines/duckdb/#engine-options) and [Python options](/documentation/engines/python/#engine-options). JavaScript, Supabase, and ClickHouse accept no additional constructor engine fields. Database credentials belong to [source parameters](/documentation/data/sources/#connect-a-source).

To run Python in your own service, see [Supply a Python executor](/documentation/engines/python/#supply-a-python-executor). To supply an engine from your application, see [Custom engines](/documentation/engines/custom/).

## Shared contract

Engines load data, discover schema, compute profiles, generate queries from supplied context, execute them, and release resources. AVA owns schema/profile caching and decides when discovery or computation is needed.

Applications normally use the `AVA` API. Implementers should follow the [engine contract](/documentation/engines/custom/#engine-contract), including separate `load()` and `schema()` methods.

## Registration

The Node.js entry point registers all five engines; the browser entry point registers JavaScript only. The registry keeps the core `AVA` class independent of platform-specific imports.

For SDK extensions, call `registerEngine('sales', SalesEngine)`, then select `engine: { type: 'sales' }`. See [Custom engines](/documentation/engines/custom/) for the contract and a complete example.
