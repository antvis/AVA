`Schema` describes the structure of your data. `Profile` adds statistics such as row counts, minimums, and averages. Both belong to the currently loaded source.

## Read the schema

Load a source, then ask AVA for its structure:

```typescript
await ava.source({
  type: 'json',
  options: { data: [{ region: 'East', revenue: 120 }] },
});

const schema = await ava.schema();
console.log(schema.tables);
```

`source()` only loads the data. The first `schema()` call reads the structure through the engine and saves it; later calls return the saved schema. Analysis and profiling also obtain the schema when needed.

## Schema structure

| Property | Meaning |
| --- | --- |
| `tables` | Tables or views available for queries |
| `tables[].name` | Table name |
| `tables[].columnCount` | Number of columns |
| `tables[].fields` | Column names, types, and optional nullability |
| `tables[].indexes` | Index definitions, including primary keys when available |
| `relations` | Foreign-key relationships, when available |

The available details depend on the source and engine. A query result's `schema` describes only its output columns; it is not a source `Schema`.

## Profile a dataset

Call `profile()` to calculate statistics through the engine:

```typescript
const profile = await ava.profile({ metrics: ['row_count', 'mean'] });
console.log(profile.tables[0].metrics);
console.log(profile.tables[0].fields);
```

Each call calculates fresh statistics and saves the returned profile. Analysis, translation, and suggestions can then use it. Profiling requires engine support and does not call an LLM.

## Select metrics

Omit options to use the default metrics, or pass `metrics` to choose your own set:

```typescript
await ava.profile();
await ava.profile({ metrics: ['min', 'max'] });
```

The defaults are `row_count`, `null_count`, `distinct_count`, `top_values`, `min`, `max`, and `mean`. Additional built-in metrics include `duplicate_count`, `min_length`, `max_length`, `sum`, `stddev`, and `median`.

Metrics apply to compatible tables or columns. A supplied list replaces the defaults; `metrics: []` produces empty metric objects. See the [API reference](/documentation/reference/api/#profile) for metric options.

## Profile format

A profile includes the schema and these additional fields:

| Property | Meaning |
| --- | --- |
| `tables[].metrics` | Table statistics, such as `row_count` |
| `tables[].fields[].metrics` | Column statistics, such as `mean` |
| `tables[].fields[].logicalType` | Column category, such as `numeric` or `string` |
| `generatedAt` | Creation time in Unix milliseconds |

A missing metric means it was not computed. It does not mean zero.

## Supply metadata

If you already have a schema or profile, pass a **setter** as the second argument. A setter is simply a function that returns the value you want AVA to use.

Here, `savedSchema` and `savedProfile` are results you saved from earlier calls:

```typescript
await ava.schema(undefined, () => savedSchema);
await ava.profile(undefined, () => savedProfile);
```

AVA uses the setter's return value instead of asking the engine. Omit the setter to use the normal engine behavior:

```typescript
await ava.schema();  // Read the saved schema, or discover it through the engine.
await ava.profile(); // Calculate a fresh profile through the engine.
```

The first argument is options. `undefined` uses the default `{}`. If the setter needs options, it receives that same object as its argument. Schema currently has no configurable options.

Setting a schema replaces the saved schema and clears the saved profile, so set the schema first when supplying both. Setting a profile replaces only the profile. AVA validates and copies each returned value; a thrown error or invalid value leaves the previous metadata unchanged.

Use metadata that matches the loaded data. Loading another source or calling `dispose()` clears both saved values.
