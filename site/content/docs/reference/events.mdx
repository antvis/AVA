## Listen to events

AVA emits events while loading data, analyzing questions, and performing other operations. Subscribe by event name, or use `'*'` for every event:

```typescript
import { AVA } from '@antv/ava';

const ava = new AVA({ llm: { model: 'your-model' } });
const listener = (event) => console.log(event.type, event.data);

ava.on('*', listener);
try {
  await ava.source({ type: 'json', options: { data: [{ sales: 120 }] } });
} finally {
  ava.off('*', listener);
  await ava.dispose();
}
```

Each event has a lowercase `type` and a `data` object. For example, `sourcestart` has `data: { type: 'json' }`. Event classes and constants are not exported by the public package; use the names below as strings.

Most operations emit a start and an end event. A failed operation emits an end event with `data.error: { message, name? }` and rejects its Promise. Check for `error` before treating an end event as a success. A precondition failure, such as a missing source, can occur before the start event.

## Lifecycle events

These events mark AVA operations. Successful end events have empty data (`{}`).

| Operation | Start event | Start data | End event |
| --- | --- | --- | --- |
| Create or dispose an engine | `createstart` / `disposestart` | `{}` | `createend` / `disposeend` |
| Load a source | `sourcestart` | `{ type }` | `sourceend` |
| Discover or set schema | `schemastart` | `{}` | `schemaend` |
| Compute or set profile | `profilestart` | `{}` | `profileend` |
| Set semantic definitions | `semanticstart` | `{}` | `semanticend` |
| Analyze a question | `analyzestart` | `{ query }` | `analyzeend` |
| Visualize a result | `visualizestart` | `{ query }` | `visualizeend` |
| Suggest questions | `suggeststart` | `{}` | `suggestend` |

Cached schema reads and semantic reads do not emit events. `recommend()` and `viz()` do not emit their own events.

## Analysis events

These events describe steps within analysis. Direct calls to `translate()` and `query()` emit the same translation and query events.

| Step | Start event and data | End event and successful data |
| --- | --- | --- |
| Translate a question | `translatestart`: `{ query }`; direct analysis also includes `attempt` | `translateend`: `{ dsl }` |
| Execute a query | `querystart`: `{ dsl }` | `queryend`: `ExecutionResult` |
| Summarize results | `summarizestart`: `{}` | `summarizeend`: `{ text }` |
| Loop reasoning | `reasonstart`: `{ step }` | `reasonend`: `{ step, action, text }` |

Failed end events carry `{ error }`. A reasoning failure also carries `step`; the final fallback includes `finalAttempt: true` on both events. See [analysis strategies](/documentation/analysis/strategies/) for these steps.

For example, a successful direct `analyze()` typically emits:

```text
analyzestart → translatestart → translateend → querystart → queryend
             → summarizestart → summarizeend → analyzeend
```

Retries can repeat translation and query events. The summary is omitted when `includeSummary` is `false`. Concurrent operations can interleave; events do not contain an operation ID.

## Listener parameters

| Method | Behavior |
| --- | --- |
| `on(name, listener, once?)` | Subscribe; the optional `once` flag defaults to `false`. |
| `once(name, listener)` | Subscribe for one invocation. |
| `off(name?, listener?)` | Remove a listener, all listeners for a name, or all listeners if omitted. Pass the same listener reference used to subscribe. |
| `emit(name, ...args)` | Emit an event manually. |
| `getEvents()` | Return the listener registry. |

These methods are synchronous; `on`, `once`, and `off` return the emitter. Synchronous listener errors propagate, and asynchronous listeners are not awaited. Event data is not copied; use `structuredClone(event)` if you need a snapshot.
