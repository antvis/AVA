Use this reference to look up inputs after following the [quickstart](/documentation/quickstart/). Types and defaults below follow the current `src/ava.ts` implementation. All instance methods listed here are asynchronous.

## Constructor

`new AVA(config: AVAConfig)`

| Parameter       | Type           | Required | Default / behavior                                            |
| --------------- | -------------- | -------- | ------------------------------------------------------------- |
| `config`        | `AVAConfig`    | Yes      | Configuration object.                                         |
| `config.llm`    | `LLMConfig`    | Yes      | [Model fields below](#model-options).                         |
| `config.engine` | `EngineConfig` | No       | `{ type: 'duckdb' }`; [engine fields below](#engine-options). |

The constructor does not load data. Engine creation happens on `source()`.

### Model options

Fields below belong to `config.llm`.

| Field          | Type                                  | Required | Meaning / default                                                                 |
| -------------- | ------------------------------------- | -------- | --------------------------------------------------------------------------------- |
| `provider`     | `'openai' \| 'gateway'`               | No       | Defaults to OpenAI-compatible Chat Completions. Gateway reads AI_GATEWAY_API_KEY. |
| `model`        | `string \| LanguageModel`             | Yes      | Model name or a preconfigured AI SDK model instance.                              |
| `apiKey`       | `string`                              | No       | API key for the LLM provider                                                      |
| `baseURL`      | `string`                              | No       | Optional API base URL                                                             |
| `maxRetries`   | `number`                              | No       | Maximum retries for retryable model API failures. Default 3.                      |
| `onQueryUsage` | `(usage: LanguageModelUsage) => void` | No       | Optional callback for SQL-generation token usage                                  |

String model names use OpenAI-compatible **Chat Completions** by default. A supplied model object is used directly. Usage callbacks are not a complete accounting stream for every LLM request.

### Engine options

`config.engine.type` is required when `engine` is supplied. Supported values are `duckdb`, `python`, `javascript`, `supabase`, and `clickhouse`, plus names registered through `registerEngine()`. Omitting `engine` selects DuckDB. JavaScript, Supabase, and ClickHouse accept no additional engine fields; connection credentials belong to `source()`.

#### DuckDB

Set `engine.type` to `duckdb`. These are all additional fields accepted on `engine`.

| Field                      | Type      | Required | Meaning / default                                                               |
| -------------------------- | --------- | -------- | ------------------------------------------------------------------------------- |
| `memoryLimit`              | `string`  | No       | Memory limit, e.g. '512MB'. Default '512MB'.                                    |
| `threads`                  | `number`  | No       | Number of worker threads. Default 1.                                            |
| `maxTempDirectorySize`     | `string`  | No       | Max size of the spill (temp) directory, e.g. '1GB'. Unset = unlimited.          |
| `queryTimeoutMs`           | `number`  | No       | Per-query timeout in milliseconds. Default 30000.                               |
| `allowCommunityExtensions` | `boolean` | No       | Allow DuckDB community extensions during source loading when explicitly needed. |

#### Python

Set `engine.type` to `python`. These are all additional fields accepted on `engine`.

| Field            | Type                                         | Required | Meaning / default                                                                                                                                                                                                                                                                         |
| ---------------- | -------------------------------------------- | -------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `execute`        | `(code: string) => Promise<ExecutionResult>` | No       | Override local python3 execution with a custom environment. Local execution is not sandboxed. Run the complete Python script and return its JSON output as ExecutionResult. Source loading and result limits are included in the script; configure remote execution deadlines separately. |
| `queryTimeoutMs` | `number`                                     | No       | Client wait limit and local process execution deadline. Default 30000 ms.                                                                                                                                                                                                                 |

#### Registered engines

Set `engine.type` to the name passed to `registerEngine()`. Additional fields are forwarded to the engine constructor as `options`. This is an SDK-only capability; the CLI supports built-in engine names.

| Field        | Type            | Required          | Meaning / default                          |
| ------------ | --------------- | ----------------- | ------------------------------------------ |
| `type`       | `string`        | Yes               | Registered engine name, such as `'sales'`. |
| Other fields | Engine-specific | Depends on engine | Validated by the registered engine.        |

## registerEngine

`registerEngine(type: string, engineClass: EngineClass): void`

Exported by both SDK entry points. Register an engine implemented in your own application before loading a source.

| Parameter     | Type                                                                              | Required | Meaning                                                                                             |
| ------------- | --------------------------------------------------------------------------------- | -------- | --------------------------------------------------------------------------------------------------- |
| `type`        | `string`                                                                          | Yes      | Engine name. Re-registering replaces the constructor used for future loads.                         |
| `engineClass` | `new (llmConfig: LLMConfig, options?: Record<string, unknown>) => AnalysisEngine` | Yes      | Engine class. AVA passes its model configuration and remaining engine options to each new instance. |

Registration affects the loaded SDK module only. See [Custom engines](/documentation/engines/custom/) for a complete external implementation and lifecycle details.

## source

```typescript
source(config: DataSourceConfig): Promise<void>
```

Loads a data source through the engine. It returns no value and does not discover the schema.

```typescript
await ava.source({ type: 'json', options: { data: [{ revenue: 120 }] } });
```

| Parameter | Type | Required | Meaning |
| --- | --- | --- | --- |
| `config` | `DataSourceConfig` | Yes | Data source to load. |
| `config.type` | `SourceType` | Yes | [Source type](/documentation/data/sources/#connect-a-source), such as `json` or `csv-file`. |
| `config.options` | Source-specific object | Yes | [Reader or connection settings](/documentation/data/sources/#connect-a-source) for that type. |

Loading a source disposes the previous engine and clears the saved schema and profile. A failed load leaves no active source. Await pending operations before replacing a source.

## schema

```typescript
schema(options?: SchemaOptions, setter?: (options: SchemaOptions) => OldSchema): Promise<OldSchema>
```

Returns the structure of the loaded source. Without a setter, AVA returns the saved schema or discovers it through the engine and saves it.

```typescript
const schema = await ava.schema();
```

To supply an existing schema, pass a function that returns it:

```typescript
await ava.schema(undefined, () => savedSchema);
```

| Parameter | Type | Required | Meaning / default |
| --- | --- | --- | --- |
| `options` | `SchemaOptions` | No | `{}`; currently has no configurable fields. |
| `setter` | `(options: SchemaOptions) => OldSchema` | No | Returns the schema to save instead of discovering it through the engine. |

A setter receives the options object (default `{}`) and returns a `OldSchema` synchronously. Its result replaces the saved schema and clears the saved profile. AVA validates and copies the result; invalid results or thrown errors reject the call without changing previous metadata.

Requires a loaded source. Analysis and profiling obtain the schema when needed; direct `query()` does not. See [schema structure](/documentation/data/schema/#schema-structure).

## profile

```typescript
profile(options?: ProfileOptions, setter?: (options: ProfileOptions) => OldProfile): Promise<OldProfile>
```

Calculates and saves statistics for the loaded source through the engine. Each call without a setter computes a fresh profile and requires engine profiling support.

```typescript
const profile = await ava.profile({ metrics: ['row_count', 'mean'] });
```

To supply an existing profile, pass a function that returns it:

```typescript
await ava.profile(undefined, () => savedProfile);
```

| Parameter | Type | Required | Meaning / default |
| --- | --- | --- | --- |
| `options` | `ProfileOptions` | No | `{}`; uses the default metrics below. |
| `options.metrics` | `MetricConfig[]` | No | Metrics for engine computation. A supplied list replaces the defaults. |
| `setter` | `(options: ProfileOptions) => OldProfile` | No | Returns the profile to save instead of computing it through the engine. |

A setter receives the options object (default `{}`) and returns a `OldProfile` synchronously. It does not require engine profiling support. AVA validates and copies its result; invalid results or thrown errors reject the call without changing previous metadata. The options are passed to the setter; AVA does not calculate or filter metrics on its behalf.

Requires a loaded source. Both paths replace the saved profile, which analysis, translation, and suggestions can reuse. Setting a profile does not replace the saved schema. See [profile format](/documentation/data/schema/#profile-format).

### Metrics

The default metrics are `row_count`, `null_count`, `distinct_count`, `top_values`, `min`, `max`, and `mean`. Additional built-in metrics are `duplicate_count`, `min_length`, `max_length`, `sum`, `stddev`, and `median`.

Each entry is a metric name or an object with an `id` and metric-specific options:

```typescript
await ava.profile({
  metrics: ['row_count', { id: 'top_values', limit: 5 }],
});
```

| Field | Type | Default / behavior |
| --- | --- | --- |
| `id` | `string` | Required for object entries; the metric name. |
| `limit` | `number` | `top_values` only. Default `3`; a non-negative safe integer. |
| `maxDistinctRatio` | `number` | `top_values` only. Default `0.5`; a finite number from `0` to `1`. |

Other built-in metrics accept no additional options. Unknown metrics and unknown option names are rejected when the engine computes the profile. Availability depends on the engine and field type.

`metrics: []` produces empty metric objects. A new profile replaces previous statistics; metrics are not accumulated.

## analyze

`analyze(query: string, config?: AnalysisConfig): Promise<AnalysisResponse>`

| Parameter                    | Type                               | Required                  | Default / behavior                                                                                                              |
| ---------------------------- | ---------------------------------- | ------------------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| `query`                      | `string`                           | Yes                       | Natural-language question.                                                                                                      |
| `config`                     | `AnalysisConfig`                   | No                        | `{}`.                                                                                                                           |
| `config.includeSummary`      | `boolean`                          | No                        | `true`; `false` returns empty `text`.                                                                                           |
| `config.maxRows`             | `number`                           | No                        | `200`; see [execution limits](#executionoptions).                                                                               |
| `config.maxResultBytes`      | `number`                           | No                        | `1048576`; see [execution limits](#executionoptions).                                                                           |
| `config.strategy`            | `AnalysisStrategyConfig`           | No                        | Direct analysis.                                                                                                                |
| `config.strategy.type`       | `'direct'` / `'loop'` / `'subset'` | When strategy is provided | Selects the strategy.                                                                                                           |
| `config.strategy.maxRetries` | `number`                           | No; `direct` only         | `2` with explicit `type: 'direct'`; currently `10` when the strategy is omitted. Correction attempts after the first execution. |
| `config.strategy.maxSteps`   | `number`                           | No; `loop` only           | `12`; maximum reasoning steps.                                                                                                  |

`subset` has no additional options. These retry controls differ from `llm.maxRetries`. See [strategy behavior and requirements](/documentation/analysis/strategies/).

Requires a loaded source. Returns an [ExecutionResult](#executionresult) plus:

| Result field | Type     | Presence | Meaning                                                                   |
| ------------ | -------- | -------- | ------------------------------------------------------------------------- |
| `query`      | `string` | Always   | Original question.                                                        |
| `text`       | `string` | Always   | Summary, or empty when disabled.                                          |
| `markdown`   | `string` | Optional | Markdown content.                                                         |
| `sql`        | `string` | Optional | Executed query or DSL; the property name is retained for non-SQL engines. |

## translate

`translate(query: string): Promise<string>`

| Parameter | Type     | Required | Meaning                    |
| --------- | -------- | -------- | -------------------------- |
| `query`   | `string` | Yes      | Natural-language question. |

Requires a loaded source. Returns generated DSL without executing it; use `query()` to execute that string.

## query

`query(dsl: string, options?: ExecutionOptions): Promise<ExecutionResult>`

| Parameter                | Type               | Required | Default / behavior                                      |
| ------------------------ | ------------------ | -------- | ------------------------------------------------------- |
| `dsl`                    | `string`           | Yes      | Executable statement in the selected engine's language. |
| `options`                | `ExecutionOptions` | No       | Default execution limits below.                         |
| `options.maxRows`        | `number`           | No       | `200`.                                                  |
| `options.maxResultBytes` | `number`           | No       | `1048576` bytes.                                        |

Requires a loaded source. Does not generate or summarize a query with the model.

### ExecutionOptions

| Field            | Type     | Default           | Accepted values / behavior                                                                                       |
| ---------------- | -------- | ----------------- | ---------------------------------------------------------------------------------------------------------------- |
| `maxRows`        | `number` | `200`             | Rounded down and bounded to `1`–`1000000`; values outside the safe integer range after rounding use the default. |
| `maxResultBytes` | `number` | `1048576` (1 MiB) | Finite values are rounded down and clamped to at least `1`; non-finite values use the default.                   |

These limits bound returned data; they are separate from engine execution timeouts.

### ExecutionResult

| Field           | Type                             | Presence       | Meaning                                                 |
| --------------- | -------------------------------- | -------------- | ------------------------------------------------------- |
| `schema`        | `QueryColumn[]`                  | Always         | Returned column metadata.                               |
| `schema[].name` | `string`                         | Always         | Column name.                                            |
| `schema[].type` | `string`                         | Optional       | Native type name, if available.                         |
| `data`          | `T[]`                            | Always         | Returned rows.                                          |
| `truncated`     | `true`                           | When truncated | Result was bounded.                                     |
| `truncatedBy`   | `'maxRows'` / `'maxResultBytes'` | When truncated | Limit that stopped the result.                          |
| `rowCount`      | `number`                         | When known     | Row count when execution reaches the end of the result. |

## suggest

`suggest(count?: number): Promise<SuggestResult[]>`

| Parameter | Type     | Required | Default / behavior                  |
| --------- | -------- | -------- | ----------------------------------- |
| `count`   | `number` | No       | `3`; requested number of questions. |

Requires a loaded source. Returns suggestions sorted by descending score, each with `query: string`, `score: number` (0–1), and `reason: string`.

## visualize and recommend

`visualize(analysisResult): Promise<VisualizeResponse | null>`

`recommend(analysisResult): Promise<ChartSpec | null>`

Both methods accept the same input:

| Parameter              | Type                                        | Required | Meaning                                                          |
| ---------------------- | ------------------------------------------- | -------- | ---------------------------------------------------------------- |
| `analysisResult`       | `Pick<AnalysisResponse, 'query' \| 'data'>` | Yes      | An analysis result or an object containing the two fields below. |
| `analysisResult.query` | `string`                                    | Yes      | Question or visualization intent.                                |
| `analysisResult.data`  | `Record<string, unknown>[]`                 | Yes      | Rows to visualize.                                               |

Neither requires a loaded source. Both use the model and return `null` for empty data or when no chart is recommended. Generation errors propagate. `recommend()` returns a `ChartSpec`; `visualize()` additionally returns `html: string` containing a standalone chart page.

## viz

`viz(spec: ChartSpec): Promise<string>`

| Parameter        | Type        | Required | Meaning                                                                                             |
| ---------------- | ----------- | -------- | --------------------------------------------------------------------------------------------------- |
| `spec`           | `ChartSpec` | Yes      | Chart specification.                                                                                |
| `spec.chartType` | `ChartType` | Yes      | One of the chart types below. Part of the shared spec; the current renderer uses `config` directly. |
| `spec.config`    | `ChartConfig` | Yes    | GPT-Vis JSON config to embed in HTML; `config.type` matches `chartType`.                            |

`ChartType` values: `line`, `column`, `bar`, `pie`, `area`, `scatter`, `dual-axes`, `histogram`, `boxplot`, `radar`, `funnel`, `waterfall`, `liquid`, `word-cloud`, `violin`, `venn`, `treemap`, `sankey`, `table`, `summary`.

Returns a standalone HTML string. Does not require a loaded source or call a model. See [chart specifications](/documentation/visualization/overview/#recommend).

## dispose

`dispose(): Promise<void>` takes no parameters. Releases the current engine and clears the schema and profile. Await it in a `finally` block.

## Event methods

AVA inherits synchronous `on`, `once`, `off`, `emit`, and `getEvents` methods from the AntV event emitter. See [event method parameters](/documentation/reference/events/#listener-parameters).

## executionResult helper

`executionResult<T>(rows: T[], schema: QueryColumn[], options?: ExecutionOptions, upstreamTruncatedBy?: 'maxRows' | 'maxResultBytes'): ExecutionResult<T>`

A synchronous helper exported by both SDK entry points for custom engine implementations. Import it from `@antv/ava` or `@antv/ava/browser`.

| Parameter             | Type                              | Required | Meaning / default                                                                                    |
| --------------------- | --------------------------------- | -------- | ---------------------------------------------------------------------------------------------------- |
| `rows`                | `T[]`                             | Yes      | Rows produced by the engine.                                                                         |
| `schema`              | `QueryColumn[]`                   | Yes      | Output columns; each has `name: string` and optional `type: string`.                                 |
| `options`             | `ExecutionOptions`                | No       | `{}`; uses the [execution limits](#executionoptions) above.                                          |
| `upstreamTruncatedBy` | `'maxRows'` or `'maxResultBytes'` | No       | Preserve truncation already reported by an upstream executor unless a local limit truncates further. |

Returns bounded `data`, `schema`, and either `rowCount` for a complete result or truncation metadata for a partial result. Throws if an individual result field exceeds 1 MiB. The helper bounds already-produced rows; it does not limit query execution or input memory use.
