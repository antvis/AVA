<h2 id="supabase">连接 Supabase</h2>

```typescript
const ava = new AVA({
  llm: { model: 'YOUR_MODEL', apiKey: process.env.OPENAI_API_KEY },
  engine: { type: 'supabase' },
});
await ava.source({
  type: 'supabase',
  options: {
    projectRef: 'YOUR_PROJECT_REF',
    accessToken: process.env.SUPABASE_ACCESS_TOKEN!,
  },
});
```

使用 `engine: { type: 'supabase' }`，并在数据源中提供 Management API OAuth 流程取得的 `accessToken` 和目标 `projectRef`。这个令牌不是项目的匿名 Key。引擎发现远程结构，并在对应 PostgreSQL 中执行查询。

<h2 id="clickhouse">连接 ClickHouse</h2>

```typescript
const ava = new AVA({
  llm: { model: 'YOUR_MODEL', apiKey: process.env.OPENAI_API_KEY },
  engine: { type: 'clickhouse' },
});
await ava.source({
  type: 'clickhouse',
  options: {
    url: 'http://localhost:8123',
    database: 'analytics',
    username: 'reader',
    password: process.env.CLICKHOUSE_PASSWORD,
  },
});
```

使用 `engine: { type: 'clickhouse' }`，连接参数放在 `source()` 的 `options`。`url` 优先于 `host`，`username` 优先于 `user`；`port` 可以覆盖地址中的端口。

<h2 id="source-options">参数与执行位置</h2>

完整参数见[数据源指南](/documentation/data/sources/#clickhouse)。两种远程引擎都不接受额外的 `engine` 构造字段。SDK 不会因为你传入远程数据源而自动选择引擎，需要显式配置。

查询执行于远程数据库，按对应 SQL 方言生成和校验。返回数据限制与远程服务的处理能力是不同层面的约束；连接权限由所提供的凭证决定。
