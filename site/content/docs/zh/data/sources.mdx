<Heading as="h2" id="connect-a-source">接入数据源</Heading>

创建 AVA 实例，然后调用 `source(config)`，传入数据位置与读取设置：

```typescript
import { AVA } from '@antv/ava';

const ava = new AVA({
  llm: { model: 'YOUR_MODEL', apiKey: process.env.OPENAI_API_KEY },
});

await ava.source({
  type: 'json',
  options: {
    data: [
      { city: 'Hangzhou', revenue: 120 },
      { city: 'Shanghai', revenue: 200 },
      { city: 'Beijing', revenue: 160 },
    ],
  },
});

const schema = await ava.schema();
```

| 参数 | 类型 | 必填 | 含义 |
| --------- | ---------------------- | -------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| `type` | `SourceType` | 是 | 支持 `csv`、`csv-file`、`json`、`json-file`、`parquet`、`excel`、`text`、`sqlite`、`mysql`、`postgresql`、`mongodb`、`supabase`、`clickhouse`、`snowflake`、`feishu-bitable`、`tencent-smartsheet`、`github`。 |
| `options` | 数据源对应的对象 | 是 | 使用下方对应的数据源参数表，字段名均相对于 `options`。 |

`source()` 没有返回值，负责为执行准备数据。结构发现会推迟到 `schema()` 或其他操作需要时进行。再次调用 `source()` 会替换当前数据源并清空元数据缓存。使用 `schema()` 查看表名与字段名，结束后调用 `await ava.dispose()`。

示例均在 Node.js 中运行。Supabase、ClickHouse 和 Snowflake 的示例同时给出了必需的构造函数配置。前端应用请参考[浏览器用法](/documentation/browser/)。

<Heading as="h2" id="csv">CSV</Heading>

<Heading as="h3" id="inline-csv">直接传入 CSV</Heading>

设置 `type: 'csv'`，以字符串传入 CSV 内容。

```typescript
await ava.source({
  type: 'csv',
  options: { csv: 'city,revenue\nHangzhou,120\nShanghai,200\nBeijing,160' },
});
```

| 字段 | 类型 | 必填 | 含义与默认值 |
| --------- | ---------------- | -------- | ------------------------------------------ |
| `csv` | `string` | 是 | 原始 CSV 字符串。 |
| `options` | `CSVReadOptions` | 否 | [CSV 读取选项](#csv-reader-options)。 |

<Heading as="h3" id="csv-files">读取 CSV 文件</Heading>

设置 `type: 'csv-file'`，传入本地路径或 HTTP(S) URL。URL 需要鉴权时，可在 `options.headers` 中提供请求头。

远程 CSV、JSON、Parquet 和 Excel 文件只要传入非空 `headers`，就仅允许同来源跳转（协议、主机名和有效端口均相同），最多跳转 20 次。此规则同时适用于 DuckDB 和 Python，包括自定义 Python 执行器。跨来源跳转会在发送下一次请求前报错，即使请求头只有 `Accept`，或跳转是从 HTTP 升级到 HTTPS。未传请求头或传入 `headers: {}` 时，保留底层下载器原有的跳转行为。需要从其他来源下载受保护文件时，请直接使用已确认可信的最终地址。

```typescript
await ava.source({
  type: 'csv-file',
  options: {
    path: 'https://example.com/sales.csv',
    headers: { Authorization: 'Bearer YOUR_TOKEN' },
    options: { header: true, delim: ';' },
  },
});
```

| 字段 | 类型 | 必填 | 含义与默认值 |
| --------- | ------------------------ | -------- | ---------------------------------------------------- |
| `path` | `string` | 是 | 本地文件路径或 HTTP(S) URL。 |
| `headers` | `Record<string, string>` | 否 | 远程数据源的 HTTP 请求头，例如 Authorization。 |
| `options` | `CSVReadOptions` | 否 | [CSV 读取选项](#csv-reader-options)。 |

<Heading as="h3" id="csv-reader-options">CSV 读取选项</Heading>

DuckDB 引擎的 `csv`、`csv-file` 数据源可在 `options.options` 中使用以下字段，全部可选。AVA 将显式提供的值转发给 `read_csv`；省略时使用 DuckDB 的默认值或自动检测结果。下表说明各读取选项自身的默认值，实际表头、分隔符和类型也可能由自动检测确定。

| 字段 | 类型 | 必填 | 含义与默认值 |
| ---------------------- | ------------------------------------ | -------- | ----------------------------------------------------------------------------------------------- |
| `header` | `boolean` | 否 | 文件首行是否包含列名，默认 false。 |
| `names` | `string[]` | 否 | 列名列表。 |
| `columns` | `Record<string, string>` | 否 | 列名到类型的映射，例如 &#123; col1: 'INTEGER' &#125;；设置后关闭结构自动检测。 |
| `types` | `string[] \| Record<string, string>` | 否 | 按位置提供类型列表，或按列名提供类型映射。 |
| `all_varchar` | `boolean` | 否 | 跳过类型检测，将所有列读为 VARCHAR，默认 false。 |
| `normalize_names` | `boolean` | 否 | 移除列名中的非字母数字字符，并为保留字添加下划线前缀。 |
| `force_not_null` | `string[]` | 否 | 不参与 NULL 字符串匹配的列。 |
| `delim` | `string` | 否 | 字段分隔符，最多 4 字节，默认 `','`。 |
| `quote` | `string` | 否 | 引号字符，默认 `'"'`。 |
| `escape` | `string` | 否 | 引号包裹的字段内，用于转义引号的字符，默认 `'"'`。 |
| `comment` | `string` | 否 | 注释起始字符。 |
| `new_line` | `string` | 否 | 换行符：`'\r'`、`'\n'` 或 `'\r\n'`。 |
| `auto_detect` | `boolean` | 否 | 自动检测 CSV 参数，默认 true。 |
| `auto_type_candidates` | `string[]` | 否 | 检测列类型时考虑的候选类型，例如 `['BIGINT', 'DATE']`。 |
| `dateformat` | `string` | 否 | 解析日期使用的格式。 |
| `timestampformat` | `string` | 否 | 解析时间戳使用的格式。 |
| `decimal_separator` | `string` | 否 | 数字的小数分隔符，默认 `'.'`。 |
| `thousands` | `string` | 否 | 千位分隔符，须为单个字符，且与 decimal_separator 不同。 |
| `nullstr` | `string \| string[]` | 否 | 代表 NULL 的一个或多个字符串。 |
| `allow_quoted_nulls` | `boolean` | 否 | 允许将引号包裹的值转换成 NULL，默认 true。 |
| `sample_size` | `number` | 否 | 自动检测时采样的行数，默认 20480。 |
| `buffer_size` | `number` | 否 | 读取缓冲区大小，单位字节，默认 `16 * max_line_size`。 |
| `files_to_sniff` | `number` | 否 | 多文件结构检测时采样的文件数；-1 表示全部，默认 10。 |
| `max_line_size` | `number` | 否 | 单行大小上限，单位字节，默认 2000000。 |
| `parallel` | `boolean` | 否 | 使用并行 CSV 读取器，默认 true。 |
| `skip` | `number` | 否 | 跳过每个文件开头的行数，默认 0。 |
| `ignore_errors` | `boolean` | 否 | 忽略解析错误，默认 false。 |
| `null_padding` | `boolean` | 否 | 对较短的行在右侧补 NULL，默认 false。 |
| `strict_mode` | `boolean` | 否 | 遇到任何问题即抛错，默认 true。 |
| `store_rejects` | `boolean` | 否 | 跳过出错行并保存到拒绝记录表，默认 false。 |
| `rejects_table` | `string` | 否 | 保存出错行的临时表名，默认 `'reject_errors'`。 |
| `rejects_scan` | `string` | 否 | 保存出错扫描的临时表名，默认 `'reject_scans'`。 |
| `rejects_limit` | `number` | 否 | 每个文件记录的出错行数上限；0 表示不限制，默认 0。 |
| `encoding` | `string` | 否 | 文件编码，可选 `'utf-8'`、`'utf-16'`、`'latin-1'`，默认 `'utf-8'`。 |
| `compression` | `string` | 否 | 压缩方式，可选 `'none'`、`'gzip'`、`'zstd'`，默认根据扩展名检测。 |
| `union_by_name` | `boolean` | 否 | 多个文件按列名而非列位置对齐，默认 false。 |
| `hive_partitioning` | `boolean` | 否 | 将路径解释为 Hive 分区路径，默认自动检测。 |
| `filename` | `boolean` | 否 | 为每行添加保存来源文件路径的 `filename` 列，默认 false。 |

<Heading as="h3" id="json-reader-options">JSON 读取选项</Heading>

使用 DuckDB 时，两种 JSON 数据源均接受 `options.options`，所有字段可选。
`JSONReadOptions` 暴露完整的 [DuckDB JSON 读取参数](https://duckdb.org/docs/current/data/json/loading_json)：

| 参数 | 类型 | 默认值 | 含义 |
| --- | --- | --- | --- |
| `auto_detect` | `boolean` | `true` | 推断数据结构。 |
| `columns` | `Record<string, string>` | 未设置 | 列名到 DuckDB 类型的映射，同时用于选择列。 |
| `compression` | `'auto_detect' \| 'none' \| 'gzip' \| 'zstd'` | `'auto_detect'` | 压缩编解码方式。 |
| `dateformat` | `string` | `'iso'` | 日期格式。 |
| `field_appearance_threshold` | `number` | `0.1` | 稀疏对象推断为 MAP 的阈值。 |
| `filename` | `boolean` | `false` | 在 `SELECT *` 中包含文件名。 |
| `format` | `'auto' \| 'unstructured' \| 'newline_delimited' \| 'array'` | `'auto'` | `read_json` 的输入组织形式。 |
| `hive_partitioning` | `boolean` | 自动检测 | 根据路径识别分区。 |
| `ignore_errors` | `boolean` | `false` | 跳过错误，仅适用于 NDJSON。 |
| `map_inference_threshold` | `number` | `200` | STRUCT 子字段数量阈值；-1 关闭 MAP 推断。 |
| `maximum_depth` | `number` | `-1` | 结构推断深度；-1 表示不限。 |
| `maximum_object_size` | `number` | `16777216` | 单个对象的字节上限。 |
| `maximum_sample_files` | `number` | `32` | 采样文件数量。 |
| `records` | `'auto' \| 'true' \| 'false'` | `'auto'` | 是否展开对象。 |
| `sample_size` | `number` | `20480` | 采样对象数量；-1 扫描全部。 |
| `timestampformat` | `string` | `'iso'` | 时间戳格式。 |
| `union_by_name` | `boolean` | `false` | 合并数据结构。 |

内存数据会序列化为未压缩的 JSON 数组，请选择与此兼容的读取选项。
远程文件会下载到临时路径，读取压缩 URL 时应显式设置 `compression`。

<Heading as="h2" id="excel">Excel</Heading>

从本地路径或 HTTP(S) URL 读取 `.xlsx` 工作簿。每个被选中的工作表会成为一张独立的表，以工作表名称命名。调用 `schema()` 可查看生成的表与列。

```typescript
await ava.source({
  type: 'excel',
  options: {
    path: './sales.xlsx',
    sheets: [
      { sheet: 'Sales', range: 'A3:F100', header: true },
      { sheet: 'Costs', range: 'B2:C50', header: false },
    ],
  },
});
```

<Heading as="h3" id="source-options">数据源选项</Heading>

| 字段 | 类型 | 必填 | 含义与默认值 |
| --- | --- | --- | --- |
| `path` | `string` | 是 | 本地文件路径或 HTTP(S) URL。 |
| `headers` | `Record<string, string>` | 否 | 远程数据源的 HTTP 请求头，例如 Authorization。 |
| `sheets` | `ExcelSheetOptions[]` | 否 | 要加载的工作表及各自的读取设置；省略时加载全部工作表，并使用 `header: true`。 |

<Heading as="h3" id="sheet-selection-and-reader-options">工作表选择与读取选项</Heading>

`sheets` 中的每一项都包含必填的 `sheet`，以及可选的 `ExcelReadOptions` 字段。读取选项直接放在工作表项上，写法如上例所示。

| 字段 | 类型 | 默认值 | 含义 |
| --- | --- | --- | --- |
| `sheet` | `string` | 必填 | 精确的工作表名称，同时作为表名。 |
| `range` | `string` | 由引擎推断 | 包含首尾边界的 A1 矩形范围，例如 `B3:F100`。 |
| `header` | `boolean` | `true` | 将所选范围的第一行作为列名；设为 false 时保留为数据。 |
| `all_varchar` | `boolean` | `false` | 仅 DuckDB：将所有单元格读为 VARCHAR。 |
| `ignore_errors` | `boolean` | `false` | 仅 DuckDB：类型转换失败的单元格改为 NULL。 |
| `stop_at_empty` | `boolean` | 有 `range` 时为 `false`，否则为 `true` | 仅 DuckDB：遇到第一个空行时停止读取。 |
| `empty_as_varchar` | `boolean` | `false` | 仅 DuckDB：将空单元格推断为 VARCHAR，而非 DOUBLE。 |

提供 `sheets` 时，列表不能为空；每个工作表名必须存在且只能出现一次。范围必须是有效、有界的 A1 矩形。无效选择及不受支持的字段会被拒绝。

<Heading as="h3" id="engine-behavior">引擎行为</Heading>

两种引擎都支持 `sheet`、`range` 和 `header`。Python 引擎会拒绝上表中的四个 DuckDB 专用选项。

DuckDB 的读取选项遵循 [`read_xlsx`](https://duckdb.org/docs/current/core_extensions/excel#reading-xlsx-files)，但 AVA 默认 `header` 为 true，而非自动推断。例如，要将混合类型单元格保留为文本，并继续读取空行之后的数据：

```typescript
await ava.source({
  type: 'excel',
  options: {
    path: './sales.xlsx',
    sheets: [{ sheet: 'Sales', all_varchar: true, stop_at_empty: false }],
  },
});
```

DuckDB 会拒绝含有字面 XML 实体文本工作表名的工作簿，例如 `Sales &amp; Tax`，因为 Excel 扩展可能将它与另一张表混淆。请重命名这些工作表，或使用 Python 引擎。普通的 &、引号和 Unicode 名称均受支持。

<Heading as="h2" id="postgresql">PostgreSQL</Heading>

连接数据库并发现其中的表。

```typescript
await ava.source({
  type: 'postgresql',
  options: {
    host: 'localhost',
    database: 'analytics',
    user: 'reader',
    password: process.env.POSTGRES_PASSWORD,

```

| 字段 | 类型 | 必填 | 含义与默认值 |
| ---------- | ------------ | -------- | ------------------------------------------------ |

| `port` | `number` | 否 | 默认 `5432`。 |
| `database` | `string` | 是 | 要暴露的数据库。 |
| `user` | `string` | 否 | 数据库用户，不提供则省略。 |
| `password` | `string` | 否 | 数据库密码，不提供则省略。 |
| `schema` | `string` | 否 | 表所属的数据库 schema，默认 `public`。 |
| `ssh` | `SSHOptions` | 否 | 可选的 [SSH 隧道](#ssh-options)。 |

<Heading as="h2" id="ssh-options">SSH 选项</Heading>

通过跳板机访问 MySQL 或 PostgreSQL 时，在 `options` 中添加 `ssh`。数据库的 `host` 和 `port` 应填写跳板机能够访问的地址与端口。

先通过可信渠道向 SSH 服务器管理员获取主机密钥指纹。管理员可在服务器上运行 `ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub -E sha256`，将输出中的 `SHA256:...` 值填入连接配置：

```typescript
await ava.source({
  type: 'mysql', // PostgreSQL 使用 'postgresql'
  options: {
    host: 'db.internal',
    database: 'analytics',
    user: 'reader',
    password: process.env.DB_PASSWORD,
    ssh: {
      host: 'bastion.example.com',
      user: 'ssh-user',
      password: process.env.SSH_PASSWORD,
      hostKeyFingerprint: 'SHA256:REPLACE_WITH_SERVER_FINGERPRINT',
    },
  },
});
```

`options.ssh` 中的字段：

| 字段 | 类型 | 必填 | 含义与默认值 |
| --- | --- | --- | --- |
| `host` | `string` | 是 | SSH 服务器主机名。 |
| `port` | `number` | 否 | 默认 `22`。 |
| `user` | `string` | 是 | SSH 登录用户。 |
| `password` | `string` | 否 | SSH 登录密码。 |
| `hostKeyFingerprint` | `string` | 是 | 预期的主机密钥指纹，格式为 `SHA256:<base64>`，不带填充字符。 |

<Heading as="h2" id="feishu-bitable">飞书多维表格</Heading>

await ava.source({

<Heading as="h2" id="snowflake">Snowflake</Heading>

在 Node.js 中使用 `snowflake` 数据源和引擎，分析 Snowflake 仓库中的表和视图。每个数据源对应一个 schema，查询结果返回 AVA。

<Heading as="h3" id="snowflake-permissions">权限</Heading>

准备好仓库、数据库和 schema。连接角色需要三者的 `USAGE` 权限，以及待分析表和视图的 `SELECT` 权限。`SNOWFLAKE_SAMPLE_DATA` 这类共享数据库需要授予 `IMPORTED PRIVILEGES`。请勿向该角色授予存储过程、外部函数或集成的使用权限。

以下示例创建使用[密钥对认证](https://docs.snowflake.com/en/developer-guide/node-js/nodejs-driver-authenticate)的只读服务用户。将 `<public-key-body>` 替换为公钥正文，下方连接配置使用对应的私钥文件。

```sql
CREATE ROLE AVA_READER;
GRANT USAGE ON WAREHOUSE AVA_WH TO ROLE AVA_READER;
GRANT USAGE ON DATABASE ANALYTICS TO ROLE AVA_READER;
GRANT USAGE ON SCHEMA ANALYTICS.SALES TO ROLE AVA_READER;
GRANT SELECT ON ALL TABLES IN SCHEMA ANALYTICS.SALES TO ROLE AVA_READER;
GRANT SELECT ON ALL VIEWS IN SCHEMA ANALYTICS.SALES TO ROLE AVA_READER;
CREATE USER AVA_READER_SVC TYPE = SERVICE DEFAULT_ROLE = AVA_READER DEFAULT_WAREHOUSE = AVA_WH
  RSA_PUBLIC_KEY = '<public-key-body>';
GRANT ROLE AVA_READER TO USER AVA_READER_SVC;
```

查询会消耗仓库 credits，请开启自动挂起并配置资源监控来控制用量。

<Heading as="h3" id="snowflake-connection-fields">连接字段</Heading>

将引擎和数据源类型均设为 `snowflake`，填入账号、凭证和仓库信息：

```typescript
const ava = new AVA({
  llm: { model: 'YOUR_MODEL', apiKey: process.env.OPENAI_API_KEY },
  engine: { type: 'snowflake' },
});
await ava.source({
  type: 'snowflake',
  options: {
    account: 'myorg-myaccount',
    username: 'AVA_READER_SVC',
    authenticator: 'SNOWFLAKE_JWT',
    privateKeyPath: '/secure/ava_reader_key.p8',
    warehouse: 'AVA_WH',
    role: 'AVA_READER',
    database: 'ANALYTICS',
    schema: 'SALES',
  },
});
```

| 字段 | 类型 | 必填 | 含义与默认值 |
| --------------- | -------- | -------------------- | ------------------------------------------------------------------------------------ |
| `account` | `string` | 是 | 账号标识，格式为 `orgname-accountname`。 |
| `database` | `string` | 是 | 要发现和查询的数据库。 |
| `schema` | `string` | 否 | 暴露其中表和视图的 schema，也是会话的默认 schema。默认 `PUBLIC`。 |
| `warehouse` | `string` | 否 | 执行查询的仓库，默认使用用户的 `DEFAULT_WAREHOUSE`。 |
| `role` | `string` | 否 | 会话使用的角色，默认使用用户的 `DEFAULT_ROLE`。请使用只读角色。 |
| `username` | `string` | 多数认证方式必填 | 登录名。 |
| `authenticator` | `string` | 否 | 驱动的认证方式，如 `SNOWFLAKE_JWT`、`PROGRAMMATIC_ACCESS_TOKEN` 或 `OAUTH`。默认 `SNOWFLAKE`（密码）。 |
| `privateKey` | `string` | `SNOWFLAKE_JWT` 时必填 | PEM 格式私钥；也可用 `privateKeyPath` 从文件读取，加密的私钥用 `privateKeyPass` 提供口令。 |
| `token` | `string` | 令牌类认证时必填 | Programmatic access token 或 OAuth 访问令牌；也可用 `tokenFilePath` 从文件读取。 |
| `password` | `string` | `SNOWFLAKE` 时必填 | 密码。Snowflake 正在逐步停用单因素密码登录，建议使用密钥对或令牌。 |
| `queryTimeoutMs` | `number` | 否 | 单条语句的时限（毫秒）。由 Snowflake 执行（语句超时和排队超时），到期时客户端也会取消语句。默认 `30000`。 |

其他[驱动连接选项](https://docs.snowflake.com/en/developer-guide/node-js/nodejs-driver-options)，如 `host`、代理设置和 `queryTag`（默认 `AVA`），会透传给驱动。结果格式和会话清理由 AVA 管理。数据库、schema 或仓库不存在或未授权时，加载会报错。

<Heading as="h3" id="snowflake-query-execution">查询执行</Heading>

用 `schema()` 查看已授权的表、视图和声明的键，用 `query()` 执行 Snowflake SQL，或用 `analyze()` 以自然语言提问。`analyze()` 会将问题和数据集元数据发送给配置的模型来生成 SQL；默认还会将查询结果发送给模型生成摘要，传入 `{ includeSummary: false }` 可跳过摘要。

```typescript
try {
  const result = await ava.analyze('每个月的订单总金额是多少？');
  console.log(result.data, result.text);
} finally {
  await ava.dispose();
}
```

- 使用单条只读 `SELECT`（支持 `WITH`），按 `schema()` 列出的名称为表和列加双引号。存储过程、`SYSTEM$` 函数，以及 `IDENTIFIER(name)(...)` 形式的动态函数调用会被拒绝。
- `maxRows` 和 `maxResultBytes` 分别限制返回结果的行数和大小。
- `NUMBER` 在转换不损失数字位数时转为 JavaScript 数字，更大或更精确的值保留为十进制字符串；浮点数的 `NaN` 和无穷大保留为字符串。日期使用 `YYYY-MM-DD`，时间和时间戳带九位小数，时区类型附带偏移量。`VARIANT`、`OBJECT` 和 `ARRAY` 是解析后的 JSON，`BINARY` 是十六进制文本。

## 腾讯文档智能表格

通过腾讯文档原生 OpenAPI 将显式授权的单个智能子表加载到 DuckDB，不依赖 MCP SDK。支持 Node.js SDK 和 CLI，使用 DuckDB 引擎。

```typescript
await ava.source({
  type: 'tencent-smartsheet',
  options: {
    fileId: '<原生 OpenAPI fileID>',
    sheetId: '<子表 sheetID>',
    clientId: '<client-id>',
    openId: '<open-id>',
    accessToken: '<access-token>',
  },
});
```

按官方 [OAuth 流程](https://docs.qq.com/open/document/app/oauth2/)取得应用授权，并通过 options 显式传入 clientId、openId、accessToken。调用方可自行读取环境变量，loader 不读取环境变量；CLI 使用本地未跟踪的配置文件，不自动展开环境变量。旧 MCP token 不再接受；不提供 OAuth 回调、自动续期或写入。

fileId 使用原生 ID，分享链接 encoded ID 需通过官方 [ID 转换](https://docs.qq.com/open/document/app/openapi/v2/file/util/converter.html)取得；sheetId 可通过官方[子表接口](https://docs.qq.com/open/document/app/openapi/v2/smartsheet/sheet/get_sheet.html)取得。连接器不搜索私人文件或自动选择子表。

| 参数 | 类型 | 必填与默认 |
| --- | --- | --- |
| `fileId` | `string` | 必填，原生 OpenAPI ID。 |
| `sheetId` | `string` | 必填，显式子表 ID。 |
| `clientId` | `string` | 必填，通过 options 显式传入。 |
| `openId` | `string` | 必填，通过 options 显式传入。 |
| `accessToken` | `string` | 必填，通过 options 显式传入。 |
| `pageSize` | `number` | 1–100，默认 100，作用于字段/记录分页。 |
| `maxRecords` | `number` | 1–100,000，默认 10,000，超限失败。 |
| `timeoutMs` | `number` | 1–110,000 毫秒，默认 60,000，覆盖整次加载。 |
| `maxRetries` | `number` | 0–5，默认 2，仅瞬态 HTTP/网络错误。 |

支持原生类型 1 文本、2 数字、3 复选框、4 日期、12/13 创建/修改时间、14 进度、15 电话、16 邮箱、17 单选、26 货币、28 百分比。数字保留有限原始 DOUBLE，不按显示格式强转或缩放；布尔保留 false，电话/邮箱保留字符串和前导零。日期为毫秒字符串，规范化 UTC；系统时间仅在对应 12/13 单元格省略时映射记录 createTime/updateTime，不覆盖显式 null。旧公开枚举页未列全，26/28 已由当前官方元数据与真实 OpenAPI 响应交叉验证。复杂字段不暴露，_record_id 保留源记录身份；空表、空行和全空列保持语义。

字段上限 1,000，响应/分页读取 16 MiB；展开后另限 16 MiB UTF-8 JSON、1,000,000 单元格（含 null、列名和记录 ID），宽表有效行数进一步受限。完整分页、唯一 ID、递进偏移、总量和元数据变化检查失败时不返回部分结果。通过参数化 JSON 和显式 schema 直接创建内存表，不写临时文件，不放开临时目录。

分别检查 HTTP 与业务 ret，保留状态、业务 ret/msg、请求 ID，以及网络异常的名称、消息、错误码和一层原因；不复制任意对象、堆栈或请求头。仅对选定字符串精确替换凭证，超过 8 KiB 的字段整体省略；非 JSON 或不完整的 HTTP 错误正文不输出，仍保留状态和请求 ID。只重试网络错误及 HTTP 429/500/502/503/504，遵循有效且不超过 30 秒的 Retry-After；认证和业务错误不自动重试。端点固定，拒绝重定向。

加载时停止编辑源表，这不是远端事务快照或持续同步。两个业务示例、配置迁移和验证结果见[接入说明](https://github.com/antvis/AVA/tree/oss-camp2026/examples/tencent-docs)。

<Heading as="h2" id="github">GitHub</Heading>

用于分析仓库的 Issue 积压和 PR 合并耗时。AVA 通过 [GitHub REST API](https://docs.github.com/rest/issues/issues#list-repository-issues) 只读读取一个仓库的 issue 和 PR，载入 DuckDB 的两张表 `issues`、`pull_requests`。仅支持 Node.js SDK 和 CLI，以及 DuckDB 引擎。

```typescript
await ava.source({
  type: 'github',
  options: { repository: 'antvis/AVA', token: process.env.GITHUB_TOKEN },
});

const backlog = await ava.analyze('未关闭的 issue 中有多少个没有负责人，多少个是 90 天前创建的？');
```

| 字段 | 类型 | 必填 / 默认值 |
| --- | --- | --- |
| `repository` | `string` | 必填；`owner/name` 或 github.com 仓库链接。 |
| `token` | `string` | 公开仓库可不填，此时按 IP 共享每小时 60 次请求；有 token 时每小时 5,000 次，并可读取 token 有权访问的私有仓库。 |
| `since` | `string` | 可选，ISO 8601 日期或时间，不带时区时按 UTC。所有未关闭的 issue 和 PR 照常全部读取，保证积压完整；已关闭的只读取此后有更新的。 |
| `maxRecords` | `number` | 1–100,000，默认 10,000 个 issue 和 PR；超出直接失败，不截断。 |
| `timeoutMs` | `number` | 1–110,000，默认 60,000 毫秒，覆盖整次加载，包括重试和限流等待。 |

| 表 | 列 |
| --- | --- |
| `issues` | `number`（主键）、`title`、`state`、`state_reason`、`author`、`author_association`、`author_is_bot`、`assignees`、`labels`、`comments`、`created_at`、`updated_at`、`closed_at`、`html_url` |
| `pull_requests` | 同上，但没有 `state_reason`，另有 `is_draft`、`is_merged`、`merged_at` |

与 GitHub 一致，已合并的 PR `state` 为 `closed`，用 `is_merged` 区分合并与关闭未合并。`state`、`state_reason`、`author_association` 是 GitHub 文档取值加上实际返回取值构成的 `ENUM`，schema 中直接列出可用取值。时间统一为 UTC 的 `TIMESTAMP`，与 GitHub 搜索限定词（如 `created:2026-10-01..2026-10-31`）时区一致。`assignees`、`labels` 为 `VARCHAR[]`，可用 `list_contains(labels, 'bug')`、`len(assignees) = 0` 或 `unnest(labels)`。`comments` 为对话评论数。不读取正文、review、commit 和仓库的其他对象。

私有仓库请为该仓库创建只读 **Issues**、**Pull requests** 权限的 [fine-grained token](https://github.com/settings/personal-access-tokens/new)；classic token 读公开仓库无需 scope，读私有仓库需要 `repo`。组织启用 SAML 单点登录时还需为该组织授权 token。loader 不读取环境变量；CLI 依次读取 `GH_TOKEN`、`GITHUB_TOKEN`。

每次请求最多 100 条，只沿 `api.github.com` 上的 `Link` 分页。GitHub 返回限流时，按重置时间、`retry-after` 或次级限流的 1 分钟等待；等待会超过 `timeoutMs` 时立即失败并给出重置时间。网络错误、响应中途断开和 5xx 重试三次；401、403（含 SAML 单点登录）、404 等错误保留 GitHub 的原始信息，不重试。数据异常的条目会使加载失败。行数据以 JSON 参数绑定写入，不写临时文件。

CLI 自动识别仓库链接（包括其 `/issues`、`/pulls` 页面），`owner/name` 需配合 `--type github`。`since` 和各项上限通过 `@file` 配置传入；CLI 会话须在两分钟内加载完成。

```sh
ava source https://github.com/antvis/AVA
ava analyze <datasetId> "2026 年 10 月合并的 PR 从创建到合并的中位时长是多少小时？"
```

两个业务问题及其与 GitHub 搜索结果的核对见 [GitHub 示例](https://github.com/antvis/AVA/tree/oss-camp2026/examples/github)。
