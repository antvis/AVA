<Heading as="h2" id="public-entry-points">公开入口</Heading>

[`index.ts`](https://github.com/antvis/AVA/blob/ai/src/index.ts) 注册全部 Node.js 引擎，导出 `AVA` 和公开类型；[`index.browser.ts`](https://github.com/antvis/AVA/blob/ai/src/index.browser.ts) 只注册 JavaScript。[`ava.ts`](https://github.com/antvis/AVA/blob/ai/src/ava.ts) 协调数据源状态、数据模型、事件与引擎生命周期。

契约按公开 API 组织。`source/` 按数据源类型分文件维护 schema、选项与类型，包括 CSV/JSON/Excel 读取选项；`source/index.ts` 组装数据源联合契约，`source/shared.ts` 维护共用的文件与连接字段。`schema.ts`、`profile.ts`、`semantic.ts`、`query.ts`、`analyze.ts`、`suggest.ts` 分别维护对应 API 的公开输入与输出。`visualize.ts` 维护 `recommend()`、`viz()`、`visualize()` 共用的图表结构及显式绑定配置。跨 API 的 JSON 值与数据模型基础定义放在 `shared/`。

策略、方言与各引擎的运行接口继续跟随实现。数据模型组装器维护从公共元数据字段派生的严格输入校验。`contracts/` 外的模块统一通过 `contracts/index.ts` 导入共享契约；契约定义之间直接引用，避免循环依赖。公开入口保留既有导出；CLI 消息协议、AI 阶段输出与引擎专用限制仍由各自模块维护。

<Heading as="h2" id="method-to-module">方法与模块的对应关系</Heading>

| 公开方法 | 职责与实现 |
| ------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `source()` / `schema()` / `dispose()` | [`ava.ts`](https://github.com/antvis/AVA/blob/ai/src/ava.ts) 中的数据源状态与引擎生命周期 |
| `profile()` | 各引擎实现统计计算，共享指标约定位于 [`util/profile.ts`](https://github.com/antvis/AVA/blob/ai/src/util/profile.ts) |
| `analyze()` | 分发到 [`analysis/direct.ts`](https://github.com/antvis/AVA/blob/ai/src/analysis/direct.ts) 或 [`analysis/loop.ts`](https://github.com/antvis/AVA/blob/ai/src/analysis/loop.ts) |
| `translate()` / `query()` | 引擎的 `getDSL()` / `execute()` |
| `suggest()` | [`suggest/index.ts`](https://github.com/antvis/AVA/blob/ai/src/suggest/index.ts) |
| `recommend()` | [`visualization/advisor.ts`](https://github.com/antvis/AVA/blob/ai/src/visualization/advisor.ts) 与配置生成 |
| `viz()` | [`visualization/generator.ts`](https://github.com/antvis/AVA/blob/ai/src/visualization/generator.ts) 中的 HTML 包装 |
| `visualize()` | 组合 `recommend()` 和 `viz()` |

<Heading as="h2" id="context-and-state">上下文与状态</Heading>

每个 AVA 实例持有一个活动引擎及其 schema、profile 缓存。`source()` 加载数据，`schema()` 在首次使用时发现结构；`profile()` 重新计算并保存统计信息；需要时再由缓存元数据组装数据模型。重新加载或释放实例会清空两类缓存。

引擎持有数据与连接。`load()` 不返回元数据，`schema()` 发现结构，`profile(schema, options?)` 计算统计信息，`getDSL(query, dataModel)` 使用 AVA 组装的数据模型。共享数据校验位于 `contracts/`；目录组装与指标执行工具保留在 `util/`。

分析策略共享一个运行时，其中包括引擎、模型配置、数据模型与事件发射器。查询结果限制通过共享工具统一规范化。

<Heading as="h2" id="documentation-organization">文档组织方式</Heading>

每个主题都是 `site/content/docs/` 下的独立 MDX 文件，按 `data/`、`analysis/`、`visualization/`、`engines/`、`reference/` 分组。这样的组织对应公开能力，无需将每个内部辅助函数都拆成独立的用户文档。
