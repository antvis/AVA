<Heading as="h2" id="initialization">初始化</Heading>

<Heading as="h3" id="constructor">构造函数</Heading>

`new AVA(config: AVAConfig)`

| 参数 | 类型 | 必填 | 默认值与行为 |
| --------------- | -------------- | -------- | ------------------------------------------------------------- |
| `config` | `AVAConfig` | 是 | 配置对象。 |
| `config.llm` | `LLMConfig` | 是 | 见[下方模型字段](#model-options)。 |
| `config.engine` | `EngineConfig` | 否 | `{ type: 'duckdb' }`，见[下方引擎字段](#engine-options)。 |

构造函数不加载数据，引擎会在 `source()` 时创建。

<h4 id="model-options">模型选项</h4>

以下字段位于 `config.llm` 中。

| 字段 | 类型 | 必填 | 含义与默认值 |
| -------------- | ------------------------------------- | -------- | --------------------------------------------------------------------------------- |
| `provider` | `'openai' \| 'gateway'` | 否 | 默认使用兼容 OpenAI 的 Chat Completions；Gateway 可读取 AI_GATEWAY_API_KEY。 |
| `model` | `string \| LanguageModel` | 是 | 模型名称，或预先配置好的 AI SDK 模型实例。 |
| `apiKey` | `string` | 否 | 模型服务商的 API 密钥。 |
| `baseURL` | `string` | 否 | 可选的 API 基础地址。 |
| `maxRetries` | `number` | 否 | 模型 API 可重试错误的最大重试次数，默认 3。 |

以字符串传入模型名称时，默认使用兼容 OpenAI 的 **Chat Completions** ；传入模型对象时则直接使用该对象。用量回调并不完整覆盖每次模型请求，不能用来汇总全部用量。

<h4 id="engine-options">引擎选项</h4>

提供 `engine` 时，`config.engine.type` 必填。支持 `duckdb`、`python`、`javascript`、`supabase`、`clickhouse`、`snowflake`，以及通过 `registerEngine()` 注册的名称。省略 `engine` 时选择 DuckDB。JavaScript、Supabase、ClickHouse、Snowflake 没有其他引擎字段，连接凭证放在 `source()` 中。

<h5 id="duckdb">DuckDB</h5>

将 `engine.type` 设为 `duckdb`。`engine` 接受的全部额外字段如下。

| 字段 | 类型 | 必填 | 含义与默认值 |
| -------------------------- | --------- | -------- | ------------------------------------------------------------------------------- |
| `memoryLimit` | `string` | 否 | 内存限制，例如 `'512MB'`，默认 `'512MB'`。 |
| `threads` | `number` | 否 | 工作线程数，默认 1。 |
| `maxTempDirectorySize` | `string` | 否 | 临时溢写目录的大小上限，例如 `'1GB'`；不设置则不限制。 |
| `queryTimeoutMs` | `number` | 否 | 单次查询超时，单位毫秒，默认 30000。 |
| `allowCommunityExtensions` | `boolean` | 否 | 数据源加载明确需要社区扩展时，允许启用 DuckDB 社区扩展。 |

<h5 id="python">Python</h5>

将 `engine.type` 设为 `python`。`engine` 接受的全部额外字段如下。

| 字段 | 类型 | 必填 | 含义与默认值 |
| ---------------- | -------------------------------------------- | -------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `execute` | `(code: string) => Promise<ExecutionResult>` | 否 | 用自定义环境替换本地 python3 执行。本地执行没有沙箱；请运行完整 Python 脚本，将其 JSON 输出作为 ExecutionResult 返回。每次查询先发送只编译的校验脚本，再发送包含数据加载和结果限制的执行脚本；远程执行时限需另行配置。 |
| `queryTimeoutMs` | `number` | 否 | 每次校验或执行调用的等待上限及本地进程时限，默认 30000 毫秒。 |

<h5 id="registered-engines">已注册的引擎</h5>

将 `engine.type` 设为传给 `registerEngine()` 的名称。其余字段以 `options` 传给引擎构造函数。这是 SDK 能力，CLI 仅支持内置引擎名。

| 字段 | 类型 | 必填 | 含义与默认值 |
| ------------ | --------------- | ----------------- | ------------------------------------------ |
| `type` | `string` | 是 | 已注册的引擎名称，例如 `'sales'`。 |
| 其他字段 | Engine-specific | 取决于引擎 | 由注册的引擎负责验证。 |

<Heading as="h2" id="data">数据</Heading>

<Heading as="h3" id="source">source</Heading>

```typescript
source(configs: DataSourceConfig | DataSourceConfig[]): Promise<void>
```

通过配置的引擎加载数据源。AVA 在需要时读取数据结构。

```typescript
await ava.source({ type: 'json', options: { data: [{ revenue: 120 }] } });
```

| 参数 | 类型 | 必填 | 含义 |
| --- | --- | --- | --- |
| `configs` | `DataSourceConfig \| DataSourceConfig[]` | 是 | 一份[数据源配置](/documentation/data/sources/#connect-a-source)，或非空的配置数组。 |

Node.js SDK 的 DuckDB 引擎支持一次加载多个数据源。批量配置和命名规则见[接入多个数据源](/documentation/data/sources/#connect-multiple-sources)。

每次调用都会先释放当前引擎，清除保存的 schema、profile 和业务语义，再加载数据。加载失败后，实例没有活动数据集。调用 `source()` 前，请等待正在进行的操作完成。

<Heading as="h3" id="schema">schema</Heading>

```typescript
schema(options?: SchemaOptions, setter?: (options: SchemaOptions) => Schema): Promise<Schema>
```

返回已加载数据源的结构。不提供 setter 时，AVA 优先返回已保存的 schema；没有缓存则通过引擎发现并保存。

```typescript
const schema = await ava.schema();
```

如需提供已有 schema，传入返回该对象的函数：

```typescript
await ava.schema(undefined, () => savedSchema);
```

| 参数 | 类型 | 必填 | 含义与默认值 |
| --- | --- | --- | --- |
| `options` | `SchemaOptions` | 否 | `{}`，目前没有可配置字段。 |
| `setter` | `(options: SchemaOptions) => Schema` | 否 | 返回要保存的 schema，替代引擎发现过程。 |

Setter 接收选项对象（默认 `{}`），同步返回 `Schema`。结果会替换已保存的 schema，并清空 profile。AVA 会验证并复制结果；结果无效或 setter 抛错时，调用失败，原有元数据保持不变。

需要先加载数据源。分析和统计会按需获取 schema，直接 `query()` 不要求提前发现结构。使用流程见[了解数据结构](/documentation/data/schema/)。

<h4 id="schema-structure">Schema 结构</h4>

| 字段 | 含义 |
| --- | --- |
| `models` | 可用于查询的表或视图，必填。 |
| `models[].name` | 模型名称。 |
| `models[].tableReference` | 物理数据源标识，包含 `table`，以及可选的 `catalog`、`schema`。 |
| `models[].columns` | 列定义，每列包含 `name`、`type` 和可选的 `notNull`。 |
| `models[].primaryKey` | 单列名称，或代表复合主键的有序非空数组。 |
| `models[].uniqueKeys` | 候选唯一键数组，每项为单列名称或复合键数组。 |
| `relationships` | 可发现时返回的外键关系。 |
| `views` | 可发现时返回的命名视图查询，包含 `name` 和 `statement`。 |

具体内容取决于数据源和引擎。查询结果中的 `schema` 描述输出列，并不是数据源的 `Schema`。

<Heading as="h3" id="profile">profile</Heading>

```typescript
profile(options?: ProfileOptions, setter?: (options: ProfileOptions) => Profile): Promise<Profile>
```

通过引擎计算并保存已加载数据源的统计信息。不传 setter 时，每次调用都会重新计算，需要引擎支持统计。

```typescript
const profile = await ava.profile({ metrics: ['row_count', 'mean'] });
```

如需提供已有 profile，传入返回该对象的函数：

```typescript
await ava.profile(undefined, () => savedProfile);
```

| 参数 | 类型 | 必填 | 含义与默认值 |
| --- | --- | --- | --- |
| `options` | `ProfileOptions` | 否 | `{}`，使用下方默认指标。 |
| `options.metrics` | `MetricConfig[]` | 否 | 交给引擎计算的指标列表；提供后替换默认列表。 |
| `options.typeSchema` | `Record<string, Record<string, ProfileType>>` | 否 | 按模型名和列名覆写 DuckDB 画像类型。例如 `{ data: { order_date: 'DateTime' } }` 将文本按日期解析并计算日期指标。 |
| `options.inferTypes` | 对象 | 否 | `{}` 启用基于存储值的 DuckDB 类型推断。数值列的不同值数不超过 `numericCategoryThreshold` 时视为类别。文本列由 `textCategoryThreshold` 和 `textCategoryRatio` 判断是否为类别。默认阈值分别为 `5`、`50` 和 `0.5`。 |
| `options.inferTypes.booleanMappings` | `Record<string, boolean>` | 否 | 小写文本到布尔值的映射。默认识别 `true`、`t`、`yes`、`y` 和 `false`、`f`、`no`、`n`。全部观测都匹配时才推断为布尔。 |
| `options.inferTypes.url`、`options.inferTypes.path` | 布尔 | 否 | 所有观测值都带协议和主机时推断为 URL，所有观测值都为绝对 POSIX 路径时推断为路径。 |
| `options.inferTypes.fileRoot`、`options.inferTypes.image` | 字符串、布尔 | 否 | 指定本地绝对根目录后，目录内的普通文件可推断为 `File`。设 `image: true` 可将带受支持图片文件头的值推断为 `Image`。敏感模式跳过文件系统推断。 |
| `options.sensitive` | 布尔 | 否 | `true` 时 DuckDB 仅计算允许的汇总指标，省略原始行、重复组、原值和文本频数、文件元数据及时序点。 |
| `setter` | `(options: ProfileOptions) => Profile` | 否 | 返回要保存的 profile，替代引擎计算。 |

可解析为数值且不同值数超过 `numericCategoryThreshold` 的文本按数值画像。整数字符串在取值范围允许时使用 64 位整数类型。
支持解析的同格式或混合格式日期文本按 `DateTime` 画像。空字符串和 `NaT` 标记在日期统计中视为缺失。

Setter 接收选项对象（默认 `{}`），同步返回 `Profile`，不要求引擎支持统计。AVA 会验证并复制结果；无效结果或 setter 抛错会让调用失败，并保留原有元数据。选项直接传给 setter，AVA 不会代替它计算或过滤指标。

需要先加载数据源。两条路径都会替换已保存的 profile，供分析、翻译和推荐问题复用。设置 profile 不会替换 schema。

<h4 id="profile-format">Profile 格式</h4>

DuckDB 类型覆写支持 `Numeric`、`Categorical`、`Text`、`Boolean`、`DateTime`、`TimeSeries`、`URL`、`Path`、`File`、`Image` 和 `Unsupported`。已覆写的列会返回 `properties.profileType`。

Profile 通过名称，将统计信息附加到已有的 schema 模型和列上：

| 字段 | 含义 |
| --- | --- |
| `models[].name` | 要补充统计信息的模型。 |
| `models[].metrics` | 表级统计，例如 `row_count`。 |
| `models[].columns[].name` | 该模型中要补充统计信息的列。 |
| `models[].columns[].metrics` | 列级统计，例如 `mean`。 |
| `models[].columns[].properties.logicalType` | 规范化分类：`numeric`、`string`、`boolean`、`date` 或 `unknown`。 |

指标缺失表示未计算，不代表零。设置 schema 会清空 profile，因此手动提供两者时应先设置 schema。加载新数据源或调用 `dispose()` 会清空 schema、profile、semantic；更新 schema 或 profile 会保留 semantic。

<h4 id="metrics">统计指标</h4>

`metrics` 的每一项可以是指标名，也可以是带 `id` 和指标参数的对象。

```typescript
await ava.profile({
  metrics: ['row_count', { id: 'top_values', limit: 5 }],
});
```

**通用指标**

| 指标 | 适用范围 | 默认计算 | 含义 |
| --- | --- | --- | --- |
| `row_count` | 表 | 是 | 总行数。 |
| `null_count` | 列 | 是 | SQL NULL 或引擎中的缺失值数量。 |
| `distinct_count` | 数值、文本、布尔、日期 | 是 | 不同非空值的数量。 |
| `top_values` | 文本、布尔 | 是 | 最常见的非空值及其计数。不同值占比超过 `maxDistinctRatio` 时省略。 |
| `min`、`max` | 数值、日期 | 是 | 最小值和最大值。日期使用 Unix 毫秒。 |
| `mean` | 数值 | 是 | 算术均值。 |
| `duplicate_count` | 列 | — | 非空值数减去不同值数。 |
| `min_length`、`max_length` | 文本 | — | 最短和最长字符串的长度。 |
| `sum` | 数值 | — | 总和。 |
| `stddev` | 数值 | — | 样本标准差。 |
| `median` | 数值 | — | 中位数。 |

**DuckDB 扩展指标**

| 指标 | 适用范围 | 含义 |
| --- | --- | --- |
| `table_summary` | 表 | 行列数、SQL NULL 单元格数与占比、含 NULL 的列数、全 NULL 列数及各逻辑类型的列数。空表的全 NULL 列数为零。`data-profiling` 模式中，没有有效观测的列的逻辑类型为 `unknown`。 |
| `memory_size`、`record_size` | 表、列（`memory_size`） | 估算 DuckDB 数据字节数及平均每行字节数。计入定长槽位、UTF-8 文本和二进制数据，其他类型按 UTF-8 文本表示估算。计算范围为数据本身。 |
| `time_index` | 表 | 时序列数量、索引长度、端点和平均间隔。日期和时长使用毫秒。 |
| `row_duplicates` | 表 | 重复组数、重复组数占总行数的比例、组内总行数、去重后会移除的行数，以及按频次和键排序的样本。 |
| `row_sample` | 表 | 首部、尾部和随机样本，含按 DuckDB 扫描顺序计算的零起始行号。随机样本无放回。 |
| `pearson` | 表中的数值列 | 对称相关矩阵 `{ columns, matrix }`。每对列使用两边均为有限值的行。常量列或样本不足时返回 `null`。 |
| `spearman` | 表中的数值列 | 对称秩相关矩阵。每对列在各自的有限观测上排序，并列值取平均秩。 |
| `kendall` | 表中的数值列 | 有限值对的 Kendall tau-b 矩阵，分母包含并列值校正。 |
| `cramers` | 表中的类别列 | 经过偏差校正的 Cramér's V，对 2 × 2 列联表使用 Yates 校正。排除 NULL 和 NaN，符合条件的列不足两列时返回 `null`。 |
| `auto` | 表中的数值列和类别列 | 两列均为数值时使用 Spearman，含类别时使用 Cramér's V。数值与类别配对前对数值做右闭等宽分箱。 |
| `phi_k` | 表 | 由列联表计算 Phi-k 相关。数值列使用等宽分箱，系数通过二元正态分布校准。 |
| `missing_correlation` | 表 | 缺失标记之间的 Pearson 相关矩阵，SQL NULL 与 NaN 均算缺失。排除全缺失或全非缺失的列。 |
| `missing_matrix` | 表 | 按扫描顺序为每行返回一个字符串。所选列的 SQL NULL 或 NaN 记为 `1`，有值记为 `0`。同时返回列名和总行数。 |
| `missing_bands` | 表 | 将扫描行等间距分段，汇总每段中各列的非缺失比例，供 HTML 报告绘制缺失矩阵。 |
| `scatter_pairs` | 表 | 数值列之间的散点。数据量较小时返回配对的有限值，超过阈值时返回六边形分箱计数。 |
| `valid_count` | 列 | 非 NULL 值数量。 |
| `null_ratio` | 列 | SQL NULL 数量除以总行数。 |
| `distinct_ratio` | 数值、文本、布尔、日期 | 不同非空值数除以非空值数。 |
| `unique_count`、`unique_ratio` | 数值、文本、布尔、日期 | 仅出现一次的值数，以及该数量占非空值数的比例。 |
| `is_unique` | 数值、文本、布尔、日期 | 所有非空值是否都仅出现一次。无非空值时返回 `false`。 |
| `value_counts` | 数值、文本、布尔、日期 | 全部非空值的 `{ value, count }` 频数，按计数降序和原值排序。结果大小随不同值的数量增长。 |
| `extreme_values` | 数值 | 按值返回最小和最大的不同值及其频数。 |
| `text_examples` | 文本 | 按扫描顺序返回最前面的非空文本，可含重复值。 |
| `mode`、`mode_count` | 数值、文本、布尔、日期 | 频数排序中第一位的值及其计数。 |
| `imbalance` | 文本、布尔、数值类别编码 | 一减去归一化的 Shannon 熵，排除 NULL 和 NaN。均匀分布或少于两个类别时返回零。 |
| `monotonicity` | 数值 | 按 DuckDB 扫描顺序比较相邻有效值，跳过 NULL 和 NaN。返回递增、递减及各自严格单调的标志，`direction` 为严格递增 `2`、严格递减 `-2`、非严格递增 `1`、非严格递减 `-1` 或 `0`。 |
| `autocorrelation` | 数值 | 对有限观测计算 ACF 和未调整的 Yule–Walker PACF，附 95% 置信区间。 |
| `time_series_gaps` | 数值 | 找出超过平均正间隔两倍的观测断点，返回端点及间隔统计。日期索引和时长使用毫秒。 |
| `frequency_spectrum` | 数值 | FFT 正频率及分贝功率、检测到的峰值、选中的季节性峰值与对应观测周期。 |
| `adf` | 数值 | 含常数项的增广 Dickey–Fuller 检验统计量、MacKinnon p 值、选用滞后阶数、有效样本数和平稳判定。样本过少或回归奇异时返回 `null`。 |
| `chi_squared` | 数值、日期、文本 | 检验频数是否符合均匀分布，返回 `{ statistic, pvalue }`。文本按类别计数，数值和日期对有限值自动等宽分箱。 |
| `mean_length`、`median_length` | 文本 | 按 Unicode 码点计算的长度均值和中位数，重复值按出现次数加权。`data-profiling` 模式的中位数采用参考库将长度权重单独排序的算法。 |
| `length_histogram` | 文本 | 按长度排列的 `{ length, count }`。排除 NULL，空字符串长度为零。 |
| `word_counts` | 文本 | 使用 Unicode 小写、空白切词和 ASCII 标点修剪后的 `{ value, count }`。重复字符串按频数加权。 |
| `character_counts` | 文本 | 各 Unicode 码点的 `{ value, count }` 频数，保留空白和大小写。 |
| `unicode_summary` | 文本 | Unicode 码点总数、不同码点数，以及按通用类别、区块别名和文字系统分组的总频数与字符频数。 |
| `url_summary` | 文本 | URL 协议、授权部分、路径、查询和片段的频数。缺省部分计为空字符串。 |
| `path_summary` | 文本 | POSIX 路径的主干、后缀、名称、父目录和锚点频数与去重计数，以及字符级公共前缀。 |
| `file_summary` | `File` | 文件大小、访问时间、修改时间、元数据变更时间和文件大小直方图。时间使用 Unix 毫秒，保留到秒。 |
| `image_summary` | `Image` | 尺寸频数、宽高和面积统计、截断图像计数及可选的 EXIF 频数。使用可选依赖 `sharp` 和 `exifr`。 |
| `date_validation` | 文本、日期 | 无效日期的去重计数、行数和占比。文本支持 pandas 纳秒日期范围内的 ISO、常见数字和英文月份格式。 |
| `zero_count`、`zero_ratio` | 数值 | 零值数量及其占总行数的比例。 |
| `negative_count`、`negative_ratio` | 数值 | 负值数量及其占总行数的比例，包含负无穷。 |
| `infinite_count`、`infinite_ratio` | 数值 | 正负无穷值数量及其占总行数的比例。 |
| `nan_count`、`nan_ratio` | 数值 | NaN 数量及其占总行数的比例。 |
| `finite_count`、`finite_ratio` | 数值 | 有限值数量及其占总行数的比例。 |
| `variance`、`mad`、`iqr` | 数值 | 样本方差、中位数绝对偏差、75% 分位数减去 25% 分位数。 |
| `cv` | 数值 | 样本标准差除以均值。均值为零时返回 `null`。 |
| `range` | 数值、日期 | 最大值减去最小值。日期使用毫秒。整数和小数先相减再转为 JavaScript 数值，溢出时回退到浮点计算。 |
| `skewness`、`kurtosis` | 数值 | 样本偏度和超额峰度，分别至少需要三个和四个有限值。 |
| `quantiles` | 数值 | 按请求顺序返回 `{ probability, value }`。对有限值线性插值，无有限值时 `value` 为 `null`。 |
| `histogram` | 数值、日期 | 有限值的 `{ bin_edges, counts }`。内部分界线上的值归右侧桶，常量列使用一个加宽的桶。日期边界使用 Unix 毫秒。 |

DuckDB 中，分母为零时比例返回 `0`。默认分别统计 SQL NULL、NaN 和无穷值，数值摘要使用有限值。设定 `semantics: 'data-profiling'` 会将 NaN 视为 NULL，同时保留 `nan_count` 和 `nan_ratio`，并按参考库的规则在数值摘要中处理无穷值。正负无穷分别使用字符串 `Infinity` 和 `-Infinity`，未定义的数值结果使用 `null`。频数中的日期、大整数和小数也可用字符串保留原值。

表级缺失统计与列空值计数共用扫描，频数指标共用聚合，Pearson 的所有列对共用一次扫描。Pearson 的列对数随列数平方增长，宽表可指定列子集。直方图和分布形状指标共用一次预扫描计算分桶边界与均值。所有分位点在一次列表聚合中计算。

<Heading as="h3" id="compareprofiles">compareProfiles</Heading>

`compareProfiles(before, after)` 校验两份已保存的画像，按名称对齐模型、列和指标，并返回两侧观测值与有限数值差。两份画像需使用相同统计口径，仅出现在一侧的模型和列也会保留。

```typescript
import { compareProfiles } from '@antv/ava';

const comparison = compareProfiles(beforeProfile, afterProfile);
```

`renderProfileComparisonHtml(before, after, { title })` 将两侧观测和变化量渲染为可离线查看的并排表格。

<Heading as="h3" id="renderprofilehtml">renderProfileHtml</Heading>

`renderProfileHtml(profile, { title })` 将保存的画像渲染成可离线打开的 HTML。报告展示已有的指标表格、分布、相关矩阵和质量告警，读取报告无需重新计算画像。

<Heading as="h3" id="profileexpectations">profileExpectations</Heading>

`profileExpectations(profile, { name })` 根据已保存的画像生成旧版 Great Expectations 风格的规则集，每个模型一份。非空、唯一、数值和日期范围、单调性及允许值规则取自对应的已保存指标。

`validateProfileExpectations(profile, suites)` 用传入的画像验证已生成的规则集。每条规则返回 `passed`、`failed` 或 `missing_evidence`。

<Heading as="h3" id="quality">quality</Heading>

```typescript
quality(options?: QualityOptions): Promise<Quality>
```

用 `profile()` 已保存的指标检查数据质量，返回 `{ models: [{ name, alerts }] }`。这一步直接读取画像。每条告警包含规则名 `rule`，并在适用时返回相关列、观测值和阈值。

```typescript
await ava.profile({ metrics: ['row_count', 'null_count', 'distinct_count'] });
const quality = await ava.quality({ rules: ['missing', 'constant'] });
```

| 规则 | 使用的画像指标 | 默认阈值 |
| --- | --- | --- |
| `empty` | `row_count` 或 `table_summary` | 行数为零 |
| `duplicates` | `row_duplicates` | 至少一个重复组 |
| `constant`、`unique` | `distinct_count`、`row_count` | 仅一个不同值，或每行都有不同值 |
| `missing` | `null_ratio`，或 `null_count` 与 `row_count`，已有 `nan_count` 时计入 NaN | `ratioThreshold: 0.01` |
| `zeros`、`infinite` | `zero_ratio`、`infinite_ratio` | `ratioThreshold: 0.01` |
| `high_cardinality` | 文本列的 `distinct_count` | `cardinalityThreshold: 50` |
| `high_correlation` | 已保存的相关矩阵，每对列取绝对值最大的系数 | `correlationThreshold: 0.9` |
| `imbalance` | `imbalance` | `imbalanceThreshold: 0.5` |
| `skewed` | `skewness` | 偏度绝对值超过 `skewnessThreshold: 20` |
| `uniform` | 数值和文本列的 `chi_squared.pvalue` | `uniformThreshold: 0.999` |
| `non_stationary`、`seasonal` | 时序列的 `adf` 和 `frequency_spectrum` | ADF 检验未通过或检测到季节性峰时判为非平稳。 |
| `unsupported`、`rejected` | 列逻辑类型 | `unknown` |

省略 `rules` 时检查所有具有对应指标的规则。默认画像支持基础检查，其他检查需要先计算相应指标。

<Heading as="h3" id="semantic">semantic</Heading>

```typescript
semantic(options?: SemanticOptions, setter?: (options: SemanticOptions) => Semantic): Promise<Semantic>
```

读取或替换已加载数据源的语义定义。不传 setter 时返回已保存的定义，初始为 `{}`。这个调用不会发现 schema、计算 profile 或请求大模型。

```typescript
await ava.semantic(undefined, () => ({
  description: 'Sales reporting; amounts are in USD.',
  cubes: [{
    name: 'revenue',
    baseObject: 'data',
    measures: [{ name: 'total', expression: 'SUM(revenue)', type: 'DOUBLE' }],
  }],
}));

const definitions = await ava.semantic();
await ava.semantic(undefined, () => ({})); // Clear the saved definitions.
```

| 参数 | 类型 | 必填 | 含义与默认值 |
| --- | --- | --- | --- |
| `options` | `SemanticOptions` | 否 | `{}`，目前没有可配置字段。 |
| `setter` | `(options: SemanticOptions) => Semantic` | 否 | 返回要保存的业务语义，替换之前的完整定义。 |

Setter 接收选项对象，同步返回 `Semantic`。AVA 验证并复制结果；结果无效或 setter 抛错时保留之前的定义。需要先加载数据源。替换数据源或释放实例会清空语义；更新 schema、profile 会保留它。

`Semantic` 描述业务定义，不包含模型或列的 `metrics`；统计信息应通过 `profile()` 提供。引擎接收的组合上下文仍是 `DataModel`。

编写流程和销售示例见[补充业务语义](/documentation/data/semantic/)，详细字段见[语义字段](#semantic-fields)。

在 `analyze()`、`translate()`、`suggest()` 中，AVA 按名称将语义中的模型和列与 schema、profile 合并。未指定的模型、列及统计信息仍可使用；模型和列的属性按键合并，同名键以语义值为准。显式提供的关系或视图列表会整体替换发现的列表，包括空列表。每个语义模型都必须且只能声明一种来源：`tableReference`、`refSql` 或 `baseObject`。

这些定义为查询生成提供上下文。声明 cube、view 或计算列不会创建数据库对象，生成的查询仍须能在配置的引擎中执行。

<Heading as="h3" id="viz">viz</Heading>

`viz(spec: ChartSpecInput): Promise<string>`

| 参数 | 类型 | 必填 | 含义 |
| ---------------- | ----------- | -------- | --------------------------------------------------------------------------------------------------- |
| `spec` | `ChartSpecInput` | 是 | 应用默认值之前的图表描述对象。 |
| `spec.chartType` | `ChartType` | 是 | 下方类型之一；JSON 图表必须与 `config.type` 一致。 |
| `spec.config` | `ChartSpecInput['config']` | 是 | 原生 GPT-Vis 配置；省略 `config.type` 时由 `chartType` 补齐。`summary` 使用 T8 Syntax 字符串。 |

`ChartType` 可选值：`line`、`column`、`bar`、`pie`、`area`、`scatter`、`dual-axes`、`histogram`、`boxplot`、`radar`、`funnel`、`waterfall`、`liquid`、`word-cloud`、`violin`、`venn`、`treemap`、`sankey`、`table`、`summary`。

GPT-Vis 支持 26 种可视化类型。AVA 自动推荐上述 19 种 JSON 图表，也允许通过 `viz({ chartType: 'summary', config: '# 销售报告' })` 渲染原生摘要字符串。6 种关系图暂不在 AVA 契约范围内。`ChartSpec` 描述规范化后的结果，其中 JSON 图表的 `config.type` 已补齐。

`spec.html?: string` 用于接收 `visualize()` 的完整返回值。渲染始终根据 `config` 生成新的 HTML，不复用已有 `html`；外层其他未知字段会被拒绝。

返回独立 HTML 字符串，无需加载数据源，也不会调用模型。参见[图表配置](/documentation/visualization/overview/#recommend)。

<Heading as="h2" id="runtime-contracts">运行时契约</Heading>

AVA 将 `@antv/gpt-vis` 固定为 1.3.1。生成的 HTML 从 CDN 加载同一版本，原生图表契约也通过该包的类型检查。分类、名称和分组标签遵循原生字符串类型，时间标签也可以是数值；Treemap 节点必须提供 `value`。主题支持内置名称和原生主题对象，原生选项包含子标题、瀑布图中间合计和 Venn 字符串集合。

Node 和浏览器入口导出共享运行时 schema。SDK 的 `source()`、`recommend()`、`viz()` 和 CLI 在各自的输入边界使用这些契约。

MCP 等集成直接从 SDK 入口导入 API schema 与数据类型。Node 使用 `@antv/ava`，浏览器使用 `@antv/ava/browser`：

```typescript
import { queryInputSchema, queryOutputSchema } from '@antv/ava';
import type { ExecutionResult } from '@antv/ava';

const input = queryInputSchema.parse({ dsl: 'SELECT * FROM data', options: { maxRows: 10 } });
const output: ExecutionResult<unknown> = queryOutputSchema.parse(await ava.query(input.dsl, input.options));
```

API 类型统一通过 `z.input<typeof inputSchema>` 与 `z.output<typeof outputSchema>` 推导，结构、画像、语义、分析和建议等类型均与运行时 schema 共用字段定义。数据源类型描述规范化之前的输入，例如 Excel 的 `header` 仍可省略。`ExecutionResult<Row>` 保留查询行的泛型；运行时校验结果结构，不推断调用方泛型中的行字段。ClickHouse 选项继续引用官方客户端的原生类型，支持 TLS Buffer、Agent 和回调等，由客户端处理透传的原生选项。

公开 schema 按 API 的输入、输出命名。多参数方法使用命名参数对象，单参数方法直接使用参数值；省略选项时仍由 SDK 应用默认值。setter 回调保留为 SDK 函数，不放入数据 schema，其返回的元数据可用对应输出 schema 校验。CLI 会话字段和更严格的传输限制由适配层维护。

| API | 输入 schema 与形状 | 输出 schema |
| --- | --- | --- |
| `source` | `sourceInputSchema`：数据源配置 | 无返回值（`void`） |
| `schema` | `schemaInputSchema`：选项 `{}` | `schemaOutputSchema` |
| `profile` | `profileInputSchema`：`{ metrics? }` | `profileOutputSchema` |
| `quality` | `qualityInputSchema` | `qualityOutputSchema` |
| `semantic` | `semanticInputSchema`：选项 `{}` | `semanticOutputSchema` |
| `query` | `queryInputSchema`：`{ dsl, options? }` | `queryOutputSchema` |
| `analyze` | `analyzeInputSchema`：`{ query, config? }` | `analyzeOutputSchema` |
| `translate` | `translateInputSchema`：问题字符串 | `translateOutputSchema`：DSL 字符串 |
| `suggest` | `suggestInputSchema`：数量 | `suggestOutputSchema`：建议数组 |
| `recommend` | `recommendInputSchema`：`{ query, data }` | `recommendOutputSchema`：图表配置或 `null` |
| `visualize` | `visualizeInputSchema`：`{ query, data }` | `visualizeOutputSchema`：必含 HTML 的图表配置或 `null` |
| `viz` | `vizInputSchema`：应用默认值前的图表配置 | `vizOutputSchema`：HTML 字符串 |

Node 和 browser 入口统一导出 API 输入、输出 schema。类型沿用 `DataSourceConfig`、`SchemaOptions`、`ExecutionResult`、`AnalysisResponse` 等原有命名。`ExecutionResult<Row>`、`AnalysisResponse<Row>` 保留行泛型，默认使用对象行类型。`dispose()` 没有输入数据或返回值，无需数据 schema。

MCP 等 JSON Schema 工具对输入使用 `z.toJSONSchema(inputSchema, { io: 'input' })`，对输出使用 `z.toJSONSchema(outputSchema, { io: 'output' })`。输入模式描述归一化之前的值；输出模式包含图表 `config.type` 等归一化后的必需字段。

<Heading as="h2" id="cleanup">资源清理</Heading>

<Heading as="h3" id="dispose">dispose</Heading>

`dispose(): Promise<void>` 没有参数，释放当前引擎并清空 schema、profile 与业务语义。应在 `finally` 中等待它执行完成。

<Heading as="h2" id="semantic-model-reference">语义模型参考</Heading>

<Heading as="h3" id="semantic-fields">语义字段</Heading>

六个顶层字段均可选，按应用需要提供即可。名称和必填表达式必须是非空字符串。`properties` 包含 JSON 值，其中的数值必须有限；`description`、`unit`、`synonyms`、`owner` 等键是应用约定，不代表 SDK 内置行为。

| 字段 | Shape | 用途 |
| --- | --- | --- |
| `description` | `string` | 共享业务背景、术语、记录范围与时间口径。 |
| `properties` | `Record<string, JsonValue>` | 共享注释。 |
| `models` | 下方的模型定义 | 物理及逻辑数据集、列含义与来源映射。 |
| `relationships` | 下方的关系定义 | 命名模型之间的连接关系。 |
| `views` | 下方的视图定义 | 可复用的命名 SQL 查询。 |
| `cubes` | 下方的 Cube 定义 | 指标、分组表达式与下钻路径。 |

<Heading as="h3" id="semantic-models">语义模型</Heading>

| 字段 | 必填 | 含义 |
| --- | --- | --- |
| `name` | 是 | 逻辑模型名；按名称匹配已有 schema 模型，或添加新模型。 |
| `tableReference` | 三种来源选择器之一 | `{ table, schema?, catalog? }`，独立于逻辑名称的物理标识；额外的来源属性必须是 JSON 值。 |
| `refSql` | 三种来源选择器之一 | 列映射与计算之前，用于定义源数据行的 SQL。 |
| `baseObject` | 三种来源选择器之一 | 提供数据行的另一个模型或视图名称。 |
| `columns` | 否 | 列定义见下方；未列出的已有列仍保留。 |
| `primaryKey` | 否 | 单列名称，或代表复合主键的有序非空数组。 |
| `uniqueKeys` | 否 | 唯一键数组，每项是单列名称或非空复合键数组。 |
| `dialect` | 否 | `refSql` 的 SQL 方言；省略时使用执行上下文。 |
| `properties` | 否 | 模型注释，尤其是行粒度和业务用途。 |

主键、唯一键是声明，不是统计结论，需要对照数据源验证。`primaryKey: ['tenant_id', 'order_id']` 表示一个复合键；`uniqueKeys: ['email', ['tenant_id', 'external_id']]` 则声明两个候选唯一键。

<Heading as="h3" id="semantic-columns">语义列</Heading>

| 字段 | 必填 | 含义 |
| --- | --- | --- |
| `name` | 是 | 所属模型内的名称，用于匹配已有列。 |
| `type` | 是 | 声明的类型；关系导航列则填写目标模型名称。 |
| `properties` | 否 | 列的上下文，例如描述、单位、枚举含义或空值约定。 |
| `expression` | 否 | 针对来源的 SQL 映射或计算；`null` 或省略表示不提供表达式。 |
| `isCalculated` | 否 | 标记派生列的布尔值，本身不会执行计算。 |
| `isPrimaryKey` | 否 | 标记是否属于已声明主键的布尔值。 |
| `notNull` | 否 | 声明的非空约束，省略表示未指定。 |
| `relationship` | 否 | 用于导航的关系标识，不是外键列名。 |

<Heading as="h3" id="semantic-relationships-and-views">语义关系与视图</Heading>

| 字段 | 必填 | 含义 |
| --- | --- | --- |
| `relationships[].name` | 是 | 关系标识，也用于列导航。 |
| `relationships[].models` | 是 | 恰好两个模型名，顺序为第一模型、第二模型。 |
| `relationships[].joinType` | 是 | `ONE_TO_ONE`、`ONE_TO_MANY`、`MANY_TO_ONE` 或 `MANY_TO_MANY`。 |
| `relationships[].condition` | 是 | 使用限定列名的 SQL 连接条件。 |
| `relationships[].properties` | 否 | 关系的业务背景。 |
| `views[].name` | 是 | 查询的逻辑名称。 |
| `views[].statement` | 是 | 定义结果的 SQL；保存不会执行它。 |
| `views[].dialect` | 否 | SQL 方言，省略时使用执行上下文。 |
| `views[].properties` | 否 | 用途与业务口径。 |

关系和视图允许额外的 JSON 属性，由应用及其使用方约定含义。

<Heading as="h3" id="semantic-cubes-and-expressions">语义 Cube 与表达式</Heading>

| 字段 | 必填 | 含义 |
| --- | --- | --- |
| `name` | 是 | Cube 标识。 |
| `baseObject` | 是 | 提供聚合数据行的模型或视图。 |
| `measures` | 是 | 非空的聚合定义数组。 |
| `dimensions` | 否 | 分组定义。 |
| `timeDimensions` | 否 | 日期、时间分组定义，粒度在查询时选择。 |
| `hierarchies` | 否 | 名称到非空维度名数组的映射，从粗粒度到细粒度排列。 |
| `properties` | 否 | Cube 注释。 |

`measures`、`dimensions` 和 `timeDimensions` 的每一项都使用以下字段：

| 字段 | 必填 | 含义 |
| --- | --- | --- |
| `name` | 是 | Cube 内的表达式标识。 |
| `expression` | 是 | 指标使用 SQL 聚合表达式，维度使用分组表达式。 |
| `type` | 是 | 声明的结果类型。 |
| `description` | 否 | 表达式的业务含义。 |
| `properties` | 否 | 单位、同义词等注释。 |

例如，按日历下钻时，先定义 `year`、`month`、`order_date` 的维度表达式，再声明 `hierarchies: { calendar: ['year', 'month', 'order_date'] }`。层级只描述路径，不会自动生成这些字段。

模型、列、Cube 和表达式对象会拒绝未知字段；需要应用注释时，放在支持的 `properties` 中。

<Heading as="h3" id="semantic-model-sources">语义模型来源</Heading>

编写映射前，先调用 `schema()` 检查模型名称、来源引用与列类型。名称必须在所属模型内准确匹配。销售示例的内存 JSON 暴露为 `data`；其他数据源可能使用不同名称，并带有 catalog 或 schema 限定信息。

`models` 中的每一项都需要 `name`，并且 **只能选择一种** 来源，即使只是想给已有模型补充描述：

| 来源选择器 | 适用情况 | 示例 |
| --- | --- | --- |
| `tableReference` | 模型映射到物理表或数据库视图，保留发现的来源限定信息。 | `{ tableReference: { schema: 'public', table: 'orders' } }` |
| `refSql` | 用 SQL 定义逻辑模型的源数据行。 | `{ refSql: "SELECT * FROM orders WHERE status = 'paid'" }` |
| `baseObject` | 由另一个模型或已声明视图提供源数据行。 | `{ baseObject: 'paid_orders' }` |

使用已有 schema 模型的 `name` 可以补充该模型。换用其他名称会新增逻辑模型，不会重命名底层表。列即使只补充描述，也必须提供 `name` 和 `type`；物理列沿用发现的类型，计算列声明结果类型。

`baseObject`、`refSql` 和列的 `expression` 为查询生成器描述映射。逻辑名称不代表能直接交给 `query()` 执行。例如，查询计算列 `net_amount` 时，需要展开其表达式，或通过子查询、CTE 定义。

<Heading as="h3" id="semantic-join-and-view-examples">语义关系与视图示例</Heading>

跨模型分析时添加关系；可复用 SQL 有助于表达业务逻辑时添加视图。以下片段假定已有数据源提供 `orders`、`customers`，与前面的单表销售示例相互独立。

<h4 id="relationship-example">关系示例</h4>

```typescript
import type { Semantic } from '@antv/ava';

const semantic = {
  relationships: [{
    name: 'order_customer',
    models: ['orders', 'customers'],
    joinType: 'MANY_TO_ONE',
    condition: 'orders.customer_id = customers.id',
    properties: { description: 'Each order belongs to one customer.' },
  }],
} satisfies Semantic;
```

`models` 是有序模型对。`MANY_TO_ONE` 表示第一模型的多行可以匹配第二模型的一行。`joinType` 描述基数，不决定使用 `LEFT JOIN` 还是 `INNER JOIN`。复合键的连接条件需要包含所有键字段。

如果暴露关系导航列，应将 `relationship` 设为关系的 **名称** ，将 `type` 设为目标模型名，例如 `{ name: 'customer', type: 'customers', relationship: 'order_customer' }`。物理外键列仍是 `customer_id`。

跨表聚合前先检查行粒度。一笔订单连接多条明细时，订单金额可能被重复计算。基数声明只提供上下文，AVA 不会验证唯一性，也不会自动避免重复计数。

<h4 id="view-and-derived-model-example">视图与派生模型示例</h4>

```typescript
import type { Semantic } from '@antv/ava';

const semantic = {
  views: [{
    name: 'paid_orders',
    statement: "SELECT * FROM orders WHERE status = 'paid'",
    dialect: 'duckdb',
    properties: { description: 'Paid orders only; this excludes fully refunded orders.' },
  }],
  models: [{
    name: 'paid_sales',
    baseObject: 'paid_orders',
    properties: { description: 'One row per paid order.' },
  }],
} satisfies Semantic;
```

这里的逻辑模型引用一个命名查询，生成器可以将其展开为 CTE 或子查询。只有执行引擎中已存在 `paid_orders` 时，`await ava.query('SELECT * FROM paid_orders')` 才能执行；保存定义不会创建它。不需要单独命名视图时，也可以直接用模型的 `refSql` 描述来源查询。

<Heading as="h3" id="save-and-combine-semantic-definitions">保存并合并语义定义</Heading>

在应用中保留一份完整定义，与对应数据源一起管理版本，并在 `source()` 之后传给 AVA。每次 setter 都替换已保存的整个语义对象，不会追加或局部修改旧定义。

```typescript
await ava.semantic(undefined, () => completeDefinitions);
const saved = await ava.semantic();
await ava.semantic(undefined, () => ({})); // Clear all saved semantics.
```

定义可保存在代码或应用自己的 JSON 文件中。例如，Node.js 加载数据源后：

```javascript
const { readFile } = require('node:fs/promises');
const definitions = JSON.parse(await readFile('./sales-semantic.json', 'utf8'));
await ava.semantic(undefined, () => definitions);
```

JSON 文件只包含定义对象，不带 JavaScript 变量声明或 setter。AVA 接受对象而非文件路径；如果保存为 YAML，请先在应用中解析，再调用 setter。读取和解析文件可以异步完成，setter 本身同步返回对象。

操作需要数据模型时，AVA 按以下顺序组合输入：

| 组合方式 | 行为 |
| --- | --- |
| 先 schema，再 profile | 按名称将统计信息附加到已有模型和列。 |
| 语义模型 | 同名模型补充已有内容，新名称添加逻辑模型；显式来源选择器优先。 |
| 语义列 | 同名列补充已有列，新名称添加新列。未列出的模型、列及 profile 指标仍可使用；空列数组不会删除已发现的列。 |
| 模型与列的 `properties` | 按键合并，同名键以语义值为准；嵌套 JSON 值整体替换，不递归合并。 |
| 显式提供的其他模型与列字段 | 语义值替换对应字段，包括类型与键声明。 |
| 顶层字段 | 显式值替换对应内容。关系与视图数组整体替换；`[]` 会清空组合上下文中的相应列表。 |

省略某部分会保留对应的 schema 上下文。需要在已发现的外键之外新增关系时，应在传入列表中包含仍要保留的关系。读取 `schema()`、`profile()`、`semantic()` 返回的仍是各自输入，不是组合模型；目前没有公开方法读取合并后的 `DataModel`。

更新 schema 会清空 profile、保留语义；计算 profile 会替换统计信息、保留语义；加载新数据源或调用 `dispose()` 会清空三者。加载新数据源后应重新应用保存的定义，并在结构变化时复核映射。这些调用都需要活动数据源，无效数据源配置会保留当前数据集；配置通过校验后，实际替换过程失败则没有活动数据源。

Setter 验证并复制返回对象。验证失败或 setter 抛错时，之前的语义定义保持不变。

<Heading as="h3" id="semantic-validation">语义验证</Heading>

结构验证检查字段形状、必填项、来源选择器的互斥性及非空指标列表，但 **不能证明** SQL 有效、引用对象存在、键声明成立、单位一致或业务规则正确。重复的语义模型名、同一模型内的重复列名，会在分析、翻译或推荐问题组装组合模型时被拒绝，而非仅由 setter 拒绝。

为自己的数据定义口径时，可以沿用销售示例的验证流程：

1. 查看 `schema()`，准确匹配名称与物理类型。远程数据源需保留 catalog 和 schema 限定信息。
2. 请业务负责人复核行粒度、纳入统计的状态、空值处理、单位与时间口径。
3. 用答案已知的小数据集逐一运行表达式，按需覆盖被排除记录、空值、退款及连接重复计数等情况。
4. 针对同样的问题检查 `translate()` 输出，再将执行结果与已知答案对照。Setter 成功不等于端到端验证成功。
5. 数据源结构或业务定义变化后，重新执行这些检查。

| 现象 | 检查方向 |
| --- | --- |
| Setter 拒绝模型 | 必须且只能提供 `tableReference`、`refSql`、`baseObject` 之一；列需要 `name` 和 `type`。 |
| Setter 拒绝 Cube | 需要 `baseObject`，以及至少一个包含 `name`、`expression`、`type` 的指标。 |
| Setter 拒绝统计信息 | 模型与列的 `metrics` 应传给 `profile()`，不要放进 `semantic()`。 |
| 查询提示逻辑名称不存在 | 检查 SQL 是否将声明的表达式、视图或模型展开为可执行 SQL。 |
| 已发现的连接关系消失 | 你提供的关系列表替换了发现的列表，请包含所有仍需要的关系。 |
| 数值偏大 | 检查行粒度、连接基数、重复键、记录过滤和退款处理。 |
| 规则未生效 | 检查生成的查询。必须遵守的访问规则应在数据层或执行层强制实施。 |
