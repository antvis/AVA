这页用于查方法签名、字段和默认值。第一次使用建议先看[快速开始](/documentation/quickstart/)。数据与可视化方法均为异步调用；生命周期监听见[事件参考](/documentation/reference/events/)。

<h2 id="api-at-a-glance">先找到你需要的操作</h2>

| 目标 | 方法 |
| --- | --- |
| 配置模型与引擎 | `new AVA(config)` |
| 加载或切换数据 | `source(config)` |
| 读取或提供结构 | `schema(options?, setter?)` |
| 计算或提供统计 | `profile(options?, setter?)` |
| 读取或提供业务口径 | `semantic(options?, setter?)` |
| 用自然语言分析 | `analyze(query, config?)` |
| 分开生成与执行 | `translate(query)`、`query(dsl, options?)` |
| 推荐分析问题 | `suggest(count?)` |
| 推荐或生成图表 | `recommend(result)`、`visualize(result)` |
| 渲染已有图表配置 | `viz(spec)` |
| 释放资源 | `dispose()` |

<h2 id="initialization">初始化</h2>

<h3 id="constructor">构造实例</h3>

`new AVA(config: AVAConfig)` 只保存配置，不立即加载数据。引擎在 `source()` 时创建。

| 字段 | 必填 | 用法 |
| --- | --- | --- |
| `llm` | 是 | 模型配置。 |
| `engine` | 否 | 默认 `{ type: 'duckdb' }`。 |

<h3 id="model-options">模型配置</h3>

| 字段 | 类型 | 默认行为 |
| --- | --- | --- |
| `provider` | `'openai' \| 'gateway'` | 默认兼容 OpenAI 的 Chat Completions。 |
| `model` | `string \| LanguageModel` | 必填，模型名或已配置模型对象。 |
| `apiKey` | `string` | 可选，服务凭证。 |
| `baseURL` | `string` | 可选，自定义服务地址。 |
| `maxRetries` | `number` | 模型请求重试次数，默认 `3`。 |

Gateway 未显式提供 Key 时可读取 `AI_GATEWAY_API_KEY`。模型对象直接使用，不再按字符串重新创建。详见[模型配置](/documentation/configuration/)。

<h3 id="engine-options">引擎配置</h3>

提供 `engine` 时，`type` 必填。支持 duckdb、python、javascript、supabase、clickhouse 和注册名称。

| 字段 | 所属引擎 | 默认行为 |
| --- | --- | --- |
| `memoryLimit` | DuckDB | `'512MB'`。 |
| `threads` | DuckDB | `1`。 |
| `maxTempDirectorySize` | DuckDB | 不设置临时目录大小上限。 |
| `queryTimeoutMs` | DuckDB、Python | `30000` 毫秒。 |
| `allowCommunityExtensions` | DuckDB | 必要时显式启用社区扩展。 |
| `execute` | Python | 自定义完整 Python 脚本执行器，返回 `Promise<ExecutionResult>`。 |

其他内置引擎没有额外构造字段。连接凭证属于[数据源参数](/documentation/data/sources/)，引擎扩展见[自定义引擎](/documentation/engines/custom/)。

<h2 id="data">数据与上下文</h2>

<h3 id="source">加载数据</h3>

```typescript
source(config: DataSourceConfig): Promise<void>
```

```typescript
await ava.source({ type: 'json', options: { data: [{ revenue: 120 }] } });
```

`config.type` 指定源类型，`config.options` 提供对应配置。方法只加载，不发现结构。切换前释放旧引擎，并清空结构、统计和语义；加载失败后没有活动数据源。

<h3 id="schema">结构发现与替换</h3>

```typescript
schema(options?: SchemaOptions, setter?: (options: SchemaOptions) => Schema): Promise<Schema>
```

无 Setter 时返回已保存的结构，首次读取则通过引擎发现并保存。分析和统计也会按需获取结构，直接 `query()` 不要求先发现。

```typescript
const schema = await ava.schema();
```

```typescript
await ava.schema(undefined, () => savedSchema);
```

`options` 默认 `{}`，当前没有可配置字段。Setter 同步返回 Schema，验证后复制保存，并清空旧 Profile；校验失败或 Setter 抛错时保留旧元数据。必须先加载数据。

<h3 id="schema-structure">Schema 结构</h3>

| 字段 | 含义 |
| --- | --- |
| `models` | 必填，可查询的模型列表。 |
| `models[].name` | 模型名称。 |
| `models[].tableReference` | 物理来源，包含 table，可选 catalog、schema。 |
| `models[].columns` | 字段列表，每个字段有 name、type，可选 notNull。 |
| `models[].primaryKey` | 单字段名，或表示复合键的非空有序数组。 |
| `models[].uniqueKeys` | 备选唯一键列表，每个元素为字段名或复合键数组。 |
| `relationships` | 数据源提供的外键关系。 |
| `views` | 命名查询，包含 name、statement。 |

查询结果的 `schema` 只描述返回列，与这里的数据源 Schema 不同。

<h3 id="profile">计算与提供统计</h3>

```typescript
profile(options?: ProfileOptions, setter?: (options: ProfileOptions) => Profile): Promise<Profile>
```

```typescript
const profile = await ava.profile({ metrics: ['row_count', 'mean'] });
```

不提供 Setter 时每次重新计算，要求引擎支持统计；提供 Setter 时保存其同步返回的 Profile，不要求引擎计算能力。

```typescript
await ava.profile(undefined, () => savedProfile);
```

`options.metrics` 是 `MetricConfig[]`，传入后替换默认指标列表；不会替 Setter 计算或筛选结果。每次调用替换完整 Profile，不修改 Schema。

<h3 id="profile-format">Profile 结构</h3>

| 字段 | 含义 |
| --- | --- |
| `models[].name` | 要补充的模型名。 |
| `models[].metrics` | 表级统计，如 row_count。 |
| `models[].columns[].name` | 对应模型内的字段名。 |
| `models[].columns[].metrics` | 字段统计，如 mean。 |
| `models[].columns[].properties.logicalType` | numeric、string、boolean、date 或 unknown。 |

缺少指标表示未计算，不表示零。手动提供两种元数据时先设置 Schema，因为更新结构会清空 Profile。

<h3 id="metrics">统计指标</h3>

默认指标为 `row_count`、`null_count`、`distinct_count`、`top_values`、`min`、`max`、`mean`。还支持 `duplicate_count`、`min_length`、`max_length`、`sum`、`stddev`、`median`。可用性取决于引擎和字段类型。

```typescript
await ava.profile({
  metrics: ['row_count', { id: 'top_values', limit: 5 }],
});
```

对象条目需要 `id`。`top_values` 还支持 `limit`（默认 3，非负安全整数）和 `maxDistinctRatio`（默认 0.5，0—1 的有限值）。其他内置指标没有额外选项；未知指标与选项在计算时拒绝。`metrics: []` 产生空统计对象。

<h3 id="semantic">读取与替换业务语义</h3>

```typescript
semantic(options?: SemanticOptions, setter?: (options: SemanticOptions) => Semantic): Promise<Semantic>
```

不提供 Setter 时返回已保存定义，初始为 `{}`。这个方法不发现结构、不计算统计，也不调用模型。

```typescript
await ava.semantic(undefined, () => ({
  description: 'Sales reporting; amounts are in USD.',
  cubes: [{
    name: 'revenue',
    baseObject: 'data',
    measures: [{ name: 'total', expression: 'SUM(revenue)', type: 'DOUBLE' }],
  }],
}));

const definitions = await ava.semantic();
await ava.semantic(undefined, () => ({})); // Clear the saved definitions.
```

`options` 默认 `{}`，当前没有可配置字段。Setter 同步返回完整定义，验证并复制后替换旧值，不是补丁；失败保留原定义。结构、统计更新时保留语义，加载其他源或释放实例时清空。完整示例见[业务语义指南](/documentation/data/semantic/)。

<h2 id="analysis-and-queries">分析与查询</h2>

<h3 id="analyze">回答自然语言问题</h3>

`analyze(query: string, config?: AnalysisConfig): Promise<AnalysisResponse>`

| 字段 | 用法 |
| --- | --- |
| `query` | 必填问题。 |
| `includeSummary` | 默认 `true`，关闭后 text 为空。 |
| `maxRows` | 默认 `200`。 |
| `maxResultBytes` | 默认 `1048576`。 |
| `strategy` | 按次选择 direct 或 loop，详见[策略说明](/documentation/analysis/strategies/)。 |

需要已加载数据。返回 ExecutionResult 的字段，额外带原始 `query`、总结 `text`，以及可选的 `sql`、`markdown`。`sql` 字段也用于非 SQL 引擎的实际执行代码。分析本身不生成图表。

<h3 id="translate">只生成查询</h3>

`translate(query: string): Promise<string>`。需要已加载数据与可用模型，使用结构、已有统计和业务语义生成 DSL，不执行。

<h3 id="query">直接执行代码</h3>

`query(dsl: string, options?: ExecutionOptions): Promise<ExecutionResult>`。`dsl` 必填，按当前引擎语言执行；不经过模型翻译、总结或自动纠正。

<h3 id="executionoptions">ExecutionOptions</h3>

| 字段 | 默认值 | 规范化规则 |
| --- | --- | --- |
| `maxRows` | `200` | 向下取整，限制在 1—1,000,000；取整后超出安全整数范围则用默认值。 |
| `maxResultBytes` | `1048576` | 有限值向下取整且最小为 1；非有限值使用默认值。 |

这些选项限制返回数据，与引擎超时分别生效。

<h3 id="executionresult">ExecutionResult</h3>

| 字段 | 含义 |
| --- | --- |
| `schema` | 结果列列表，每列含 name，可选 type。 |
| `data` | 返回的数据行数组。 |
| `truncated` | 截断时为 true。 |
| `truncatedBy` | 触发限制的 maxRows 或 maxResultBytes。 |
| `rowCount` | 完整结果行数，已知时提供。 |

<h3 id="suggest">推荐问题</h3>

`suggest(count?: number): Promise<SuggestResult[]>`。`count` 默认 3，需要已加载数据并调用模型。每项含 `query`、`score`、`reason`；分数限制为 0—1，按降序返回，表示问题价值而非答案置信度。返回数组可以为空。

<h2 id="visualization">可视化</h2>

<h3 id="visualize-and-recommend">推荐图表或一步生成</h3>

`recommend(analysisResult): Promise<ChartSpec | null>`

`visualize(analysisResult): Promise<VisualizeResponse | null>`

都接收 `analysisResult.query` 和 `analysisResult.data`。前者描述问题或绘图意图，后者是记录数组。不需要已加载的数据源，但会调用模型；空数据或没有推荐时返回 null，生成错误继续抛出。

`recommend()` 返回 `chartType` 与 GPT-Vis `config`；`visualize()` 还带独立 HTML。

<h3 id="viz">渲染指定配置</h3>

`viz(spec: ChartSpec): Promise<string>`。`spec.chartType` 和 `spec.config` 必填；config.type 应对应 chartType。当前渲染器直接使用 config。无需模型或已加载源，返回独立 HTML。图表种类见[图表指南](/documentation/visualization/overview/#chart-specifications)。

<h2 id="cleanup">资源清理</h2>

<h3 id="dispose">结束使用</h3>

`dispose(): Promise<void>`。释放引擎，清空结构、统计和语义。无参数，推荐在 finally 中等待完成。

<h2 id="semantic-model-reference">语义模型字段参考</h2>

<h3 id="semantic-fields">顶层字段</h3>

六个字段都可选，按业务需要提供。名称和必要表达式必须为非空字符串。

| 字段 | 用途 |
| --- | --- |
| `description` | 业务背景、术语、有效记录与时间约定。 |
| `properties` | 额外 JSON 注解，数字必须有限。 |
| `models` | 模型、字段含义和来源映射。 |
| `relationships` | 模型间的连接。 |
| `views` | 可复用的命名 SQL。 |
| `cubes` | 聚合指标、维度和下钻层级。 |

description、unit、synonyms、owner 等 properties 键是应用约定，不代表 SDK 有对应的内建行为。

<h3 id="semantic-models">模型定义</h3>

| 字段 | 要求与含义 |
| --- | --- |
| `name` | 必填，匹配已有模型或增加逻辑模型。 |
| `tableReference` | 来源三选一，含 table，可选 schema、catalog。 |
| `refSql` | 来源三选一，通过 SQL 定义原始记录。 |
| `baseObject` | 来源三选一，引用另一个模型或 view。 |
| `columns` | 字段定义，未列出的现有字段仍保留。 |
| `primaryKey` | 一个字段名或非空复合键数组。 |
| `uniqueKeys` | 多个备选唯一键。 |
| `dialect` | refSql 使用的 SQL 方言。 |
| `properties` | 模型用途、记录粒度等注解。 |

键是声明，不是已验证的统计。复合主键用一个数组，多种唯一键则放在 uniqueKeys 的不同元素里。

<h3 id="semantic-columns">字段定义</h3>

| 字段 | 要求与含义 |
| --- | --- |
| `name` | 必填，在所属模型内匹配字段。 |
| `type` | 必填，声明类型；关系导航字段用目标模型名。 |
| `properties` | 业务含义、单位、枚举解释和空值约定。 |
| `expression` | 来源映射或计算 SQL，可省略或为 null。 |
| `isCalculated` | 是否计算字段；声明本身不执行计算。 |
| `isPrimaryKey` | 是否属于声明的主键。 |
| `notNull` | 非空约束，省略表示未说明。 |
| `relationship` | 关系标识，不是外键字段名。 |

<h3 id="semantic-relationships-and-views">关系与逻辑视图</h3>

| 字段 | 要求与含义 |
| --- | --- |
| `relationships[].name` | 必填，关系标识。 |
| `relationships[].models` | 必填，按方向排列的两个模型名。 |
| `relationships[].joinType` | 必填，ONE_TO_ONE、ONE_TO_MANY、MANY_TO_ONE 或 MANY_TO_MANY。 |
| `relationships[].condition` | 必填，含限定字段的 SQL 连接条件。 |
| `relationships[].properties` | 关系的业务背景。 |
| `views[].name` | 必填，逻辑查询名。 |
| `views[].statement` | 必填，SQL 查询，保存时不会执行。 |
| `views[].dialect` | 可选 SQL 方言。 |
| `views[].properties` | 用途与业务约定。 |

关系与视图还接受应用约定的额外 JSON 属性。

<h3 id="semantic-cubes-and-expressions">指标集合与表达式</h3>

| 字段 | 要求与含义 |
| --- | --- |
| `name` | 必填，cube 标识。 |
| `baseObject` | 必填，提供原始记录的模型或 view。 |
| `measures` | 必填且非空，聚合指标。 |
| `dimensions` | 分组维度。 |
| `timeDimensions` | 日期时间分组，粒度在查询时确定。 |
| `hierarchies` | 下钻路径，名称映射到由粗到细的非空维度名数组。 |
| `properties` | 额外注解。 |

measures、dimensions、timeDimensions 中的表达式项都需要 `name`、`expression`、`type`，可选 `description` 与 `properties`。指标的 expression 是聚合 SQL，维度的 expression 是分组表达式。

模型、字段、cube 和表达式对象拒绝未知字段；额外注解应放在支持的 properties 中。

<h3 id="semantic-model-sources">把逻辑含义映射回真实数据</h3>

先检查 Schema，按准确名称匹配模型与字段，保留来源的 catalog、schema 限定信息。每个语义模型必须且只能选 tableReference、refSql、baseObject 之一；即使只补说明，也需要 name 与来源选择器。每个字段都需要 name 与 type。

不同模型名会增加逻辑模型，不会重命名物理表。定义本身不创建数据库对象，查询生成器需要把表达式、view 或逻辑模型展开成能执行的 SQL。

<h3 id="semantic-join-and-view-examples">跨表时先检查粒度</h3>

一对多连接可能重复订单金额。joinType 描述基数，不代表 LEFT JOIN 或 INNER JOIN；复合键需要完整连接条件。关系声明不会自动验证唯一性或阻止重复计数。

关系导航字段的 relationship 指向关系名，type 指向目标模型，真实外键字段依然独立存在。

<h3 id="save-and-combine-semantic-definitions">保存与组合规则</h3>

完整定义可以保存在代码或应用管理的 JSON 文件中，读取后交给 Setter；不能直接把文件路径传给 semantic()。YAML 需要应用先解析。

| 输入组合 | 行为 |
| --- | --- |
| Schema 加 Profile | 按模型、字段名补充观察结果。 |
| 语义模型与字段 | 同名补充，新名称增加；未列出的结构与统计保留。 |
| properties | 按键合并，同键以语义值优先；嵌套 JSON 整体替换。 |
| 其他模型、字段属性 | 语义值替换对应值，包括类型与键声明。 |
| 顶层字段 | 提供后整体替换；关系和视图列表不会逐项追加，空数组会清空对应列表。 |

省略的部分保留对应结构上下文。三个读取方法返回各自保存值，没有公开方法读取合并后的 DataModel。

<h3 id="semantic-validation">结构合法，还要验证业务正确</h3>

结构验证检查形状、必填字段、来源三选一和非空指标列表，不验证 SQL 正确性、对象存在性、键唯一性、单位或业务口径。同名语义模型和模型内重复字段在构造分析上下文时拒绝，不只在 Setter 校验时处理。

用小数据验证有效状态、空值、退款和连接重复；再检查生成的 SQL 与已知答案是否一致。必须执行的访问控制，应落实在数据或执行层。
