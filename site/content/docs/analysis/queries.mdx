## Translate a question

```typescript
const dsl = await ava.translate('Total revenue by region');
console.log(dsl);
```

`translate(query): Promise<string>` uses the selected engine, loaded schema, and available profile to generate DSL without executing it. The language is DuckDB SQL, PostgreSQL SQL, ClickHouse SQL, Python, or JavaScript depending on the engine.

## Execute a query

```typescript
const result = await ava.query(dsl, {
  maxRows: 100,
  maxResultBytes: 1048576,
});
console.log(result.schema, result.data);
```

`query(dsl, options?)` executes the supplied DSL without asking the LLM to translate or summarize it. It does not automatically correct failed queries.

## Execution results

`ExecutionResult` contains result column `schema` and `data`. Truncated results include `truncated: true` and `truncatedBy` (`maxRows` or `maxResultBytes`). A complete result can include `rowCount`.

SQL engines validate read-only queries. Python and JavaScript execute analysis code using their respective execution environments; see their engine pages for the boundaries and expected bindings.

## Inspect before executing

Separating translation from execution lets your application display or review the generated query before running it. Call `schema()` for exact table and field names when writing a query yourself.
