Getting AI to write a SQL query or generate a chart is no longer the hard part. Real business questions bring a different set of challenges: data lives in separate systems, metrics follow different definitions, and conclusions need to stand up to scrutiny.

**AI-powered data analysis takes more than a stronger model. It needs trustworthy data context, reliable computation, and clear visualizations.**

That is what AVA 4.0 is designed to address. AVA is **<span style={{ color: '#2F4BDA', backgroundColor: '#FBF5CB' }}>an open-source data analysis and visualization framework for JavaScript applications and AI agents</span>**.

AVA 3.0 focused on automated insights and chart recommendations, using rules and statistical methods to help developers identify anomalies and trends and choose suitable charts. Version 4.0 extends that foundation to AI agents, connecting data access, analysis execution, and visualization. An agent can interpret a question using the relevant business definitions, ask AVA to query and compute the data, and present the results in a chart.

## Start with a business question

**“<u><span style={{ color: '#117CEE' }}>Net sales</span></u> <u><span style={{ color: '#D22D8D' }}>are down</span></u>. <u><span style={{ color: '#601BDE' }}>Should we increase ad spend</span></u>?”**

The question asks both what is happening and what to do next. Answering it means first agreeing on what net sales includes, which periods to compare, and how to attribute refunds. Then you need to find where the decline comes from and assess whether the available data supports a recommendation to spend more on advertising.

## Establish shared business definitions

Reliable analysis depends on business definitions that people and agents can reuse: how metrics are calculated, which time periods records belong to, and how datasets relate to one another. Clear definitions provide a common basis for channel breakdowns, product analysis, and comparisons over time.

AVA defines a unified **<span style={{ color: '#2F4BDA' }}>DataModel</span>** that supplies standardized context for query generation:

| Context | Purpose | Typical contents |
| --- | --- | --- |
| **Schema** | Describe how the data is organized | Tables and views, field types, key constraints, and relationships |
| **Profile** | Describe the values actually present in the data | Row counts, null counts, cardinality, value ranges, and frequent values |
| **Semantic** | Map business concepts to the underlying data | Metric expressions, analysis dimensions, time definitions, and business relationships |

---

**Large language models are powerful, but translating natural language into accurate SQL is still difficult.** Using GLM-5.1, we compared performance with different levels of data context on the public DataBench analysis benchmark and the SQLite subset of the Spider2-Lite natural language-to-SQL (NL2SQL) benchmark.

![Benchmark accuracy with different levels of data context](https://intranetproxy.alipay.com/skylark/lark/0/2026/png/95056757/1793762051667-80cfafad-8d57-4177-8e77-5679a94a2678.png)

On the Spider2-Lite SQLite subset, accuracy was **25.9%** with only column names and sample data. Adding schema information and statistical profiles brought it to **33.3%**. Including business definitions raised it to **80.7%**. More context also increases token usage, of course.

**Answering business questions correctly requires a semantic layer, too.** The schema tells the model which fields exist; business definitions explain how to calculate metrics and relate the data. Capturing that knowledge lets people and agents work from the same definitions.

## Connect heterogeneous sources for complex analysis

Orders may live in a database, advertising data in files, and operational records in a Feishu spreadsheet. A sales review often requires filtering, joining, and aggregating large volumes of records across these sources.

AVA divides the work accordingly: **<span style={{ color: '#2F4BDA' }}>the model guides the investigation; code does the computation</span>.** The model breaks down the question, generates queries, and chooses the next step. Execution engines process the data and return results or errors so the model can compare findings and drill down. The full raw table does not need to go into the model's context.

AVA provides a unified interface to **<span style={{ color: '#ED740C' }}>more than 10 data sources</span>**, so applications can reuse analysis workflows across different sources.

![Supported data sources](https://intranetproxy.alipay.com/skylark/lark/0/2026/png/95056757/1793762072208-9f3740e4-b2a2-413e-b806-62cb0cf1bb87.png)

Once the data is connected, AVA can use different execution engines according to where the data lives and what the analysis requires:

+ **File analysis:** DuckDB 2.0 handles filtering, aggregation, and joins across tables, supporting file queries over roughly **600 million rows**.
+ **Database analysis:** ClickHouse and Supabase run computations in the database, using existing compute resources and returning the query results.
+ **Code-based computation:** Python/pandas handles complex transformations and numerical work, while JavaScript supports lightweight processing in a browser or Node.js.

![Execution engines](https://intranetproxy.alipay.com/skylark/lark/0/2026/png/95056757/1793761802228-0d083bd3-e047-4075-a9ab-7bc8e72f8e55.png)

## Use visualization to guide exploration

**An overall number can hide very different patterns underneath.** In the sales example above, comparing channels reveals differences behind the overall decline. In other business questions, looking at distributions or comparing groups can uncover patterns that aggregates miss.

## Make conclusions traceable and verifiable

Business analysis often involves confirming metric definitions, comparing data, and breaking down the results at several levels. Each judgment builds on earlier findings, so checking a conclusion means following that analytical path.

AVA gives the agent the executed query, result data, and execution status for each step, **making the evidence behind multi-step analysis traceable and helping pinpoint steps that need further investigation.**

---

> For example, net sales from organic search fell by CNY 877,200. You can follow the business definitions, executed query, returned data, and chart to check each assumption: Were refunds deducted? Were consignment sales counted as commission only? Did the query follow the agreed definitions? Were the display units consistent? Verifying the conclusion becomes a matter of checking specific steps in the analysis.

![Verifying business definitions, queries, data, and charts](https://intranetproxy.alipay.com/skylark/lark/0/2026/png/95056757/1793761446924-5a089d3b-9fbb-475a-ac94-24cb699a748b.png)

From verifying a sales change to investigating its causes, each result becomes evidence for the next judgment. A reasoning graph lays out that progression, helping users understand how a conclusion was reached and return to the steps that support it.

![An interactive reasoning graph of the analysis](https://intranetproxy.alipay.com/skylark/lark/0/2026/gif/95056757/1793698571700-11ee05a6-b55e-410f-814d-fe921c0b0664.gif)

**When you can inspect the process, you know where to make corrections.** If a business definition is wrong, revise it. If a query is wrong, adjust the calculation. If the evidence is insufficient, keep investigating. Trustworthy analysis comes from making each step open to verification and correction.

## Build faster with reusable analysis tools

Building a data analysis agent means handling data access, understanding schemas, executing queries, and generating charts. AVA packages these common capabilities as composable tools, <u>reducing repetitive development so you can focus on business definitions, analytical questions, and the product experience</u>.

**Already using an AI agent?** Install the AVA Skill with **<span style={{ color: '#ED740C' }}>one command</span>** to let it analyze data with AVA:

```bash
npx skills add antvis/AVA
```

Then start a new agent session and ask a question:

> Use the AVA Skill to analyze `./sales.csv` ([download the sample file](https://github.com/antvis/AVA/raw/refs/heads/ai/__tests__/datasets/sales.csv)): compare sales in January and February 2025 and identify which products contributed most to the decline.

AVA handles the queries and computations, leaving the agent to interpret the question and organize the analysis.

**Building your own application or agent?** Follow the [SDK quickstart](https://ava.antv.vision/documentation/quickstart/) to combine data access, analysis, and chart generation as needed. You can build a minimal data agent with **<span style={{ color: '#ED740C' }}>53 lines of core code</span>**. Or use the [CLI](https://ava.antv.vision/documentation/reference/cli/) to run analyses from a terminal or script after **<span style={{ color: '#ED740C' }}>two setup steps</span>**: installation and model configuration.
