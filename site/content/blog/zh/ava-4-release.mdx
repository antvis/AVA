## 统一业务口径，建立分析共识

可靠的数据分析，需要一套人和 Agent 都能复用的业务定义：指标怎么算、时间如何归属、数据如何关联。定义明确，渠道拆解、商品分析和跨期比较才有共同依据。

AVA 定义了统一的 **<font style={{ color: '#2F4BDA' }}>数据模型（DataModel）</font>**，为查询生成提供标准化的上下文：

| 上下文 | 职责 | 典型内容 |
| --- | --- | --- |
| **结构元数据（Schema）** | 描述数据的组织结构 | 表与视图、字段类型、键约束及关联关系 |
| **统计画像（Profile）** | 描述数据的实际取值特征 | 行数、空值数、基数、取值范围与高频值 |
| **业务语义（Semantic）** | 定义业务概念与数据的映射 | 指标表达式、分析维度、时间口径与业务关联 |

---

**大模型很强，但把自然语言准确转成 SQL，仍然是难题。** 我们使用 GLM-5.1，在公开数据分析基准 DataBench 和自然语言转 SQL（NL2SQL）基准 Spider2-Lite 的 SQLite 子集上，比较了模型获得不同数据背景时的表现。

![](https://intranetproxy.alipay.com/skylark/lark/0/2026/png/95056757/1793762051667-80cfafad-8d57-4177-8e77-5679a94a2678.png)

在 Spider2-Lite SQLite 子集中，仅提供表头和数据样例，正确率为 **25.9%**；补充数据结构和统计画像后为 **33.3%**；进一步加入业务定义后为 **80.7%**。当然，更多背景信息也会增加模型的 Token 用量。

**要让模型算对业务问题，还需要语义层。** 数据结构告诉模型有哪些字段，业务定义则告诉它指标怎么算、数据如何关联。把这些知识沉淀下来，人和 Agent 才能复用同一套分析口径。

## 连接多源异构数据，支撑复杂分析

订单在数据库里，广告数据在文件里，经营记录在飞书表格里。一次销售复盘，往往需要串联多个数据源，对大量明细进行筛选、关联和汇总。

面对这些任务，AVA 的分工是：**<font style={{ color: '#2F4BDA' }}>模型组织探索，程序承担计算</font>。** 模型负责拆解问题、生成查询和选择下一步；执行引擎处理数据并返回结果或错误，供模型继续比较和下钻，无需将整张原始表放进模型上下文。

AVA 通过统一接口接入 **<font style={{ color: '#ED740C' }}>10+ 种数据源</font>**，让应用在不同数据来源之间复用分析流程。

{/* 这是一张图片，ocr 内容为：母 飞书多维表格 文本 PARQUET JSON 腾讯文档 CSV EXCEL MYSQL CLICKHOUSE SQLITE MYSQL MONGODB SQL SERVER POSTGRESQL SUPABASE 持续扩展 */}

![](https://intranetproxy.alipay.com/skylark/lark/0/2026/png/95056757/1793762072208-9f3740e4-b2a2-413e-b806-62cb0cf1bb87.png)

接入数据后，AVA 可以根据数据所在位置和分析需求，使用不同的执行引擎完成计算：

+ **文件分析**：使用 DuckDB 2.0 完成筛选、聚合与多表关联，能支撑约 **6 亿行** 数据上的文件查询。
+ **数据库分析**：ClickHouse、Supabase 在数据库侧完成计算，利用已有算力返回查询结果。
+ **代码计算**：Python/pandas 承接复杂变换与数值计算，JavaScript 支持浏览器或 Node.js 中的轻量处理。

## 以可视化驱动探索，深化数据洞察

**整体数字背后，往往藏着不同的变化。** 在开头的销售分析中，渠道对比帮助我们看到整体下降背后的差异；在其他业务问题中，观察分布、比较群体，也可能带来新的发现。

以下两个案例基于模拟经营数据，展示计算与可视化如何共同回答业务问题：

| 业务问题 | 分析思路 | 可视化结果 |
| --- | --- | --- |
| **客单价没变，促销还按原来的方案做吗？** | 两期各 2,000 笔订单，客单价均约 800 元，但 600 元以下订单占比从 10.4% 升至 55.5%，高价订单也在增加。金额分布图（核密度估计，KDE）呈现了这种变化，为分层评估促销方案提供线索。 | ![](https://mdn.alipayobjects.com/huamei_aphk1k/afts/img/A*WI7kTb0m5CwAAAAAQTAAAAgAegfkAQ/original) |
| **120 家门店，都用同一套运营目标吗？** | 根据月订单量和客单价，识别走量型、均衡型和高客单型门店，为分组制定目标、分配资源提供依据。分析使用标准化和 KMeans 聚类。 | ![](https://mdn.alipayobjects.com/huamei_aphk1k/afts/img/A*uxkHQL9Hn30AAAAAQQAAAAgAegfkAQ/original) |

## 让结论有据可查，构建可信分析

一次业务分析，往往要经过指标确认、数据比较和逐层拆解。后一步判断建立在前一步结果之上，结论是否可靠，需要沿着这条分析路径核验。

AVA 将每一步分析的执行查询、结果数据与执行状态提供给 Agent，**让多步分析的依据可追溯，存在疑问的环节可定位。**

---

> 例如，自然搜索渠道净销售额下降了 87.72 万元。沿着业务定义、执行查询、返回数据和图表，可以逐项核对：退款是否扣除，代销商品是否只计佣金，查询是否遵循口径，展示单位是否一致。对结论的检查，由此落到具体的分析环节。

## 降低构建门槛，加速业务落地

构建数据分析 Agent，需要处理数据接入、结构理解、查询执行和图表生成。AVA 将这些通用能力封装为可组合的工具，<u>减少重复开发，让开发者把更多精力放在业务口径、分析问题和产品体验上</u>。

**已经有 AI Agent？** 用 **<font style={{ color: '#ED740C' }}> 1 条命令 </font>** 安装 AVA Skill，就可以让它使用 AVA 分析数据：

```bash
npx skills add antvis/AVA
```

然后开启一个新的 Agent 会话，提出你的问题：

:::color1

> 使用 AVA Skill 分析 `./sales.csv`（[下载示例文件](https://github.com/antvis/AVA/raw/refs/heads/ai/__tests__/datasets/sales.csv)）：比较 2025 年 1 月和 2 月的销售额，找出对销售额下降贡献最大的商品。

:::

这样，就可以把数据查询和计算交给 AVA，让 Agent 专注于理解问题、组织分析。

**正在构建自己的应用或 Agent？** 通过 [SDK 快速开始](https://ava.antv.vision/documentation/quickstart/) 按需组合数据接入、分析和制图能力，**<font style={{ color: '#ED740C' }}>53 行核心代码 </font>** 即可构建最小 Data Agent；也可以使用 [CLI](https://ava.antv.vision/documentation/reference/cli/)，完成安装和模型配置 **<font style={{ color: '#ED740C' }}>2 步 </font>** 后，在终端或脚本中开展分析。
