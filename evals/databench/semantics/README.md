# DataBench 手工语义配置

当前覆盖 full benchmark 的全部 79 个 suite（001–079）；`080_Books` 沿用数据加载器的排除设置。首次补齐时保留 001/002/003，004–079 按各自的 full Parquet、题目和参考标答人工选取字段、定义口径。后续失败题复核对部分配置继续作了口径修订。

配置由 `ava-workflow --strategy semantic` 按 `<suite>.yaml` 加载，使用 DuckDB、单个 `data` 表，无需新增模型生成流程。参考标答用于辨认业务含义、统计粒度和输出定义，不将答案、题号分支或预计算结果写入配置。因此这是参考标答参与设计的语义配置，不能作为仅凭 schema 的盲测基线。

## YAML 元素定义

- `dimensions`：分组、筛选使用的属性，例如记录 ID、类别、日期、数值类别编码。
- `measures`：行级可聚合的量，例如年龄、数量、金额或单条记录上的派生计算。
- `metrics`：预定义聚合或派生指标，例如 SUM、AVG、COUNT、众数及聚合比率。
- `description`：元素业务含义；`column` 指定物理列，`expr` 指定物理 SQL 表达式，`{TABLE}` 由编译器替换为表别名。

格式迁移时，79 份 YAML 共含 648 个维度、363 个行级度量、428 个指标。原 JSON 中的聚合 `measures` 全部迁为 `metrics`；行级量从原 dimensions 中按业务含义人工选取，保留原名称、说明、类型、物理列和表达式。文本、ID、日期和类别编码不因可表示为数字就自动转为度量；没有可聚合量的模型允许 `measures: []`。

SMQ 的 `metrics` 是查询目标列表，可选择维度、行级度量或聚合指标。维度和度量使用 `model__element`；唯一指标支持裸名称，旧的限定名称继续可用。仅选择行级目标且不指定 `group_by` 时保留重复记录，不隐式求和；显式 `group_by` 在无聚合时返回 DISTINCT。存在聚合时，选中的行级表达式参与分组。行级筛选进入 WHERE，聚合指标筛选进入 HAVING。

现有配置与限定指标引用继续可用。整体流程重构后的显式配置条件为 `file-v3`、SMQ 协议为 `smq-v4`（ToolLoopAgent 原生工具调用）。历史 `file-v2` 快照及成绩保持不变；新版本需要独立运行记录，不能把重构或旧版失败题合并成绩当成新版本准确率。

迁移验证：79/79 配置在 full DuckDB 数据上执行通过，600 个查询的编译结果与迁移前逐字一致；48 项语义/策略单测及 3 项评测加载器测试通过，CJS/ESM 构建和改动文件 lint 通过。原 JSON、分类清单及核验结果归档于 `evals/ava-workflow/.runs/semantic-yaml-migration-20261019/`。加载器测试可在构建后使用 Node 24 执行：`node --test evals/ava-workflow/semantic.test.cjs`。本次未调用外部模型重测。

## 设计口径

- 先明确一行代表什么，再区分记录数、去重实体数、求和、均值和单条记录极值。
- 只保留有用的业务字段和必要派生字段；优先复用现有列，不扩展通用框架。
- 保留 NULL、零、负数和原始异常值；缺失不能默认为否或零，题目明确排除时再过滤。
- 标明单位、比例尺度、类别编码、日期含义及同名指标区别。关键说明放在维度或度量的 description，供元素检索使用。
- Top-N 记录保留实体标识和重复值；“前 N 条再去重”与“前 N 个不同值”分别处理。
- 多选列表按成员统计时展开列表，空列表不计作一个成员。文本格式的列表和字典只做必要解析。

## 已知限制

- 部分题目要求原始前几行或依赖未声明的并列排序，而对应数据没有行号；本配置不补造源顺序。
- 无唯一 ID 的表中，维度查询的 DISTINCT 可能折叠重复记录。配置说明保留记录粒度，但具体查询仍需正确处理计数和重复值。
- `033_Employee` 没有教育字段，`074_Lift` 没有性别字段；不能根据标答补出教育值或从姓名推断性别。
- `006_London` 的 price 全列为 NULL；不能从其他字段恢复实际价格。
- 有些参考标答与数据或题意不一致。例如 `076_NBA` 的“篮板后保持原球队球权”应对应进攻篮板，但其中一个比例标答对应防守篮板占比；配置仍区分 OREB 与 DREB，不颠倒字段以迎合答案。
- `078_Fires` 使用数据中已变换的 area 和已提供的日历标签，按 benchmark 的存储值口径查询，不假定能恢复原始物理量。

## 本轮校验（2026-10-19）

使用 Node 24 和本地 full Parquet，未调用外部模型：

- 配置文件与 benchmark 的 79 个 suite 一一对应。
- 79/79 通过 SemanticRegistry 注册、物理字段存在性检查、SMQ 明细及聚合编译、DuckDB 执行。
- 所有派生维度在全量数据上求值；度量在全量数据上聚合，并检查维度与度量组合查询。

这些检查证明配置可加载、查询可执行及所检查的计算正确，不代表 1,789 道题已经通过 GLM 端到端评测。004–079 的模型正确率尚未测量。

## 首轮全量后的失败题修订

首轮 GLM-5.1 full 评测为 1,429/1,789（79.88%），342 道答案不匹配、18 道执行失败。随后人工复核这些题的 SQL、轨迹与 full 数据，调整 48 份配置中的 91 个元素：记录粒度、实际类别拼写、缺失值处理、列表成员、金额精度等。通用提示词补充 DISTINCT 与记录粒度的区别、列表展开和单列输出规则；未加入题号或答案分支。79 份配置执行校验及 37 项语义测试通过。

本轮还发现原 Parquet 的部分列 min/max 元数据错误：`053_Patents.type` 的元数据范围仅为 utility，而全扫描包含 design；过滤下推会错误跳过行。`041_Airline.airline` 也有同类问题。失败题重试使用保存于运行目录的无损重写副本，逐表核对 schema、记录值、重复次数和源行顺序相同，原文件保留。此运行条件与首轮存在差异，成绩变化不能全部归因于语义调整。

重试仅覆盖原失败的 360 个 ID，合并时保留原已通过 1,429 条记录。合并 CSV 是两轮结果，不是新版条件下独立的全量评测，不能据此确认新版无回归。基线、修订清单、数据核验、每轮 manifest 和逐题轨迹见 `evals/ava-workflow/.runs/semantic-retry-20261019-132316/`。
