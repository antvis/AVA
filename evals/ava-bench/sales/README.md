# Sales：销售业务分析验收集

用一套小型、合成的订单与退款数据，验证业务口径、分析方法和数据更新后的重算。规则是本验收集的明确约定，不代表通用财务准则或实际业务口径。

包含两张表、三个完整快照、20 项问题与标答。当前只维护评测材料，不包含执行或评分脚本，尚未接入 `evals/cli.js` 的 Workflow / Agent 评测入口。

## 文件与使用

- `datasets/baseline/`、`late-order/`、`late-refund/`：完整的 `orders.csv` 和 `refunds.csv`，纳入 Git，不需要下载。
- `context.json`：公共元数据、业务上下文、快照路径与时间，不包含题目和标答。
- `questions.csv`：20 条题目及标答，列为 `id,category,context,snapshots,question,answer,answer_description`。`snapshots` 是 JSON 数组，保留运行顺序和重复快照；`answer` 是直接保存事实的 JSON 对象，不再包裹 `facts`。`answer_description` 是可读的标答说明，保留原 `must_include` / `must_not_claim` 的全部内容，分别标记为“必须说明”和“不得断言或采用”。两个答案列仅供评测端使用。题目和标答只在 CSV 中维护。

未来接入执行器时，两张表需要同时加载到同一查询环境，并建立 `refunds.order_id → orders.order_id` 的关联。不能连续调用两次 AVA `source()` 来叠加表，当前接口会替换原数据源。每个版本整体替换上一版本，不能把三个完整快照追加在一起。

## 输入隔离

执行单题时，只向模型提供该题问题、指定快照的两张表、字段说明和公共元数据。`context=business` 时额外提供 `business_context`；B08 的 `context=schema_only` 必须省略它。不得提供其他题目、未来快照、标答或本 README 的答案部分。

题目和标答放在同一 CSV 中便于维护；执行器必须选择输入字段，不能将整个 CSV 或包含 `answer`、`answer_description` 的完整题目对象发送给模型。再根据该行的 `context` 和 `snapshots` 从 `context.json` 选择适用的上下文与数据。

B08 的 `answer` 数字是“明确并列两种口径”路径的参考。**只提出恰当的澄清问题同样通过，不要求同时给数字**；若直接给一个数字而不声明口径则不通过。

## 表结构

CSV 使用 UTF-8。金额为人民币整数分；时间为 UTC ISO 8601。空时间字段表示不适用，不是零时间。

| 表 | 字段 | 含义 |
| --- | --- | --- |
| orders | order_id | 唯一订单 ID，一行一个订单 |
| orders | user_id | 用户 ID，可跨订单重复 |
| orders | created_at / paid_at | 创建时间 / 支付时间；未支付、取消订单的 paid_at 为空 |
| orders | region | 订单所属地区：华东、华西、华北 |
| orders | status | paid、unpaid、cancelled；退款不改变 paid 状态 |
| orders | amount_cents | 订单金额，仅 paid 订单计入支付金额 |
| refunds | refund_id / order_id | 唯一退款 ID / 关联订单 ID；一单可有多条退款 |
| refunds | status | succeeded 或 pending |
| refunds | succeeded_at | 退款成功时间，pending 时为空 |
| refunds | amount_cents | 本次退款金额，pending 时不扣减 |

目录按场景命名：`baseline` 是初始基准，`late-order` 补入延迟到达的历史订单，`late-refund` 在此基础上补入历史订单退款。三者都是完整快照，均包含 1 月至 3 月 15 日的订单数据。

## 固定业务口径

1. 业务时区为 `Asia/Shanghai`。订单按支付时间归属周期，区间左闭右开；取消、未支付订单不计入。
2. 支付金额是有效订单金额之和。净销售额扣除截至快照 `as_of` 已成功的退款，退款回溯到原订单支付月份与地区。
3. 多次退款先按订单汇总，避免一对多关联重复计算订单金额。订单数、用户数分别按对应 ID 去重；净客单价的分母为支付订单数。
4. 退款金额率＝归属该支付周期的成功退款金额 / 支付金额。比率差转成百分点时乘以 100。
5. 变化率＝(本期－基期) / 基期；基期为零返回 null 并解释。地区贡献率＝地区差额 / 总差额，可超过 100% 或为负；总体差额为零时返回 null。
6. 参考日期固定为 `2026-03-16`，订单数据覆盖至北京时间 3 月 15 日结束。3 月同期比较区间为 `[03-01, 03-16)`，对比 `[02-01, 02-16)`，不能声称完整月结论。
7. 覆盖范围内没有有效订单的地区视为零；未来未覆盖日期不能视为零。退款按快照时间取已知成功记录，即使在订单覆盖日期之后成功，也可以修正历史订单月份。

## 验收规则与边界

- 金额、计数精确匹配。机器标答金额以分表示；`growth_rate` 等比率采用小数，如 0.1 表示 10%。`change_percentage_points` 直接表示百分点数。
- 比率及百分点的绝对误差允许 `1e-10`。展示文本允许按两位小数四舍五入；未来执行器评分先统一单位，不能对整段文字剥离非数字字符。
- `answer` 是结构化事实，`answer_description` 中的“必须说明” / “不得断言或采用”是语义规则，不要求逐字一致。数组中的地区按名称匹配，图表时间序列按月份排序。事实与说明的验收由评测器或人工完成。
- B08 可仅澄清，参考数字并非强制输出。A08 的“不支持因果结论”是人工制定的证据边界。
- R01 的重复值和 R04 的图表点是预先定义的标答；后续需在同一保存定义下真实运行，采集每轮结果，验证运行关联、图文一致性和旧结果是否正确替换。展示样式与文字措辞不必相同。
- 这套数据覆盖所列 20 项，不包含同比、异常检测、缺失值、总体变化为零、刷新失败等额外场景；不能据此宣称完整分析能力已通过验收。
