1b:T1ca9,# Architecture & source map

Understand how the public API connects to the implementation.

## Public entry points

[`index.ts`](https://github.com/antvis/AVA/blob/ai/src/index.ts) registers all Node.js engines and exports `AVA` plus public types. [`index.browser.ts`](https://github.com/antvis/AVA/blob/ai/src/index.browser.ts) registers only JavaScript. [`ava.ts`](https://github.com/antvis/AVA/blob/ai/src/ava.ts) coordinates source state, data model, events, and engine lifecycle.

## Method to module

| Public method                         | Responsibility / implementation                                                                                                                                                                                                                                             |
| ------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `source()` / `schema()` / `dispose()` | Source state and engine lifecycle in [`ava.ts`](https://github.com/antvis/AVA/blob/ai/src/ava.ts)                                                                                                                                                                           |
| `profile()`                           | Per-engine profiling; shared metric contracts in [`util/profile.ts`](https://github.com/antvis/AVA/blob/ai/src/util/profile.ts)                                                                                                                                             |
| `analyze()`                           | Dispatch to [`analysis/direct.ts`](https://github.com/antvis/AVA/blob/ai/src/analysis/direct.ts), [`analysis/loop.ts`](https://github.com/antvis/AVA/blob/ai/src/analysis/loop.ts), or [`analysis/subset.ts`](https://github.com/antvis/AVA/blob/ai/src/analysis/subset.ts) |
| `translate()` / `query()`             | Engine `getDSL()` / `execute()`                                                                                                                                                                                                                                             |
| `suggest()`                           | [`suggest/index.ts`](https://github.com/antvis/AVA/blob/ai/src/suggest/index.ts)                                                                                                                                                                                            |
| `recommend()`                         | [`visualization/advisor.ts`](https://github.com/antvis/AVA/blob/ai/src/visualization/advisor.ts) and config generation                                                                                                                                                      |
| `viz()`                               | HTML wrapping in [`visualization/generator.ts`](https://github.com/antvis/AVA/blob/ai/src/visualization/generator.ts)                                                                                                                                                       |
| `visualize()`                         | Compose `recommend()` and `viz()`                                                                                                                                                                                                                                           |

## Context and state

An AVA instance owns one active engine and its schema/profile cache. `source()` loads data; `schema()` discovers structure on first use. `profile()` computes and retains fresh observations; the data model is assembled from cached metadata when needed. Reloading or disposal clears both caches.

Engines retain data and connections. Their `load()` returns no metadata; `schema()` discovers it, `profile(schema, options?)` computes observations, and `getDSL(query, dataModel)` consumes AVA's data model. Shared validators live in `util/schema.ts` and `util/profile.ts`.

Analysis strategies share a runtime containing the engine, model configuration, data model, and event emitter. Query result limits are normalized through shared utilities.

## Documentation organization

Each topic is a separate MDX file under `site/content/docs/`, grouped into `data/`, `analysis/`, `visualization/`, `engines/`, and `reference/`. This mirrors the public capabilities without exposing every internal helper as a separate user-facing page.
