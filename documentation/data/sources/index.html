Working with data

Data sources

Load inline data, local or remote files, and database tables.

CSVInline & fileJSONInline & fileParquetColumnar fileExcelWorkbook sheetsTextLLM extractionSQLiteLocal databaseMySQLDatabasePostgreSQLDatabaseMongoDBDocument databaseSupabaseCloud databaseClickHouseAnalytics databaseCustom extensionRegister an engine

Choose a data source above, then use its example and parameter table below. CSV and JSON each support inline content and files.

Connect a source

Create an AVA instance, then call source(config) with the data location and reader settings:

ParameterTypeRequiredMeaning
typeSourceTypeYescsv, csv-file, json, json-file, parquet, excel, text, sqlite, mysql, postgresql, mongodb, supabase, clickhouse, or feishu-bitable.
optionsSource-specific objectYesUse the matching table below. Field names are relative to options.

source() returns no value and prepares the data for execution. Schema discovery is deferred until schema() or another operation needs it. Calling source() again replaces the current source and clears its cached metadata. Use schema() to inspect table and field names, and call await ava.dispose() when finished.

The examples use Node.js. Supabase and ClickHouse include their required constructor settings alongside the source call. For frontend applications, see browser usage.

Excel

Read an .xlsx workbook from a local path or HTTP(S) URL. Each selected worksheet becomes a separate table named after the sheet. Call schema() to inspect the resulting tables and columns.

Source options

FieldTypeRequiredMeaning / default
pathstringYesLocal file path or HTTP(S) URL
headersRecord<string, string>NoHTTP headers for remote sources, such as Authorization
sheetsExcelSheetOptions[]NoSheets to load and their individual read settings; omitted loads all sheets with header: true

Sheet selection and reader options

Each entry in sheets contains a required sheet and optional ExcelReadOptions fields. Set these fields directly on the sheet entry, as shown above.

FieldTypeDefaultMeaning
sheetstringRequiredExact worksheet name; also used as the table name
rangestringInferred by the engineInclusive A1 rectangle, such as B3:F100
headerbooleantrueUse the first row of the selected range as column names; false keeps it as data
all_varcharbooleanfalseDuckDB only: read all cells as VARCHAR
ignore_errorsbooleanfalseDuckDB only: replace cells that fail type conversion with NULL
stop_at_emptybooleanfalse with range, otherwise trueDuckDB only: stop reading at the first empty row
empty_as_varcharbooleanfalseDuckDB only: infer empty cells as VARCHAR instead of DOUBLE

A supplied sheets list must be non-empty, and every name must exist in the workbook and appear only once. Ranges must be valid, bounded A1 rectangles. Invalid selections and unsupported fields are rejected.

Engine behavior

Both engines support sheet, range, and header. The Python engine rejects the four DuckDB-only options in the table above.

DuckDB reader options follow read_xlsx, except that AVA defaults header to true instead of inferring it. For example, to preserve mixed cell types as text and continue past empty rows:

DuckDB rejects workbooks containing sheet names with literal XML entity text, such as Sales &amp; Tax, because its Excel extension can confuse them with another sheet. Rename those sheets or use the Python engine. Ordinary ampersands, quotes, and Unicode names are supported.

Feishu Bitable

Use type: 'feishu-bitable' with the DuckDB engine in Node.js. Rows are exposed as one read-only view named data.

Provide url, or both appToken and tableId, along with appId and appSecret. The CLI also reads credentials from AVA_FEISHU_APP_ID / AVA_FEISHU_APP_SECRET or ~/.ava/feishu.json.

Both /base/ and wiki-hosted /wiki/ links are supported. Wiki links require wiki read access and wiki space membership so the app can resolve the Bitable. The view query parameter is ignored. Complex cells (people, attachments, links, formulas, locations, and groups) are flattened to comma-separated text.
