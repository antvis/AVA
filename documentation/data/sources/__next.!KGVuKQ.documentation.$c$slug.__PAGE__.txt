<Heading as="h2" id="connect-a-source">Connect data sources</Heading>

Pass one configuration object or a nonempty array of configurations to `ava.source()`. Each configuration describes where the data comes from and how to read it.

| Field | Type | Required | Meaning |
| --- | --- | --- | --- |
| `type` | `string` | Yes | Source type. The sections below describe the supported values. |
| `options` | Source-specific object | Yes | Reader or connection settings for that source type. |
| `name` | `string` | No | Source name used to qualify table names in a batch of multiple sources. |

Each call releases the current dataset and clears its metadata before loading. A failed load leaves the instance without an active dataset. After loading, use `ava.schema()` to inspect the table structure. Call `await ava.dispose()` when finished.

### Connect one source

Pass one configuration object. This example uses the default engine in the Node.js SDK.

```typescript
import { AVA } from '@antv/ava';

const ava = new AVA({
  llm: { model: 'YOUR_MODEL', apiKey: process.env.OPENAI_API_KEY },
});

await ava.source({
  type: 'json',
  options: { data: [{ city: 'Hangzhou', revenue: 120 }] },
});
```

### Connect multiple sources

AVA can analyze data from [CSV](#csv), [JSON](#json), [Parquet](#parquet), [Excel](#excel), [text](#text), [SQLite](#sqlite), [MySQL](#mysql), [PostgreSQL](#postgresql), [MongoDB](#mongodb), [Feishu Bitable](#feishu-bitable), and [GitHub](#github) together.

In the Node.js SDK, use `ava.source([...])` to connect multiple data sources in one call.

- Use a unique **`name`** for each source.
- With two or more sources, `ava.schema()` lists tables as **`sourceName.tableName`**. A CSV source exposes one table named `data`, and an Excel workbook exposes one table per selected sheet.
- **A single source** keeps its original table names whether passed as an object or a one-entry array.

<Callout>
  Use the default engine to analyze multiple sources together. In the CLI, run `ava source A B C` to load sources into one session. See [CLI source inputs](/documentation/reference/cli/#source-inputs-and-engines).
</Callout>

```typescript
await ava.source([
  { name: 'orders', type: 'csv-file', options: { path: './sales.csv' } },
  { name: 'workbook', type: 'excel', options: { path: './sales.xlsx' } },
]);

const schema = await ava.schema();
```

## CSV

### Inline CSV

Pass the CSV content as a string with `type: 'csv'`.

```typescript
await ava.source({
  type: 'csv',
  options: { csv: 'city,revenue\nHangzhou,120\nShanghai,200\nBeijing,160' },
});
```

| Field     | Type             | Required | Meaning / default                          |
| --------- | ---------------- | -------- | ------------------------------------------ |
| `csv`     | `string`         | Yes      | Raw CSV content string                     |
| `options` | `CSVReadOptions` | No       | [CSV reader options](#csv-reader-options). |

### CSV files

Use `type: 'csv-file'` with a local path or HTTP(S) URL. For a protected URL, supply request headers in `options.headers`.

For remote CSV, JSON, Parquet, and Excel files, a nonempty `headers` object restricts redirects to the same origin (scheme, hostname, and effective port), with a limit of 20 redirects. This applies to both DuckDB and Python, including custom Python executors. Cross-origin redirects fail before the next request, even when the only header is `Accept` or the redirect upgrades HTTP to HTTPS. Downloads without headers, or with `headers: {}`, retain the underlying downloader's redirect behavior. Use the final trusted URL when a protected download requires a different origin.

```typescript
await ava.source({
  type: 'csv-file',
  options: {
    path: 'https://example.com/sales.csv',
    headers: { Authorization: 'Bearer YOUR_TOKEN' },
    options: { header: true, delim: ';' },
  },
});
```

| Field     | Type                     | Required | Meaning / default                                    |
| --------- | ------------------------ | -------- | ---------------------------------------------------- |
| `path`    | `string`                 | Yes      | Local file path or http(s) URL                       |
| `headers` | `Record<string, string>` | No       | HTTP headers for remote sources (e.g. Authorization) |
| `options` | `CSVReadOptions`         | No       | [CSV reader options](#csv-reader-options).           |

AVA forwards supplied values to `read_csv`; omitted values use DuckDB reader defaults or detection. | Field                  | Type                                 | Required | Meaning / default                                                                               |
| ---------------------- | ------------------------------------ | -------- | ----------------------------------------------------------------------------------------------- |

| `columns`              | `Record<string, string>`             | No       | Column names → types struct, e.g. &#123; col1: 'INTEGER' &#125;. Disables schema auto-detection |
| `types`                | `string[] \| Record<string, string>` | No       | Column types, by position (list) or by name (struct)                                            |
| `all_varchar`          | `boolean`                            | No       | Skip type detection and read all columns as VARCHAR. Default false                              |
| `normalize_names`      | `boolean`                            | No       | Remove non-alphanumeric chars from column names; prefix reserved keywords with \_               |
| `force_not_null`       | `string[]`                           | No       | Columns that must not be matched against the NULL string                                        |
| `delim`                | `string`                             | No       | Field delimiter (up to 4 bytes). Default ','                                                    |
| `quote`                | `string`                             | No       | Quote character. Default '"'                                                                    |
| `escape`               | `string`                             | No       | Escape character for the quote within quoted values. Default '"'                                |
| `comment`              | `string`                             | No       | Character used to initiate comments                                                             |
| `new_line`             | `string`                             | No       | New line character(s): '\r' \| '\n' \| '\r\n'                                                   |
| `auto_detect`          | `boolean`                            | No       | Auto detect CSV parameters. Default true                                                        |
| `auto_type_candidates` | `string[]`                           | No       | Types the sniffer considers when detecting column types, e.g. ['BIGINT', 'DATE']                |
| `dateformat`           | `string`                             | No       | Date format used when parsing dates                                                             |
| `timestampformat`      | `string`                             | No       | Timestamp format used when parsing timestamps                                                   |
| `decimal_separator`    | `string`                             | No       | Decimal separator for numbers. Default '.'                                                      |
| `thousands`            | `string`                             | No       | Thousands separator (single char, different from decimal_separator)                             |
| `nullstr`              | `string \| string[]`                 | No       | String(s) that represent a NULL value                                                           |
| `allow_quoted_nulls`   | `boolean`                            | No       | Allow the conversion of quoted values to NULL. Default true                                     |

## JSON

### Inline JSON

Pass an array of objects with `type: 'json'`.

```typescript
await ava.source({
  type: 'json',
  options: { data: [{ city: 'Hangzhou', revenue: 120 }] },
});
```

| Field  | Type    | Required | Meaning / default      |
| ------ | ------- | -------- | ---------------------- |
| `data` | `any[]` | Yes      | Array of rows to load. |
| `options` | `JSONReadOptions` | No | DuckDB reader parameters below. |

### JSON files

Use `type: 'json-file'` with a local path or HTTP(S) URL.

```typescript
await ava.source({
  type: 'json-file',
  options: {
    path: './sales.json',
    options: { columns: { city: 'VARCHAR', revenue: 'DOUBLE' }, sample_size: -1 },
  },
});
```

| Field     | Type                     | Required | Meaning / default                                    |
| --------- | ------------------------ | -------- | ---------------------------------------------------- |
| `path`    | `string`                 | Yes      | Local file path or http(s) URL                       |
| `headers` | `Record<string, string>` | No       | HTTP headers for remote sources (e.g. Authorization) |
| `options` | `JSONReadOptions` | No | DuckDB reader parameters below. |

### JSON reader options

Both JSON source types accept `options.options` when using the DuckDB engine. All fields are optional.
The complete [DuckDB JSON reader parameter list](https://duckdb.org/docs/current/data/json/loading_json) is exposed as `JSONReadOptions`:

| Parameter | Type | Default | Meaning |
| --- | --- | --- | --- |
| `auto_detect` | `boolean` | `true` | Infer schema |
| `columns` | `Record<string, string>` | Unset | Names → DuckDB types; selects columns |
| `compression` | `'auto_detect' \| 'none' \| 'gzip' \| 'zstd'` | `'auto_detect'` | Codec |
| `dateformat` | `string` | `'iso'` | Date pattern |
| `field_appearance_threshold` | `number` | `0.1` | Sparse-object MAP threshold |
| `filename` | `boolean` | `false` | Include filename in `SELECT *` |
| `format` | `'auto' \| 'unstructured' \| 'newline_delimited' \| 'array'` | `'auto'` | Input layout for `read_json` |
| `hive_partitioning` | `boolean` | Auto-detected | Path partitions |
| `ignore_errors` | `boolean` | `false` | Skip errors; NDJSON only |
| `map_inference_threshold` | `number` | `200` | STRUCT subfield limit; `-1` disables MAP inference |
| `maximum_depth` | `number` | `-1` | Inference depth; `-1` unlimited |
| `maximum_object_size` | `number` | `16777216` | Bytes per object |
| `maximum_sample_files` | `number` | `32` | Files sampled |
| `records` | `'auto' \| 'true' \| 'false'` | `'auto'` | Unpack objects |
| `sample_size` | `number` | `20480` | Objects sampled; `-1` scans all |
| `timestampformat` | `string` | `'iso'` | Timestamp pattern |
| `union_by_name` | `boolean` | `false` | Merge schemas |

Inline data is serialized as an uncompressed JSON array; choose compatible reader options.
Remote files are downloaded to temporary paths, so set `compression` explicitly for compressed URLs.

## Excel

Read an `.xlsx` workbook from a local path or HTTP(S) URL. Each selected worksheet becomes a separate table named after the sheet. Call `schema()` to inspect the resulting tables and columns.

```typescript
await ava.source({
  type: 'excel',
  options: {
    path: './sales.xlsx',
    sheets: [
      { sheet: 'Sales', range: 'A3:F100', header: true },
      { sheet: 'Costs', range: 'B2:C50', header: false },
    ],
  },
});
```

### Source options

| Field | Type | Required | Meaning / default |
| --- | --- | --- | --- |
| `path` | `string` | Yes | Local file path or HTTP(S) URL |
| `headers` | `Record<string, string>` | No | HTTP headers for remote sources, such as Authorization |
| `sheets` | `ExcelSheetOptions[]` | No | Sheets to load and their individual read settings; omitted loads all sheets with `header: true` |

### Sheet selection and reader options

Each entry in `sheets` contains a required `sheet` and optional `ExcelReadOptions` fields. Set these fields directly on the sheet entry, as shown above.

| Field | Type | Default | Meaning |
| --- | --- | --- | --- |
| `sheet` | `string` | Required | Exact worksheet name; also used as the table name |
| `range` | `string` | Inferred by the engine | Inclusive A1 rectangle, such as `B3:F100` |
| `header` | `boolean` | `true` | Use the first row of the selected range as column names; `false` keeps it as data |
| `all_varchar` | `boolean` | `false` | DuckDB only: read all cells as VARCHAR |
| `ignore_errors` | `boolean` | `false` | DuckDB only: replace cells that fail type conversion with NULL |
| `stop_at_empty` | `boolean` | `false` with `range`, otherwise `true` | DuckDB only: stop reading at the first empty row |
| `empty_as_varchar` | `boolean` | `false` | DuckDB only: infer empty cells as VARCHAR instead of DOUBLE |

A supplied `sheets` list must be non-empty, and every name must exist in the workbook and appear only once. Ranges must be valid, bounded A1 rectangles. Invalid selections and unsupported fields are rejected.

### Engine behavior

Both engines support `sheet`, `range`, and `header`. The Python engine rejects the four DuckDB-only options in the table above.

DuckDB reader options follow [`read_xlsx`](https://duckdb.org/docs/current/core_extensions/excel#reading-xlsx-files), except that AVA defaults `header` to `true` instead of inferring it. For example, to preserve mixed cell types as text and continue past empty rows:

```typescript
await ava.source({
  type: 'excel',
  options: {
    path: './sales.xlsx',
    sheets: [{ sheet: 'Sales', all_varchar: true, stop_at_empty: false }],
  },
});
```

DuckDB rejects workbooks containing sheet names with literal XML entity text, such as `Sales &amp; Tax`, because its Excel extension can confuse them with another sheet. Rename those sheets or use the Python engine. Ordinary ampersands, quotes, and Unicode names are supported.

## SSH options

To reach MySQL or PostgreSQL through a bastion, add `ssh` under `options`. The database `host` and `port` must be reachable from the bastion.

First, obtain the SSH server's host key fingerprint from its administrator over a trusted channel. The administrator can read it on the server with `ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub -E sha256`. Use the `SHA256:...` value in your connection configuration:

```typescript
await ava.source({
  type: 'mysql', // PostgreSQL: 'postgresql'
  options: {
    host: 'db.internal',
    database: 'analytics',
    user: 'reader',
    password: process.env.DB_PASSWORD,
    ssh: {
      host: 'bastion.example.com',
      user: 'ssh-user',
      password: process.env.SSH_PASSWORD,
      hostKeyFingerprint: 'SHA256:REPLACE_WITH_SERVER_FINGERPRINT',
    },
  },
});
```

Fields inside `options.ssh`:

| Field | Type | Required | Meaning / default |
| --- | --- | --- | --- |
| `host` | `string` | Yes | SSH server hostname. |
| `port` | `number` | No | Default: `22`. |
| `user` | `string` | Yes | SSH login user. |
| `password` | `string` | No | SSH login password. |
| `hostKeyFingerprint` | `string` | Yes | Expected host key fingerprint, `SHA256:<base64>` without padding. |

## Feishu Bitable

Use `type: 'feishu-bitable'` with the DuckDB engine in Node.js. Rows are exposed as one read-only view named `data`.

For first-time setup, follow the illustrated [Lark Base setup guide](/documentation/data/feishu-bitable/) to create an app, grant access, bind credentials, and verify the data with CLI / SDK examples and troubleshooting.

```typescript
await ava.source({
  type: 'feishu-bitable',
  options: {
    url: 'https://my.feishu.cn/base/APP_TOKEN?table=TABLE_ID',
    appId: process.env.AVA_FEISHU_APP_ID,
    appSecret: process.env.AVA_FEISHU_APP_SECRET,
  },
});
```

Complex cells (people, attachments, links, locations, and groups) become text, usually with multiple values separated by commas; formula and lookup fields are converted according to their returned value types.

## Snowflake

Use the `snowflake` source and engine in Node.js to analyze tables and views on your Snowflake warehouse. Each source discovers one schema and returns query results to AVA.

### Permissions

Prepare a warehouse, database and schema. The connection role needs `USAGE` on each, plus `SELECT` on the tables and views to analyze. For a shared database such as `SNOWFLAKE_SAMPLE_DATA`, grant `IMPORTED PRIVILEGES`. Keep procedure, external function and integration privileges out of this role.

The following example creates a read-only service user with [key-pair authentication](https://docs.snowflake.com/en/developer-guide/node-js/nodejs-driver-authenticate). Replace `<public-key-body>` with your public key; the connection below uses the corresponding private key file.

```sql
CREATE ROLE AVA_READER;
GRANT USAGE ON WAREHOUSE AVA_WH TO ROLE AVA_READER;
GRANT USAGE ON DATABASE ANALYTICS TO ROLE AVA_READER;
GRANT USAGE ON SCHEMA ANALYTICS.SALES TO ROLE AVA_READER;
GRANT SELECT ON ALL TABLES IN SCHEMA ANALYTICS.SALES TO ROLE AVA_READER;
GRANT SELECT ON ALL VIEWS IN SCHEMA ANALYTICS.SALES TO ROLE AVA_READER;
CREATE USER AVA_READER_SVC TYPE = SERVICE DEFAULT_ROLE = AVA_READER DEFAULT_WAREHOUSE = AVA_WH
  RSA_PUBLIC_KEY = '<public-key-body>';
GRANT ROLE AVA_READER TO USER AVA_READER_SVC;
```

Queries consume warehouse credits. Enable auto-suspend and a resource monitor to control usage.

### Connection fields

Set both the engine and source type to `snowflake`, then provide your account, credentials and warehouse:

```typescript
const ava = new AVA({
  llm: { model: 'YOUR_MODEL', apiKey: process.env.OPENAI_API_KEY },
  engine: { type: 'snowflake' },
});
await ava.source({
  type: 'snowflake',
  options: {
    account: 'myorg-myaccount',
    username: 'AVA_READER_SVC',
    authenticator: 'SNOWFLAKE_JWT',
    privateKeyPath: '/secure/ava_reader_key.p8',
    warehouse: 'AVA_WH',
    role: 'AVA_READER',
    database: 'ANALYTICS',
    schema: 'SALES',
  },
});
```

| Field                       | Type     | Required             | Meaning / default                                                                                                                                                   |
| --------------------------- | -------- | -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `account`                   | `string` | Yes                  | Account identifier, `orgname-accountname`.                                                                                                                          |
| `database`                  | `string` | Yes                  | Database to discover and query.                                                                                                                                     |
| `schema`                    | `string` | No                   | Schema whose tables and views are exposed; also the session's default schema. Default `PUBLIC`.                                                                     |
| `warehouse`                 | `string` | No                   | Warehouse that runs the queries; defaults to the user's `DEFAULT_WAREHOUSE`.                                                                                        |
| `role`                      | `string` | No                   | Role for the session; defaults to the user's `DEFAULT_ROLE`. Use a read-only role.                                                                                  |
| `username`                  | `string` | For most methods     | Login name.                                                                                                                                                         |
| `authenticator`             | `string` | No                   | Driver authentication method, such as `SNOWFLAKE_JWT`, `PROGRAMMATIC_ACCESS_TOKEN` or `OAUTH`. Default `SNOWFLAKE` (password).                                       |
| `privateKey`                | `string` | For `SNOWFLAKE_JWT`  | PEM private key; or set `privateKeyPath` to read it from a file, and `privateKeyPass` for an encrypted key.                                                         |
| `token`                     | `string` | For token methods    | Programmatic access token or OAuth access token; or set `tokenFilePath`.                                                                                            |
| `password`                  | `string` | For `SNOWFLAKE`      | Password. Snowflake is phasing out single-factor password sign-in, so prefer key pairs or tokens.                                                                   |
| `queryTimeoutMs`            | `number` | No                   | Limit for each statement in milliseconds. Snowflake enforces it (statement and queue timeouts) and the client cancels the statement when it expires. Default `30000`. |

Other [driver connection options](https://docs.snowflake.com/en/developer-guide/node-js/nodejs-driver-options), including `host`, proxy settings and `queryTag` (default `AVA`), are forwarded. AVA manages result formats and session cleanup. Loading fails if the database, schema or warehouse is missing or unauthorized.

### Query execution

Use `schema()` to inspect authorized tables, views and declared keys, `query()` to execute Snowflake SQL, or `analyze()` to ask a question. `analyze()` sends the question and dataset metadata to your configured model to generate SQL. By default, it also sends query results to the model for a summary; pass `{ includeSummary: false }` to skip that summary.

```typescript
try {
  const result = await ava.analyze('What is the total order amount for each month?');
  console.log(result.data, result.text);
} finally {
  await ava.dispose();
}
```

- Write a single read-only `SELECT` (`WITH` is allowed), quoting table and column names exactly as listed by `schema()`. Procedures, `SYSTEM$` functions, and dynamic function calls such as `IDENTIFIER(name)(...)` are rejected.
- Use `maxRows` and `maxResultBytes` to limit the number of rows and size of returned results.
- `NUMBER` values become JavaScript numbers when conversion preserves their digits; larger or more precise values stay decimal strings. Float `NaN` and infinities stay strings. Dates use `YYYY-MM-DD`; times and timestamps have nine fractional digits, with an offset for time-zone types. `VARIANT`, `OBJECT` and `ARRAY` are parsed JSON; `BINARY` is hexadecimal text.

## GitHub
