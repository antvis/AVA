Inspect your data

Let AVA discover the structure, inspect statistics when useful, then add business meaning.

Start with this small order table. The Define data semantics guide uses these same six rows.

AVA discovers structure and computes statistics. You add business meaning: what counts as revenue and how refunds should be handled.

Schema: the structure AVA discovers

For this table, the discovered model is:

This is your automatically discovered structural starting point. You do not write it by hand. Types and source qualifiers depend on the engine; database sources may also expose declared keys and relationships. notNull: false means there is no declared non-null constraint, not that a null was found.

AVA also discovers schema when analysis needs it, so calling schema() yourself is optional.

The maximum of 500 includes a cancelled order. Profiling describes stored values; the rules for what counts as revenue belong in semantic definitions.

Profiling is optional, requires engine support, and can scan the data. It does not call an LLM. See metric options for other statistics.

Semantic: the meaning you add

The table contains paid, refunded, pending, and cancelled orders. Which should count as revenue? That is a rule you supply:

description explains the business rule. The sales cube names its source (data), revenue calculation (measures), and region grouping (dimensions). The discovered columns remain available without repeating them; the cube guides query generation and does not create a database object.

Continue to Define data semantics for the full example and corresponding SQL result: East 150 USD, West 60 USD. Field formats, manual overrides, and update rules are in the API reference.
