Analysis & visualization

Analyze data

Turn a natural language question into a bounded data result and summary.

Use analyze() to answer questions about loaded data, suggest() to discover useful questions, and translate() / query() when you want to generate and execute queries separately.

The examples assume ava is configured and a source has been loaded with source(). For installation and a complete setup example, see Installation & Quickstart.

The examples use the same small sales dataset as Quickstart:

regionrevenue
East120
West90
East80

Analyze a question

Pass a natural-language question to analyze():

analyze() obtains schema on demand and combines it with the available profile and supplied semantic definitions to generate a query, execute it, and summarize the answer. Semantic definitions explain business rules such as which orders count as revenue. It returns data and text; it does not generate a chart.

Read the result

An illustrative response for the question above looks like this. Summary wording, generated queries, and column aliases can vary with the model.

FieldTypeWhat it tells you
querystringThe original question.
textstringThe generated summary; empty when includeSummary is false.
schemaQueryColumn[]Returned columns, each with name: string and optional type: string.
dataRecord<string, unknown>[]Rows to display, export, or visualize.
rowCountnumber, optionalRow count when the result is complete. Do not treat it as the size of the input dataset.
sqlstring, optionalThe executed query. This name is also used for Python or JavaScript code with those engines.
markdownstring, optionalMarkdown content, when supplied.
truncatedtrue, optionalMore data existed than the result limits allowed.
truncatedBy'maxRows' or 'maxResultBytes', optionalThe limit that stopped the result.

Use schema to inspect returned column names instead of assuming the model will always choose total_revenue.

Configure an analysis

analyze(query: string, config?: AnalysisConfig) accepts the following inputs:

ParameterTypeRequiredDefault / behavior
querystringYesNatural-language question.
configAnalysisConfigNo{}.
config.includeSummarybooleanNotrue; set to false to skip summarization.
config.maxRowsnumberNo200; bounds returned rows.
config.maxResultBytesnumberNo1048576 (1 MiB); bounds serialized result data.
config.strategyAnalysisStrategyConfigNoDirect analysis; see strategy options.

maxRows is rounded down and clamped to 1–1000000; values outside the safe integer range after rounding use the default. maxResultBytes is rounded down and clamped to at least 1; non-finite values use the default. Both limits also apply to query() below. They bound the returned data, not the query's total processing time or memory use.

Suggest questions

Use suggest() for analysis ideas. Computing a profile first is optional: it adds statistics to the context without an LLM call.

ParameterTypeRequiredDefault / behavior
countnumberNo3; requested number of suggestions.

suggest() requires a loaded source and calls the configured model. It uses the latest profile when available, otherwise the schema.

For the sales dataset, the returned array might look like this:

These are illustrative suggestions, not fixed output. In your interface, use the fields as follows:

FieldTypeExample use
querystringShow as a selectable question and pass it to analyze().
scorenumberPrioritize suggestions. Values are clamped to 0–1 and sorted highest first; this is a usefulness score, not confidence in an answer.
reasonstringExplain why the question may be useful, for example as text beneath the question.

At most count suggestions are returned; the array can be empty. The model is prompted to use the dataset's language for both the question and reason.

Analysis strategies

analyze() uses direct analysis by default. Choose a strategy per call when your question needs a different approach:

StrategyUse it for
directA focused question answered by generating and executing a query.
loopQuestions that benefit from intermediate exploration.
subsetSelecting relevant statistics from a large profile before analysis.

See Analysis strategies for examples, retry controls, step limits, and subset requirements.

Translate and execute separately

Use translate() to inspect generated code before deciding to execute it with query():

MethodParameterTypeRequired / default
translate(query)querystringRequired natural-language question.
query(dsl, options?)dslstringRequired executable statement in the current engine's language.
query(dsl, options?)optionsExecutionOptionsOptional; defaults below.
query(dsl, options?)options.maxRowsnumberOptional; 200. Same bounds as analyze().
query(dsl, options?)options.maxResultBytesnumberOptional; 1048576. Same bounds as analyze().

Both methods require a loaded source. translate() uses the model, schema, and available profile, then returns a string. query() executes the supplied statement without model-based translation, summarization, or automatic correction.

The default Node.js setup produces SQL. Other engines use their own SQL dialect, Python, or JavaScript. SQL engines validate read-only queries; execution restrictions for Python and JavaScript depend on their environments.

query() returns the same schema, data, and optional truncation metadata described above, without the analysis query, text, or sql fields.

Errors and cleanup

Calls reject on errors such as a missing source, a model request failure, an unparseable suggestion response, or failed execution after the available retries. Do not interpret an error as an empty answer.
