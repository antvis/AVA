AVA 4.0 发布

AVA 4.0 面向 AI Agent，打通数据接入、分析执行与可视化，让分析结论有据可查。

yvonneyx版本发布2026.11.04

今天，让 AI 写一段 SQL、生成一张图表，已经不难。但面对真实的业务问题，挑战才刚刚开始：数据分散在不同系统，指标有各自的计算口径，分析结论需要经得起核对。

AI 数据分析需要的不只是一个更强的模型，还需要可信的数据上下文、可靠的计算和清晰的可视化。

这正是 AVA 4.0 想要解决的问题。AVA 是 一套面向 JavaScript 应用和 AI Agent 的开源数据分析与可视化框架。

3.0 基于规则与统计方法，聚焦数据洞察与图表推荐，帮助开发者发现数据中的异常、趋势，并选择合适的图表。4.0 进一步面向 AI Agent，打通数据接入、分析执行与可视化表达。Agent 可以结合业务口径理解问题，调用 AVA 查询和计算数据，再用图表呈现结果。

💡 先看看 AVA 4.0 的几个核心亮点：

🔗 多源异构数据，统一接入🔍 可信分析，结论有据可查🕵️ 自动发现洞察
🔮 数据安全，运行环境自主可控📊 智能可视化，自动推荐合适图表🔗 快速接入现有 AI Agent

如果你熟悉 PandasAI，可以把 AVA 理解为 JavaScript 生态中面向 AI Agent 的数据分析与可视化框架。

从一个业务问题开始

一次经营复盘，往往从一个问题开始：

“净销售额下降，要不要加大投放？”

这个问题同时包含对现状的分析和对下一步行动的判断。回答它，需要先确定净销售额的含义、比较周期和退款归属，再检查下降来自哪里，以及现有数据能否支持增加投放的建议。

我们用同一份模拟零售数据，连续提出三个问题：

  1. 净销售额下降后的投放判断

  1. 核对净销售额有没有算对

  1. 看清两个部门怎么算销售额

这个案例的背后，是 AVA 提供的数据理解、分析执行和可视化能力。开发者可以通过 Skill、CLI 或 SDK 将这些能力接入 Agent，让它围绕业务问题开展分析。

统一业务口径，建立分析共识

可靠的数据分析，需要一套人和 Agent 都能复用的业务定义：指标怎么算、时间如何归属、数据如何关联。定义明确，渠道拆解、商品分析和跨期比较才有共同依据。

AVA 定义了统一的 数据模型（DataModel），为查询生成提供标准化的上下文：

上下文职责典型内容
结构元数据（Schema）描述数据的组织结构表与视图、字段类型、键约束及关联关系
统计画像（Profile）描述数据的实际取值特征行数、空值数、基数、取值范围与高频值
业务语义（Semantic）定义业务概念与数据的映射指标表达式、分析维度、时间口径与业务关联

大模型很强，但把自然语言准确转成 SQL，仍然是难题。 我们使用 GLM-5.1，在公开数据分析基准 DataBench 和自然语言转 SQL（NL2SQL）基准 Spider2-Lite 的 SQLite 子集上，比较了模型获得不同数据背景时的表现。

在 Spider2-Lite SQLite 子集中，仅提供表头和数据样例，正确率为 25.9%；补充数据结构和统计画像后为 33.3%；进一步加入业务定义后为 80.7%。当然，更多背景信息也会增加模型的 Token 用量。

要让模型算对业务问题，还需要语义层。 数据结构告诉模型有哪些字段，业务定义则告诉它指标怎么算、数据如何关联。把这些知识沉淀下来，人和 Agent 才能复用同一套分析口径。

连接多源异构数据，支撑复杂分析

订单在数据库里，广告数据在文件里，经营记录在飞书表格里。一次销售复盘，往往需要串联多个数据源，对大量明细进行筛选、关联和汇总。

面对这些任务，AVA 的分工是：模型组织探索，程序承担计算。 模型负责拆解问题、生成查询和选择下一步；执行引擎处理数据并返回结果或错误，供模型继续比较和下钻，无需将整张原始表放进模型上下文。

AVA 通过统一接口接入 10+ 种数据源，让应用在不同数据来源之间复用分析流程。

接入数据后，AVA 可以根据数据所在位置和分析需求，使用不同的执行引擎完成计算：

  • 文件分析：使用 DuckDB 2.0 完成筛选、聚合与多表关联，能支撑约 6 亿行 数据上的文件查询。
  • 数据库分析：ClickHouse、Supabase 在数据库侧完成计算，利用已有算力返回查询结果。
  • 代码计算：Python/pandas 承接复杂变换与数值计算，JavaScript 支持浏览器或 Node.js 中的轻量处理。

以可视化驱动探索，深化数据洞察

整体数字背后，往往藏着不同的变化。 在开头的销售分析中，渠道对比帮助我们看到整体下降背后的差异；在其他业务问题中，观察分布、比较群体，也可能带来新的发现。

以下两个案例基于模拟经营数据，展示计算与可视化如何共同回答业务问题：

业务问题分析思路可视化结果
客单价没变，促销还按原来的方案做吗？两期各 2,000 笔订单，客单价均约 800 元，但 600 元以下订单占比从 10.4% 升至 55.5%，高价订单也在增加。金额分布图（核密度估计，KDE）呈现了这种变化，为分层评估促销方案提供线索。
120 家门店，都用同一套运营目标吗？根据月订单量和客单价，识别走量型、均衡型和高客单型门店，为分组制定目标、分配资源提供依据。分析使用标准化和 KMeans 聚类。

选对图表，才能看清问题。 AVA 将不同图表的适用场景、数据要求和使用边界组织为启发式知识，结合分析意图与数据特征，引导模型推荐合适的可视化形式。

推荐结果由 AntV GPT-Vis 渲染，支持 26+ 可视化类型。

让结论有据可查，构建可信分析

一次业务分析，往往要经过指标确认、数据比较和逐层拆解。后一步判断建立在前一步结果之上，结论是否可靠，需要沿着这条分析路径核验。

AVA 将每一步分析的执行查询、结果数据与执行状态提供给 Agent，让多步分析的依据可追溯，存在疑问的环节可定位。

例如，自然搜索渠道净销售额下降了 87.72 万元。沿着业务定义、执行查询、返回数据和图表，可以逐项核对：退款是否扣除，代销商品是否只计佣金，查询是否遵循口径，展示单位是否一致。对结论的检查，由此落到具体的分析环节。

从核实销售变化到寻找下降原因，每一步结果又会成为后续判断的依据。推导图谱展开了这条逐步深入的路径，让使用者既能看清结论如何形成，也能回到支撑它的具体步骤。

让分析过程可检查，修正才有落点。 口径有误，可以修正定义；查询有误，可以调整计算；证据不足，则需要继续验证。这让可信分析落实到每一步可核验、可纠偏的过程之中。
