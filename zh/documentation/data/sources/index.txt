<Heading as="h2" id="connect-a-source">接入数据源</Heading>

创建 AVA 实例，然后调用 `source(config)`，传入数据位置与读取设置：

```typescript
import { AVA } from '@antv/ava';

const ava = new AVA({
  llm: { model: 'YOUR_MODEL', apiKey: process.env.OPENAI_API_KEY },
});

await ava.source({
  type: 'json',
  options: {
    data: [
      { city: 'Hangzhou', revenue: 120 },
      { city: 'Shanghai', revenue: 200 },
      { city: 'Beijing', revenue: 160 },
    ],
  },
});

const schema = await ava.schema();
```

| 参数 | 类型 | 必填 | 含义 |
| --------- | ---------------------- | -------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| `type` | `SourceType` | 是 | 支持 `csv`、`csv-file`、`json`、`json-file`、`parquet`、`excel`、`text`、`sqlite`、`mysql`、`postgresql`、`mongodb`、`supabase`、`clickhouse`、`snowflake`、`feishu-bitable`。 |
| `options` | 数据源对应的对象 | 是 | 使用下方对应的数据源参数表，字段名均相对于 `options`。 |

`source()` 没有返回值，负责为执行准备数据。结构发现会推迟到 `schema()` 或其他操作需要时进行。再次调用 `source()` 会替换当前数据源并清空元数据缓存。使用 `schema()` 查看表名与字段名，结束后调用 `await ava.dispose()`。

示例均在 Node.js 中运行。Supabase、ClickHouse 和 Snowflake 的示例同时给出了必需的构造函数配置。前端应用请参考[浏览器用法](/documentation/browser/)。

| --------- | ---------------- | -------- | ------------------------------------------ |

| `options` | `CSVReadOptions` | 否 | [CSV 读取选项](#csv-reader-options)。 |

<Heading as="h3" id="csv-files">读取 CSV 文件</Heading>

设置 `type: 'csv-file'`，传入本地路径或 HTTP(S) URL。URL 需要鉴权时，可在 `options.headers` 中提供请求头。

远程 CSV、JSON、Parquet 和 Excel 文件只要传入非空 `headers`，就仅允许同来源跳转（协议、主机名和有效端口均相同），最多跳转 20 次。此规则同时适用于 DuckDB 和 Python，包括自定义 Python 执行器。跨来源跳转会在发送下一次请求前报错，即使请求头只有 `Accept`，或跳转是从 HTTP 升级到 HTTPS。未传请求头或传入 `headers: {}` 时，保留底层下载器原有的跳转行为。需要从其他来源下载受保护文件时，请直接使用已确认可信的最终地址。

```typescript
await ava.source({
  type: 'csv-file',
  options: {
    path: 'https://example.com/sales.csv',
    headers: { Authorization: 'Bearer YOUR_TOKEN' },
    options: { header: true, delim: ';' },
  },
});
```

| 字段 | 类型 | 必填 | 含义与默认值 |
| --------- | ------------------------ | -------- | ---------------------------------------------------- |
| `path` | `string` | 是 | 本地文件路径或 HTTP(S) URL。 |
| `headers` | `Record<string, string>` | 否 | 远程数据源的 HTTP 请求头，例如 Authorization。 |
| `options` | `CSVReadOptions` | 否 | [CSV 读取选项](#csv-reader-options)。 |

<Heading as="h2" id="excel">Excel</Heading>

从本地路径或 HTTP(S) URL 读取 `.xlsx` 工作簿。每个被选中的工作表会成为一张独立的表，以工作表名称命名。调用 `schema()` 可查看生成的表与列。

```typescript
await ava.source({
  type: 'excel',
  options: {
    path: './sales.xlsx',
    sheets: [
      { sheet: 'Sales', range: 'A3:F100', header: true },
      { sheet: 'Costs', range: 'B2:C50', header: false },
    ],
  },
});
```

<Heading as="h3" id="source-options">数据源选项</Heading>

| 字段 | 类型 | 必填 | 含义与默认值 |
| --- | --- | --- | --- |
| `path` | `string` | 是 | 本地文件路径或 HTTP(S) URL。 |
| `headers` | `Record<string, string>` | 否 | 远程数据源的 HTTP 请求头，例如 Authorization。 |
| `sheets` | `ExcelSheetOptions[]` | 否 | 要加载的工作表及各自的读取设置；省略时加载全部工作表，并使用 `header: true`。 |

<Heading as="h3" id="sheet-selection-and-reader-options">工作表选择与读取选项</Heading>

`sheets` 中的每一项都包含必填的 `sheet`，以及可选的 `ExcelReadOptions` 字段。读取选项直接放在工作表项上，写法如上例所示。

| 字段 | 类型 | 默认值 | 含义 |
| --- | --- | --- | --- |
| `sheet` | `string` | 必填 | 精确的工作表名称，同时作为表名。 |
| `range` | `string` | 由引擎推断 | 包含首尾边界的 A1 矩形范围，例如 `B3:F100`。 |
| `header` | `boolean` | `true` | 将所选范围的第一行作为列名；设为 false 时保留为数据。 |
| `all_varchar` | `boolean` | `false` | 仅 DuckDB：将所有单元格读为 VARCHAR。 |
| `ignore_errors` | `boolean` | `false` | 仅 DuckDB：类型转换失败的单元格改为 NULL。 |
| `stop_at_empty` | `boolean` | 有 `range` 时为 `false`，否则为 `true` | 仅 DuckDB：遇到第一个空行时停止读取。 |
| `empty_as_varchar` | `boolean` | `false` | 仅 DuckDB：将空单元格推断为 VARCHAR，而非 DOUBLE。 |

提供 `sheets` 时，列表不能为空；每个工作表名必须存在且只能出现一次。范围必须是有效、有界的 A1 矩形。无效选择及不受支持的字段会被拒绝。

<Heading as="h3" id="engine-behavior">引擎行为</Heading>

两种引擎都支持 `sheet`、`range` 和 `header`。Python 引擎会拒绝上表中的四个 DuckDB 专用选项。

DuckDB 的读取选项遵循 [`read_xlsx`](https://duckdb.org/docs/current/core_extensions/excel#reading-xlsx-files)，但 AVA 默认 `header` 为 true，而非自动推断。例如，要将混合类型单元格保留为文本，并继续读取空行之后的数据：

```typescript
await ava.source({
  type: 'excel',
  options: {
    path: './sales.xlsx',
    sheets: [{ sheet: 'Sales', all_varchar: true, stop_at_empty: false }],
  },
});
```

DuckDB 会拒绝含有字面 XML 实体文本工作表名的工作簿，例如 `Sales &amp; Tax`，因为 Excel 扩展可能将它与另一张表混淆。请重命名这些工作表，或使用 Python 引擎。普通的 &、引号和 Unicode 名称均受支持。

<Heading as="h2" id="ssh-options">SSH 选项</Heading>

通过跳板机访问 MySQL 或 PostgreSQL 时，在 `options` 中添加 `ssh`。数据库的 `host` 和 `port` 应填写跳板机能够访问的地址与端口。

先通过可信渠道向 SSH 服务器管理员获取主机密钥指纹。管理员可在服务器上运行 `ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub -E sha256`，将输出中的 `SHA256:...` 值填入连接配置：

```typescript
await ava.source({
  type: 'mysql', // PostgreSQL 使用 'postgresql'
  options: {
    host: 'db.internal',
    database: 'analytics',
    user: 'reader',
    password: process.env.DB_PASSWORD,
    ssh: {
      host: 'bastion.example.com',
      user: 'ssh-user',
      password: process.env.SSH_PASSWORD,
      hostKeyFingerprint: 'SHA256:REPLACE_WITH_SERVER_FINGERPRINT',
    },
  },
});
```

`options.ssh` 中的字段：

| 字段 | 类型 | 必填 | 含义与默认值 |
| --- | --- | --- | --- |
| `host` | `string` | 是 | SSH 服务器主机名。 |
| `port` | `number` | 否 | 默认 `22`。 |
| `user` | `string` | 是 | SSH 登录用户。 |
| `password` | `string` | 否 | SSH 登录密码。 |
| `hostKeyFingerprint` | `string` | 是 | 预期的主机密钥指纹，格式为 `SHA256:<base64>`，不带填充字符。 |

<Heading as="h2" id="feishu-bitable">飞书多维表格</Heading>

在 Node.js 的 DuckDB 引擎中使用 `type: 'feishu-bitable'`。记录会暴露为名为 `data` 的只读视图。

首次接入请按[飞书多维表格配置指南](/documentation/data/feishu-bitable/)完成应用创建、权限授权和凭证绑定，指南包含流程示意图、CLI / SDK 示例与常见问题。

```typescript
await ava.source({
  type: 'feishu-bitable',
  options: {
    url: 'https://my.feishu.cn/base/APP_TOKEN?table=TABLE_ID',
    appId: process.env.AVA_FEISHU_APP_ID,
    appSecret: process.env.AVA_FEISHU_APP_SECRET,
  },
});
```

提供 `url`，或同时提供 `appToken` 与 `tableId`，并设置 `appId`、`appSecret`。CLI 也会从 `AVA_FEISHU_APP_ID`、`AVA_FEISHU_APP_SECRET` 或 `~/.ava/feishu.json` 读取凭证。

支持 `/base/` 链接和知识库中的 `/wiki/` 链接。Wiki 链接要求应用具备知识库读取权限并加入相应知识空间，才能解析多维表格。URL 中的 `view` 参数会被忽略。人员、附件、链接、位置、群组等复杂单元格会转换为文本，多个值通常以逗号分隔；公式和查找引用字段按返回值类型转换。

<Heading as="h2" id="supabase">Supabase</Heading>

提供项目标识与 Supabase Management API 访问令牌；应用负责获取和刷新令牌。

```typescript
const ava = new AVA({
  llm: { model: 'YOUR_MODEL', apiKey: process.env.OPENAI_API_KEY },
  engine: { type: 'supabase' },
});
await ava.source({
  type: 'supabase',
  options: {
    projectRef: 'YOUR_PROJECT_REF',
    accessToken: process.env.SUPABASE_ACCESS_TOKEN!,
  },
});
```

| 字段 | 类型 | 必填 | 含义与默认值 |
| ------------- | -------- | -------- | --------------------------------------------------------------------------- |
| `accessToken` | `string` | 是 | Supabase Management API OAuth 流程返回的 OAuth 访问令牌。 |
| `projectRef` | `string` | 是 | 项目标识，可从 GET https://api.supabase.com/v1/projects 的结果中获取。 |

<Heading as="h2" id="clickhouse">ClickHouse</Heading>

提供服务端点和数据库。使用 `url` 或 `host`；同时存在时 `url` 优先。

```typescript
const ava = new AVA({
  llm: { model: 'YOUR_MODEL', apiKey: process.env.OPENAI_API_KEY },
  engine: { type: 'clickhouse' },
});
await ava.source({
  type: 'clickhouse',
  options: {
    url: 'http://localhost:8123',
    database: 'analytics',
    username: 'reader',
    password: process.env.CLICKHOUSE_PASSWORD,
  },
});
```

<Heading as="h3" id="connection-fields">连接字段</Heading>

| 字段 | 类型 | 必填 | 含义与默认值 |
| ---------- | -------- | --------------- | ------------------------------------------------------------------------- |
| `host` | `string` | `host` 或 `url` | 主机名或 host:port；没有协议时，AVA 自动补上 `http://`。 |
| `url` | `string` | `host` 或 `url` | 完整的服务 URL，优先于 `host`。 |
| `port` | `number` | 否 | 覆盖端点中的端口号。 |
| `database` | `string` | 是 | 要发现结构和执行查询的数据库。 |
| `username` | `string` | 否 | 客户端用户名，优先于 `user`；客户端默认值为 `default`。 |
| `user` | `string` | 否 | `username` 的别名。 |
| `password` | `string` | 否 | 客户端密码，默认空字符串。 |

虽然底层客户端默认可连接 localhost，AVA 仍要求显式提供端点。

<Heading as="h3" id="forwarded-client-fields">透传的客户端字段</Heading>

`ClickHouseSourceOptions` 也接受以下 `@clickhouse/client` 字段。下表基于已安装客户端的类型声明（1.23.1）；这些字段由该依赖定义，AVA 会在创建客户端时透传。

| 字段 | 类型 | 默认值与含义 |
| ------------------------------ | ----------------------------- | ---------------------------------------------------------------------------------------------------------- |
| `pathname` | `string` | 默认为空，用于指定额外的代理路径。 |
| `request_timeout` | `number` | 默认 30000 毫秒。 |
| `max_open_connections` | `number` | 每个主机默认最多 10 个 socket 连接。 |
| `compression` | 对象 | 请求和响应压缩，嵌套字段见下方。 |
| `access_token` | `string` | 默认未设置，用于 ClickHouse Cloud JWT；不可与用户名、密码同时使用。 |
| `application` | `string` | 默认为空，应用名称。 |
| `clickhouse_settings` | `ClickHouseSettings` | 默认为空，服务端设置映射。AVA 每次查询都会强制 `readonly: '1'`，覆盖冲突设置。 |
| `log` | 对象 | 客户端日志选项，见下方。 |
| `session_id` | `string` | 默认为空，不显式指定服务端会话。 |
| `role` | `string \| string[]` | 默认未设置，服务端角色。 |
| `http_headers` | `Record<string, string>` | 默认为空，额外的 HTTP 请求头。 |
| `additional_headers` | `Record<string, string>` | 已废弃的客户端别名，请使用 `http_headers`。 |
| `keep_alive` | 对象 | Socket 复用选项，见下方。 |
| `json` | `Partial<JSONHandling>` | 默认使用原生 `JSON.parse` / `JSON.stringify`；回调见下方。 |
| `tracer` | `ClickHouseTracer` | 默认未设置，客户端追踪实现。 |
| `use_multipart_params` | `boolean` | 默认 false，始终以 multipart 发送查询参数。 |
| `use_multipart_params_auto` | `boolean` | 默认 false，编码后的参数超过 4096 个字符时使用 multipart。 |
| `tls` | TLS 选项对象 | 默认未设置，证书字段见下方。 |
| `http_agent` | `http.Agent \| https.Agent` | 默认未设置。自定义 agent 会取代 `max_open_connections`、`tls` 和 `keep_alive`；这是实验性客户端 API。 |
| `set_basic_auth_header` | `boolean` | 默认 true，发送 Basic Authorization 请求头；实验性选项。 |
| `capture_enhanced_stack_trace` | `boolean` | 默认 false，记录扩展客户端调用栈；实验性选项。 |
| `max_response_headers_size` | `number` | 默认未设置，使用 Node.js 的响应头字节上限。 |
| `connection` | `Connection<Stream.Readable>` | 默认未设置，实验性的客户端后端连接；会覆盖默认 HTTP 传输及其选项。 |

透传字段全部可选。服务端设置是可扩展、与服务端版本有关的映射，并非 AVA 固定定义的字段清单；可用键由依赖的 `ClickHouseSettings` 类型和实际服务端共同决定。Tracer、agent、logger 与 connection 对象需要实现相应的客户端接口，并非普通的 AVA 配置对象。

<Heading as="h3" id="nested-client-options">嵌套客户端选项</Heading>

| 字段 | 类型 | 必填与默认值 |
| ------------------------------------------ | ------------------------------------------------ | --------------------------------------------------------------------------- |
| `compression.response` | `boolean \| { codec: 'gzip' \| 'zstd' \| 'br' }` | 可选，默认 false；true 表示使用 gzip。 |
| `compression.request` | `boolean \| RequestCompression` | 可选，默认 false；true 表示使用 gzip。 |
| `compression.request.codec` | `'gzip' \| 'zstd' \| 'br'` | 使用对象形式时必填。 |
| `compression.request.level` | `number` | gzip / zstd 可选，默认使用编解码器的级别。 |
| `compression.request.quality` | `number` | Brotli 可选，默认 4。 |
| `log.LoggerClass` | `new () => Logger` | 可选，默认使用客户端的 logger。 |
| `log.level` | `ClickHouseLogLevel` | 可选，默认 WARN；可选值为 TRACE、DEBUG、INFO、WARN、ERROR、OFF。 |
| `keep_alive.enabled` | `boolean` | 可选，默认 true。 |
| `keep_alive.idle_socket_ttl` | `number` | 可选，默认 2500 毫秒；0 表示禁用闲置 socket 管理。 |
| `keep_alive.eagerly_destroy_stale_sockets` | `boolean` | 可选，默认 false。 |
| `tls.ca_cert` | `Buffer` | 提供 `tls` 时必填。 |
| `tls.cert` | `Buffer` | 双向 TLS 时必填。 |
| `tls.key` | `Buffer` | 双向 TLS 时必填。 |
| `json.parse` | `<T>(input: string) => T` | 可选，用于解析 JSON 字符串。 |
| `json.stringify` | `<T>(input: T) => string` | 可选，用于序列化值。 |

此客户端的 Zstd 压缩需要 Node.js 22.15 或更高版本。响应压缩可能与引擎强制的服务端只读设置冲突；除非服务端允许，否则请保持关闭。

<Heading as="h2" id="snowflake">Snowflake</Heading>

在 Node.js 中使用 `snowflake` 数据源和引擎，分析 Snowflake 仓库中的表和视图。每个数据源对应一个 schema，查询结果返回 AVA。

<Heading as="h3" id="snowflake-permissions">权限</Heading>

准备好仓库、数据库和 schema。连接角色需要三者的 `USAGE` 权限，以及待分析表和视图的 `SELECT` 权限。`SNOWFLAKE_SAMPLE_DATA` 这类共享数据库需要授予 `IMPORTED PRIVILEGES`。请勿向该角色授予存储过程、外部函数或集成的使用权限。

以下示例创建使用[密钥对认证](https://docs.snowflake.com/en/developer-guide/node-js/nodejs-driver-authenticate)的只读服务用户。将 `<public-key-body>` 替换为公钥正文，下方连接配置使用对应的私钥文件。

```sql
CREATE ROLE AVA_READER;
GRANT USAGE ON WAREHOUSE AVA_WH TO ROLE AVA_READER;
GRANT USAGE ON DATABASE ANALYTICS TO ROLE AVA_READER;
GRANT USAGE ON SCHEMA ANALYTICS.SALES TO ROLE AVA_READER;
GRANT SELECT ON ALL TABLES IN SCHEMA ANALYTICS.SALES TO ROLE AVA_READER;
GRANT SELECT ON ALL VIEWS IN SCHEMA ANALYTICS.SALES TO ROLE AVA_READER;
CREATE USER AVA_READER_SVC TYPE = SERVICE DEFAULT_ROLE = AVA_READER DEFAULT_WAREHOUSE = AVA_WH
  RSA_PUBLIC_KEY = '<public-key-body>';
GRANT ROLE AVA_READER TO USER AVA_READER_SVC;
```

查询会消耗仓库 credits，请开启自动挂起并配置资源监控来控制用量。

<Heading as="h3" id="snowflake-connection-fields">连接字段</Heading>

将引擎和数据源类型均设为 `snowflake`，填入账号、凭证和仓库信息：

```typescript
const ava = new AVA({
  llm: { model: 'YOUR_MODEL', apiKey: process.env.OPENAI_API_KEY },
  engine: { type: 'snowflake' },
});
await ava.source({
  type: 'snowflake',
  options: {
    account: 'myorg-myaccount',
    username: 'AVA_READER_SVC',
    authenticator: 'SNOWFLAKE_JWT',
    privateKeyPath: '/secure/ava_reader_key.p8',
    warehouse: 'AVA_WH',
    role: 'AVA_READER',
    database: 'ANALYTICS',
    schema: 'SALES',
  },
});
```

| 字段 | 类型 | 必填 | 含义与默认值 |
| --------------- | -------- | -------------------- | ------------------------------------------------------------------------------------ |
| `account` | `string` | 是 | 账号标识，格式为 `orgname-accountname`。 |
| `database` | `string` | 是 | 要发现和查询的数据库。 |
| `schema` | `string` | 否 | 暴露其中表和视图的 schema，也是会话的默认 schema。默认 `PUBLIC`。 |
| `warehouse` | `string` | 否 | 执行查询的仓库，默认使用用户的 `DEFAULT_WAREHOUSE`。 |
| `role` | `string` | 否 | 会话使用的角色，默认使用用户的 `DEFAULT_ROLE`。请使用只读角色。 |
| `username` | `string` | 多数认证方式必填 | 登录名。 |
| `authenticator` | `string` | 否 | 驱动的认证方式，如 `SNOWFLAKE_JWT`、`PROGRAMMATIC_ACCESS_TOKEN` 或 `OAUTH`。默认 `SNOWFLAKE`（密码）。 |
| `privateKey` | `string` | `SNOWFLAKE_JWT` 时必填 | PEM 格式私钥；也可用 `privateKeyPath` 从文件读取，加密的私钥用 `privateKeyPass` 提供口令。 |
| `token` | `string` | 令牌类认证时必填 | Programmatic access token 或 OAuth 访问令牌；也可用 `tokenFilePath` 从文件读取。 |
| `password` | `string` | `SNOWFLAKE` 时必填 | 密码。Snowflake 正在逐步停用单因素密码登录，建议使用密钥对或令牌。 |
| `queryTimeoutMs` | `number` | 否 | 单条语句的时限（毫秒）。由 Snowflake 执行（语句超时和排队超时），到期时客户端也会取消语句。默认 `30000`。 |

其他[驱动连接选项](https://docs.snowflake.com/en/developer-guide/node-js/nodejs-driver-options)，如 `host`、代理设置和 `queryTag`（默认 `AVA`），会透传给驱动。结果格式和会话清理由 AVA 管理。数据库、schema 或仓库不存在或未授权时，加载会报错。

<Heading as="h3" id="snowflake-query-execution">查询执行</Heading>

用 `schema()` 查看已授权的表、视图和声明的键，用 `query()` 执行 Snowflake SQL，或用 `analyze()` 以自然语言提问。`analyze()` 会将问题和数据集元数据发送给配置的模型来生成 SQL；默认还会将查询结果发送给模型生成摘要，传入 `{ includeSummary: false }` 可跳过摘要。

```typescript
try {
  const result = await ava.analyze('每个月的订单总金额是多少？');
  console.log(result.data, result.text);
} finally {
  await ava.dispose();
}
```

- 使用单条只读 `SELECT`（支持 `WITH`），按 `schema()` 列出的名称为表和列加双引号。存储过程、`SYSTEM$` 函数，以及 `IDENTIFIER(name)(...)` 形式的动态函数调用会被拒绝。
- `maxRows` 和 `maxResultBytes` 分别限制返回结果的行数和大小。
- `NUMBER` 在转换不损失数字位数时转为 JavaScript 数字，更大或更精确的值保留为十进制字符串；浮点数的 `NaN` 和无穷大保留为字符串。日期使用 `YYYY-MM-DD`，时间和时间戳带九位小数，时区类型附带偏移量。`VARIANT`、`OBJECT` 和 `ARRAY` 是解析后的 JSON，`BINARY` 是十六进制文本。
