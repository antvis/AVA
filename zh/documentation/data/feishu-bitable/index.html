理解与接入数据

飞书多维表格配置

图文介绍应用创建、权限授权、凭证绑定和多维表格加载验证。

这篇指南带你创建飞书应用、授予数据访问权限，再把多维表格接入 AVA。完成后，可以通过 CLI 或 Node.js SDK 查询数据，也可以交给 Agent Skill继续分析和生成图表。

开始前准备

  • 一个允许创建企业自建应用的飞书账号，以及目标多维表格的管理权限；需要审批时，请联系企业管理员或表格所有者。
  • Node.js 22.13.0 或更高版本。CLI 当前支持 macOS / Linux，安装方式见命令行工具。
  • 目标数据表的浏览器地址，通常包含 /base/ 或 /wiki/。

AVA 使用应用身份读取数据，在 Node.js 的 DuckDB 引擎中将记录加载为名为 data 的只读视图。加载、查看结构和执行 SQL 不需要模型 API 密钥；使用 AVA 的自然语言分析与可视化功能时，再按模型配置设置模型。

以下使用飞书官方教程中的真实界面截图，点击图片可查看原图。截图中的应用名称仅为示例，请使用你自己的应用；界面布局可能随飞书版本更新。

1. 创建应用并获取凭证

  1. 打开飞书开放平台，进入开发者后台，创建 企业自建应用；已有应用也可以复用。
  2. 填写应用名称和描述，例如「AVA 数据分析」。
  3. 在应用的 凭证与基础信息 页面找到 App ID 和 App Secret，供后续绑定使用。

这里的 App ID 标识开放平台应用，App Secret 用来获取 tenant_access_token。它们与多维表格链接中的 App Token 是不同的值，不能互相替代。AVA 会自动获取访问令牌，无需手动复制令牌。

2. 开通权限并授权表格

开放平台：允许应用调用读取接口

在应用的 权限管理 中搜索多维表格，申请能够读取数据表、字段和记录的权限。以飞书当前接口文档列出的权限要求为准；下面列出了 AVA 实际会调用的读取接口，便于逐项核对。

接口用途何时需要
GET /open-apis/bitable/v1/apps/{app_token}/tables/{table_id}/fields读取字段名称和类型每次加载
GET /open-apis/bitable/v1/apps/{app_token}/tables/{table_id}/records读取记录每次加载
GET /open-apis/bitable/v1/apps/{app_token}/tables查找数据表链接没有 table 参数时
GET /open-apis/wiki/v2/spaces/get_node将知识库节点解析为多维表格使用 /wiki/ 链接时，额外申请知识库读取权限

参考飞书服务端 API 文档。申请后，在 版本管理与发布 中创建版本并发布；如果企业要求管理员审批，等待审批完成，确认权限已生效。

多维表格：允许应用访问目标文档

  1. 打开目标多维表格，在右上角的 更多 或文档应用入口中找到 添加文档应用；具体入口名称以当前飞书界面为准。
  2. 搜索并添加刚创建的应用，使其获得读取目标表格的权限。若入口不可用或找不到应用，让表格所有者检查文档权限与应用的发布状态、可用范围。
  3. 表格启用了高级权限时，确认应用可以读取要分析的数据表、记录和字段。
  4. 使用知识库中的 /wiki/ 链接时，还需要为应用授予相应知识空间的访问权限，按知识空间设置添加应用。仅有多维表格权限不足以解析 Wiki 节点。

3. 复制目标数据表链接

在多维表格中切换到要分析的数据表，复制浏览器地址栏中的完整链接，并保留 table 参数。例如：

链接中的值对应配置含义
/base/ 后的 APP_TOKENappToken多维表格标识，不是 App ID
/wiki/ 后的 NODE_TOKEN放在 url 中知识库节点标识；AVA 自动解析实际 App Token，不能直接用作 appToken
table=TABLE_IDtableId当前数据表标识
view=VIEW_ID无AVA 会忽略这个参数

缺少 table 参数时，AVA 会尝试查找数据表：只有一张表就自动使用；有多张表则报错并列出候选表名和 ID，需要指定 table 或 tableId 后重新加载。飞书文档 /docx/、电子表格 /sheets/ 和知识库中的其他文档类型不支持作为该数据源加载。

i

AVA 加载的是应用可读取的整张数据表，按接口分页读取字段和记录，不会应用飞书视图中的筛选条件。 例如某个视图只显示本月记录，带上它的 view 参数也不会把 AVA 的数据限制为本月；请在 SQL 中明确筛选。

Lark 国际版同样支持 larksuite.com 下的 /base/ 和 /wiki/ 链接，使用 Lark 开放平台创建的应用。AVA 根据链接域名自动选择接口服务；使用 Lark 时请保留 url，仅提供 appToken / tableId 会默认访问飞书中国版接口。

方式三：使用数据源配置文件

把下面的内容保存为 feishu-source.json。这个文件只指定数据源，凭证仍可使用环境变量或已保存的绑定信息。

配置字段必填说明
url与 appToken + tableId 二选一普通多维表格或知识库链接
appToken不提供 url 时必填实际多维表格的 App Token
tableId不提供 url 时必填目标数据表 ID；也可补充到不含 table 的链接
appIdSDK 必填；CLI 可从其他位置读取开放平台应用 App ID
appSecretSDK 必填；CLI 可从其他位置读取开放平台应用 App Secret

如果同时指定 url 与 appToken / tableId，它们必须指向同一张数据表。

CLI 的凭证优先级依次为：配置中的 appId + appSecret → 环境变量 → ~/.ava/feishu.json → 交互终端绑定。前两处若只填一个值会直接报错，不会拼接不同来源的凭证。管道输入、重定向或其他非交互环境不会提示绑定，需要事先配置好凭证。

App Secret 和本地绑定文件都属于敏感信息，避免提交到 Git 或输出到日志。更换已保存的应用时，可以修改本地绑定文件中的完整凭证对，或用优先级更高的环境变量覆盖。

加载成功会返回数据集 ID。将下方的 YOUR_DATASET_ID 替换为实际返回值，再查看结构、样本和记录数：

核对表名 data、字段名称和读取范围；记录数应与应用可访问的目标数据表一致。完成后运行 ava dispose YOUR_DATASET_ID 释放会话。飞书数据更新后，重新运行 ava source 加载新数据，再使用新返回的 ID；现有会话不会持续同步远端变更。

人员、附件、关联记录等复杂字段会转换成便于查询的文本，多个值通常以逗号分隔；附件只读取元信息，不下载文件。公式和查找引用字段按返回值类型转换，不保证全部为文本。不支持的字段类型会跳过；空表仍保留支持的字段结构。

现象排查与处理
提示「飞书应用绑定失败」核对 App ID 与 App Secret 是否属于同一个企业自建应用、是否复制完整，以及飞书 / Lark 平台是否对应；错误保留平台返回的 code 和 msg。
绑定成功，加载却提示权限不足检查读取接口权限是否已发布生效，再检查目标文档是否添加了同一个应用；本人有权限不代表应用有权限。
/base/ 能加载，/wiki/ 失败检查知识库读取接口权限、知识空间访问权限，以及节点承载的对象是否为多维表格。
提示 has … tables指定 ?table=TABLE_ID 或配置 tableId，不要把视图 ID 当成数据表 ID。
提示 does not match删除重复配置，或核对 url、appToken 与 tableId 是否指向同一张表。
非交互环境提示缺少凭证预先设置成对的环境变量，或提供完整配置 / 本地绑定文件。
提示 ~/.ava/feishu.json is not valid JSON修复绑定文件为包含 appId 和 appSecret 的有效 JSON；环境变量可优先覆盖该文件。
结果多于视图中看到的记录，或远端修改未出现view 筛选会被忽略；在 SQL 中加筛选。远端更新需要重新加载数据源。
返回网络错误或非 JSON 响应检查到 open.feishu.cn / open.larksuite.com 的网络连接与代理设置，根据原始错误定位失败请求。
